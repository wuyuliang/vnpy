1.load_intraday_data 会把同字母前缀的不同目录拼到同一个品种里，导致串品种污染，严重时直接引入错误样本。loader.py (line 111) 按字母前缀扫描目录并把所有匹配目录都加入 folders，例如 CU0 会同时匹配 CU0.SHF 和 CU_small；随后在 loader.py (line 137) 到 loader.py (line 154) 直接拼接并统一回填成请求的 symbol/exchange，把污染“洗平”成看起来像单一品种的数据。这个问题在当前数据目录里已经可复现：cta/data/minute/ 同时存在 CU0.SHF 和 CU_small，实际加载 CU0 时得到的总行数正好等于两者之和，而且结果里包含 2025-10-09 这类只来自 CU_small 的日期。这个会直接破坏特征、训练样本和回测结果。

2.文档推荐的生成入口 run_generate.py 产物格式，与读取器/新批处理入口的读取格式不兼容，生成后无法被 feature_loader 正常读取。FEATURES.md (line 3) 明确写“生成脚本: python3 cta/feature/run_generate.py”。但 generate_features.py (line 65) 和 generate_features.py (line 121) 把单品种结果写成平铺文件 cta/data/feature/day/{symbol}.parquet、cta/data/feature/minute/{symbol}.parquet；而 feature_loader.py (line 43) 到 feature_loader.py (line 84) 以及 feature_loader.py (line 114) 开始的读取逻辑，要求的是 cta/data/feature/{interval}/{symbol}/{YYYY-MM-DD}.parquet。我做了一个最小复现实验，按 generate_features.py 的平铺布局写出 CU0.parquet 后，load_symbol_features("CU0", "day") 直接报 FileNotFoundError，因为它会去找目录 .../day/CU0/。这意味着文档指引的主路径会产出下游根本读不进去的文件。

3.minute5/minute15/minute30/minute60 的分钟同比特征实际上没有生成，和文档承诺不一致，而且是“静默缺失”。compute.py (line 72) 只有在 interval == "minute" 时才追加 minute_tod 特征；compute.py (line 112) 到 compute.py (line 126) 又把除 minute 之外的所有频率，包括 minute5/15/30/60，都当成 "day" 路径处理。run_all_features 里同样如此，见 run_all_features.py (line 303)。但 FEATURES.md (line 3) 写的是“75 个分钟级同比特征”，而 run_all_features.py 顶部说明还声称覆盖 day / minute / minute5 / minute15 / minute30 / minute60。我用最小样例跑了 compute_single_symbol_features：interval='minute' 时有 75 个 tod_ 列，interval='minute5' 时是 0 个。这个会让高周期分钟特征集和文档描述严重偏离，且不报错。

4. run_generate.py/generate_features.py 这个旧入口实际上只支持 day 和 minute，无法生成仓库已经支持的 minute5/15/30/60，会误导使用者走到半残入口。run_generate.py (line 1) 只是转调 generate_features.py (line 176)，而这里的 CLI 选项在 generate_features.py (line 180) 只接受 day、minute、all。这和 run_all_features.py (line 1) 中“全频率覆盖”的新入口形成双轨且不兼容的状态。结果是用户按文档走 run_generate.py，不仅拿不到 minute5/15/30/60，还会生成前面第 2 条里那种读取器不兼容的输出布局。
