## 0. 先说结论：现在不能开工，卡在数据上

按 codex 文档 §22 的验证方案（12 个月训练 / 3 个月验证 / 3 个月锁定测试、
滚动前进），需要至少 18 个月的多品种分钟数据。**现在没有。**

`cta/data/origin/minute` 实测（69 个品种）：

| 起始日早于 | 品种数 |
| --- | ---: |
| 2025-01-01 | **3**（AG 2020-01、CU 2010-01、RB 2010-01） |
| 2025-07-01 | 7 |
| 2026-01-01 | 8 |

**其余 61 个品种的分钟数据都从 2026-01-05 开始，只有约 7 个月。**

所以：

- codex §22 的 walk-forward **在当前 40 品种池上无法执行**，一折都跑不出来。
- 现在唯一能跑的窗口是 2026H1，而它是单边上涨（§1）。
- 在这个窗口上锁定任何阈值，都是在拟合一段行情。

**这不是"注意事项"，是开工的硬前置条件。**详见 §5 的阶段 0。

## 1. 当前唯一可用窗口的行情性质

2026-01-01 ~ 2026-07-01，40 品种池：

```
上涨品种占比      88%
区间涨跌幅        中位 +9.2%   平均 +13.8%
日线多头排列天数  中位 55%
日线空头排列天数  中位 26%
涨幅前五          LU +59%  FU +55%  SC +38%  PP +34%  PG +34%
```

后果有两个，都必须写在任何结论前面：

1. **多头侧的好结果里分不出 alpha 和 beta。**`multi_timeframe_trend`
   在这半年 57 笔 / +288,998 / PF 4.37，其中"做多"这个方向本身是白送的。
2. **空头侧的坏结果几乎不能证伪形态。**日线空头只占 26% 的天数；
   在这种环境里做空亏钱是结构性的。

codex 文档 §23 把"参数在单一行情阶段选择"列为风险之一，方向是对的，
但没有说明**当前可用的就只有这一个阶段**。这是程度上的根本差别。

## 2. 证伪测试：核心假设值多少（已做）

codex §3 的第 1 条假设是：

> 大周期方向一致时，中周期回调后的恢复信号比无条件追突破具有更高的净期望。

这条假设的一半**不需要写代码就能量**。`second_leg_brooks`（5 分钟回调结构
做空，无日线许可层）的 40 品种结果已经在盘上：

```
cta/strategy/report/second_leg_brooks/brooks_v1
466 笔   净 -114,260   PF 0.58   每笔期望 -0.107R   胜率 38.6%
candidates 1232 → eligible 666 → fills 466
```

把这 466 笔按**入场日前一日收盘**算出的日线 EMA 排列离线分组，
就等于加了一层日线许可：

| 分组 | n | 净 | 期望 R | 胜率 | PF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全样本（无日线许可） | 466 | −114,260 | −0.107 | 39% | 0.58 |
| **日线空头（许可通过）** | **162** | **−9,782** | **−0.045** | 43% | 0.88 |
| 日线非空头 | 304 | −104,478 | −0.140 | 37% | 0.44 |
| 　其中日线多头（完全逆势） | 236 | −93,543 | −0.161 | 35% | 0.39 |

再在许可通过的子集里按成本占 R 的比例拆一层：

| | n | 净 | 期望 R |
| --- | ---: | ---: | ---: |
| 成本 < 15%R | 120 | +3,873 | **+0.009** |
| 成本 15~30%R | 41 | −14,939 | −0.220 |

**读法：**

- **日线许可层是真的**：砍掉 65% 的交易和 **91% 的亏损**。这条值得单独拿出来
  用（§5 阶段 1）。
- **但它不够**：最好的一格是 +0.009R / 120 笔，与零无法区分。
- 口径提醒：`gross_pnl` 已含滑点（滑点体现在成交价里），
  `net_pnl = gross_pnl − fees`。许可子集毛利 −4,970、手续费 4,812。
  **不是"毛利为正被成本吃掉"，毛利本身就在零附近。**

**所以 codex 文档剩下没被这次测试覆盖的增量，是 30 分钟趋势健康层
（§9）和 5 分钟回调状态机的质量门（§11.4~11.6）。**这两层是否值 +0.05R
以上，是这个策略成不成立的全部悬念——而不是"四层架构听起来更严谨"。

> 这也说明前作 `_claude.md` 的错误：它把"日线方向 + 回调入场"当成足够的
> 组合，没有先用手边的 466 笔把增量量出来。**任何"组合两个已有部件"的提案，
> 先用已有数据把增量量出来，这比写规格便宜两个数量级。**

## 3. 架构：沿用 codex 的四层，但不要重写已有代码

codex §1 的四层划分是对的，保留：

```text
日线    是否允许做多/做空/停手
30 分钟 中周期趋势是否仍可延续
5 分钟  回调识别、恢复确认、生成候选
1 分钟  挂单、成交、持仓管理
```

但 codex §24 提议的目录树会重新实现一批**已经存在且有测试**的东西。
本轮抽出的共享层现在是这样：

| 需求 | 已有实现 | 不要重写 |
| --- | --- | --- |

| 形态原语 + **向量化回调结构搜索** | `common/bar_shapes.py::causal_low_pullback_structure` | ✔ 需泛化成方向参数 |
| `PatternMatch` / 订单时间轴 / `SetupInstrument` | `common/setup_pipeline.py` | ✔ |
| 回测编排（解析器、元数据快照、周期聚合与列贴回、回放上下文、CLI） | `common/short_setup_runner.py` | ✔ |
| 风险带 + 资金上限定仓 | `common/sizing.py::size_for_risk_band` | ✔ |
| 日线方向上下文 | `multi_timeframe_trend_rules.build_daily_context` | ✔ |

## 4. 从生产事故里来的地雷清单

codex §23 列的是市场层面的失效环境，都对。下面这些是**工程层面已经踩过的**，
新策略从第一版就要带着：

1. **时段开盘那一根被丢。**每个 segment 开盘时刻（21:00 / 09:00）的集合竞价
   K 线在加载阶段被 `_time_in_segment` 的左开区间丢掉——2026-03 全品种
   1,474 根、268 万手。它让跨休市的峰值晚一根确认，对 1 分钟出场影响最大。
   见 `2026-09-05-profit-floor-session-open-bar-trace.md`。
2. **时间窗要判在下单那一刻，不是形态收尾那一根。**判形态根会把边界上那一根
   白白作废，而开盘后头十分钟正是形态最密集的区间（BU 2026-06-25 八道门过七道，
   只差一分钟）。
3. **同一结构会连续开单。**结构成立后的几根都会重新匹配同一个摆动点和同一个
   回抽极值，止损位完全相同——等于同一笔交易下三次、风险三倍。必须去重。
4. **资金上限会和风险下限打架。**回抽止损更贴身 → R 更小 → 手数更多 →
   先撞资金上限；截断后 `quantity × loss_per_lot` 掉到风险下限以下就整单作废。
   `brooks_v1` 里 `RISK_BELOW_MINIMUM` 拒绝 62 次、`CAPITAL_LIMIT` 82 次。
   **不要靠把下限调到 0 来"解决"。**
5. **闸门会静默失效。**`brooks_v1` 报告里
   `high_gap_classification: fail-open 40/40（100%）`——高跳空分级全程没生效。
   这个缺陷在 `multi_timeframe_trend` 上修过一次（缺 `daily_atr14`），
   新策略又复现了。**每轮回测都要看"闸门降级警告"那一节。**
6. **日内熔断会截断样本。**`brooks_v1` 里 `DAILY_LOSS_CIRCUIT_BREAKER`
   拒绝了 315 个候选，是最大的单项拒绝。策略亏钱时它会不断触发，
   让"候选 1232 → 成交 466"这个漏斗看起来像形态问题，其实是风控在收口。
   **做消融时要把它单独关掉跑一次，否则分不清是形态差还是被熔断挡住。**

## 5. 分阶段实施（替换 codex §25）

### 阶段 0：让数据支撑得起验证方案（**阻塞项**）

没有这一步，后面全部无意义。

1. 把分钟数据补到**覆盖至少一个完整的下跌年度**，且覆盖 40 品种池的多数品种。
   现状是 61/69 个品种只有 2026 年。
2. 补完后先描述每一段的行情性质（上涨品种占比、日线多空天数占比），
   写进文档，**不要跳过**。
3. 至少要凑出 codex §22 的一折：12 训练 / 3 验证 / 3 锁定。

### 阶段 1：把日线许可层加到 `second_leg_brooks`（不写新策略）

§2 已经预测它把期望 R 从 −0.107 抬到 −0.045 左右。用 `--config-override`
做 A/B 实跑一次：

- **对得上** → 离线拆分口径可信，可以用它继续给后面的层做预估，省掉很多回测。
- **对不上** → 先修拆分口径或实现，再谈别的。

这一步几乎零成本，而且它验证的是**方法**，不只是一个参数。

### 阶段 2：量 30 分钟健康层值多少（仍不写新策略）

这是全文剩下的核心悬念。同样可以离线做：对 `brooks_v1` 的 466 笔，
按入场时刻的 30 分钟趋势状态（codex §9.2 的定义）分组，看许可子集内部
还能不能再分出正期望的一层。

**只有这一步量出 +0.05R 以上，才值得开工写四层策略。**

### 阶段 3~5

按 codex §25 的顺序走（原语 → 状态机 → 候选 → runner → 消融 → 压力测试），
但每一步的验收都要在**至少两段不同行情**上做。

## 6. 验收（在 codex §26 基础上收紧）

### 6.1 工程验收

沿用 codex §26.1，补三条：

- 原型（向量化复刻）与生产实现的候选数在 **±15%** 以内，差得多说明有一道门
  两边理解不一致
- `multi_timeframe_trend` 与 `second_leg_brooks` 的 `trades.csv`
  在共享层泛化前后**逐字节一致**
- 每轮回测报告的"闸门降级警告"一节必须为空，或每一条都有明确解释

### 6.2 研究晋级

沿用 codex §22.4 的指标，但门槛改成：

- **在至少两段行情性质不同的区间上，组合每笔期望 R > 0**
- 多头、空头分别看都不是单侧贡献全部收益
- 成本 1.5x 压力下期望 R 仍 > 0
- 单一区间上的正收益**不构成通过**

最后一条是本轮最贵的教训：`_claude.md` 就是拿单一上涨区间的相对比较，
推出了一个绝对水平的结论。
