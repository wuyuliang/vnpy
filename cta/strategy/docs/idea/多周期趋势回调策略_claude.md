# 多周期趋势回调策略（Multi-Timeframe Trend Pullback）

> **状态：假设已被部分证伪，暂不实现。**
>
> 这份文档最初把它当成一个值得写的新策略。在 `second_leg_brooks` 的 40 品种
> 结果出来之后，我用那份 466 笔的数据直接检验了本文的核心premise，结论是
> **不够**：本策略相对 `second_leg_brooks` 的唯一实质增量（日线方向层）
> 值 +0.06R/笔，能去掉 91% 的亏损，但落点是 0，不是正。
>
> 更要紧的是第 2.4 节：**2026H1 是 88% 品种上涨的单边行情**，用它评判任何
> 做空策略都不成立。在换到多空平衡的样本区间之前，这个策略不该被实现，
> 前面那一串关于做空的结论也都只在"相对比较"的意义上有效。

## 0. 证伪测试（后补，这是本文最重要的一节）

`second_leg_brooks` 40 品种 / 2026H1：**466 笔，净 −114,260，PF 0.58，
每笔期望 −0.107R**。

本策略与它的唯一实质差异是加了一层日线 EMA 方向过滤。这个差异不需要写代码
就能量：把 brooks 的每一笔按入场日**前一日收盘**算出的日线 EMA 排列分组。

| 分组 | n | 净 | 期望 R | 胜率 | PF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全样本 | 466 | −114,260 | −0.107 | 39% | 0.58 |
| **日线空头（顺势）** | **162** | **−9,782** | **−0.045** | 43% | 0.88 |
| 日线非空头 | 304 | −104,478 | −0.140 | 37% | 0.44 |
| 　其中日线多头（完全逆势） | 236 | −93,543 | −0.161 | 35% | 0.39 |

**日线方向过滤是真的**：砍掉 65% 的交易和 91% 的亏损。
**但它不够**：顺势子集仍是 −0.045R。

再往下拆一层，按成本占 R 的比例（顺势子集内）：

| | n | 净 | 期望 R |
| --- | ---: | ---: | ---: |
| 成本 < 15%R | 120 | +3,873 | **+0.009** |
| 成本 15~30%R | 41 | −14,939 | −0.220 |

最好的那一格（日线顺势 + 低成本占比）是 **+0.009R**，120 笔——
统计上与 0 无法区分。

> 注意口径：`gross_pnl` 里已经含了滑点（滑点体现在成交价上），
> `net_pnl = gross_pnl − fees`。顺势子集毛利 −4,970、手续费 4,812。
> 所以**不是"毛利为正被成本吃掉"，而是毛利本身就在零附近**。
> 我先前推测"问题主要是交易成本"，这个推测是错的。

**结论：本文 §2 的论证方向对，但幅度不够。**把日线方向层加到回调入场层上，
得到的是"从明显亏损变成大致持平"，不是"正收益"。

## 1. 一句话

**日线定方向，日内等回调，回调结束时顺势进场。**

不做突破、不追强势。做多和做空共用同一套结构判据，方向由日线给。

---

## 2. 为什么是这个策略

这不是凭空想的形态，是把已经跑出来的两组结论对起来之后剩下的那个交集。

### 2.1 追突破在多头一侧能赚，但赚的是被过滤之后的部分

`multi_timeframe_trend`（日线 EMA 定方向 + 5 分钟突破入场，只做多）
2026H1 / 40 品种最新一版：

```
57 笔   净 +288,998   PF 4.37   最大回撤 3.61%   胜率 46%   最差单笔 -0.98R
```

但它是从 **282 笔 / +12,481 / PF 1.01 / MDD 27.3%** 一路过滤到这里的。
赚钱的不是"突破"这个动作，是那一层层拒绝：入场时段窗、日内熔断、跨休市保护、
板块集中度、入场质量门、**区间位置门**。

其中单项贡献最大的是**区间位置门**——"不要在 2~3 天区间的高端开多"，
PF 从 1.15 提到 3.65。这条规则的本质就是：**别在已经涨完的地方追**。

### 2.2 追强势在空头一侧直接是负的，而回调结构是正的

`second_leg_down`（1/5 分钟，连续放量大阴线追空）的前瞻检验，
5 分钟、21 品种、2026H1：

| 拆分 | n | 中位 MFE | 中位 MAE | MFE−MAE |
| --- | ---: | ---: | ---: | ---: |
| 全样本 | 91 | 0.30R | 0.40R | **−0.10** |
| 腿 ≥ 6 ATR（最强的那批） | 17 | 0.28R | 0.57R | **−0.29** |

**腿越强越差。**换成"第一段 → 回抽 → 第二段"的结构口径，同一批数据：

| | 追强势 | 回调结构 |
| --- | ---: | ---: |
| 样本 | 91 | **631** |
| MFE ≥ 0.5R | 26% | **54%** |
| 中位 MFE − MAE | −0.10 | **+0.05** |

机会多 7 倍，且是试过的所有口径里唯一中位为正的。

### 2.4 但这半年的数据不能用来判断做空策略

2026-01-01 ~ 2026-07-01，本策略池的 40 个品种：

```
上涨品种占比      88%
区间涨跌幅中位    +9.2%      平均 +13.8%
日线多头排列天数  中位 55%
日线空头排列天数  中位 26%
```

涨幅前五：LU +59%、FU +55%、SC +38%、PP +34%、PG +34%。

这是一段**单边上涨**行情。它有两个后果，都很要命：

1. **多头策略 PF 4.37 里有多少是 alpha、多少是 beta，这个样本分不开。**
   §2.1 那一串过滤确实把 PF 从 1.01 抬到 4.37，那部分是真的；
   但"做多"这个方向本身在这半年是白送的。
2. **做空策略在这里亏钱，几乎不能说明形态没用。**日线空头只占 26% 的天数，
   而顺势子集（那 26%）的毛利是 −4,970 / 162 笔 ≈ 持平。在一个空头只有四分之一
   天数的市场里做到持平，和"这个形态没有边际"是两个完全不同的判断，
   **这份数据区分不了**。

我在前面几轮里反复用这半年的前瞻统计和回测去调做空策略，还基于那些结论设计了
本文——**这是方法论上的错误**。那些结论里，"回调结构优于追强势"这类**相对比较**
仍然成立（同一区间、同一批品种、只换形态口径）；但任何**绝对水平**的判断
——"这个做空形态有没有正期望"——在这个区间上都是无效的。

### 2.3 交集

多头那边花了十几轮才学会"别追高"；空头那边一上来追强势就是负的，
换成回调就转正。两边指向同一件事：

> **进场点应该在回调的末端，不是在推进的末端。**

`multi_timeframe_trend` 的日线方向层在这半年有效，而它的入场层是追突破。
把入场层换成回调结构，就是这个策略的想法。

**但 §0 已经量过：这个组合落在零附近，不是正的。**所以下面的第 3 节以后
都只是"如果要做，该怎么做"的规格，不是"该做"的论证。

## 3. 结构定义

三个时间周期，各司其职：

| 周期 | 作用 | 来源 |
| --- | --- | --- |
| 日线 | 定方向（做多/做空/不做） | `multi_timeframe_trend_rules.build_daily_context` |
| 5 分钟（可配 1 分钟） | 找回调结构、定入场与止损 | `common/bar_shapes.causal_low_pullback_structure` |
| 1 分钟 | 挂单、成交、出场 | 回放引擎 |

### 3.1 ① 日线方向

沿用现成的：`ema5 > ema10 > ema20` 为多头，反之为空头，其余不做。
额外要求 `daily_atr14` 有效（波动太小的品种没有值得做的回调幅度）。

**这一层不要重写。**它已经跑了半年数据、修过一次穿越缺陷
（`daily_actual` 缺 `daily_atr14` 导致高跳空分级全程失效，见
`2026-09-04-multi-timeframe-trend-backtest-code-review.md` R-01）。

### 3.2 ② 日内回调结构（方向对称）

以做多为例（做空全部镜像）：

```
        ①第一段：创新高的推进
       ╱╲
      ╱  ╲___ ②回抽：回落 20%~90%，2~6 根
     ╱       ╲╱
    ╱          ╲__╱ ③第二段：突破回抽起点 → 入场
```

判据（`t` 为入场根，`j` 为摆动高点）：

```
# ① 第一段
high(j) == max(high over [j - first_leg_lookback, j])
first_leg = high(j) - min(low over [j - first_leg_lookback, j])
first_leg >= first_leg_atr_mult * ATR(t)                    # 默认 1.5

# ② 回抽
dip_low  = min(low over (j, t))
dip      = high(j) - dip_low
0.20 <= dip / first_leg <= 0.90

# ③ 入场根
body(t) > 0
abs(body(t)) >= entry_body_atr_mult * ATR(t)                # 默认 1.0
high(t) - close(t) <= entry_upper_wick_ratio * abs(body(t))  # 收在高点附近
high(t) > high(j)                                            # 突破第一段的高点
volume(t) >= entry_volume_mult * baseline(t)                 # 默认 1.2
j 与 t 必须同一 session segment
```

**入场根不需要很大**（1.0×ATR，不是 3~4×ATR）。做判断的是结构，
不是某一根 K 线的暴力程度——这一点是 §2.2 用数据换来的，
不要在实现时"顺手"把门槛调高。

### 3.3 ③ 方向一致性

只做与日线方向一致的回调：日线多头 → 只做多头回调；日线空头 → 只做空头回调。
**不做逆势回调**。这是与 `second_leg_brooks` 的关键区别：
它只看 1 分钟 EMA 排列，没有更高周期的方向背书。

## 4. 必须带上的过滤（都是已验证的）

这些不是"可选优化"，是前面几轮用真金白银换出来的。新策略从第一版就该带上。

| 门 | 内容 | 证据 |
| --- | --- | --- |
| **区间位置** | 做多时入场价不得高于近 2~3 日区间的 85% 分位；做空镜像 | PF 1.15→3.65 / 1.03→2.86，两套数据都成立 |
| 区间宽度 | 区间宽度 < 2.0×ATR 时不做（震荡区里没有"趋势回调"） | 同上 |
| 入场时段窗 | 开盘后 10 分钟、收盘前 20 分钟不建仓，**判的是下单那一刻**（形态收尾根 +1 分钟） | BU 2026-06-25 那笔八道门过七道，只因边界差一分钟被扔 |
| 日内熔断 | 组合当日亏损达 2R 或连续 2 笔亏损 → 当日停手 | 已在 `BaseReplayConfig` |
| 跨休市保护 | 休市前浮盈不足则减仓/平仓，高跳空品种额外降杠杆 | 已在引擎 |
| 板块集中度 | 同板块最多 2 个持仓（用 `futures_sector_map`，不要写死） | 修掉过 `"PRECIOUS"` 硬编码的缺陷 |
| 结构去重 | 同一个 swing + 同一个回抽极值只开一次 | 不去重会把同一笔交易下三次、风险三倍 |

## 5. 仓位

```
trigger    = high(j) + 1 tick            # 做多；做空镜像
stop_price = dip_low - stop_buffer_ticks * tick
R          = trigger - stop_price
```

止损放在**回抽的极值**外侧：回抽低点被跌破，说明这次回调不是回调，是反转。

手数用现成的 `common/sizing.size_for_risk_band`：
风险带 0.2%~0.5% 权益，资金占用 ≤10%（有保证金率用保证金，否则名义），
不足 1 手买 1 手。

> **实现时盯住 `RISK_BELOW_MINIMUM`。**回抽止损比"形态区间极值"止损更贴身，
> R 更小 → 手数更多 → 资金上限更容易先撞上；撞上之后 `quantity × loss_per_lot`
> 掉到风险下限以下就会整单作废。第一轮如果这个拒绝码占比超过 10%，
> 说明风险带与资金上限打架了，要么放宽 `max_capital_share`，
> 要么把"资金上限截断"与"单笔风险太小"区分开——**不要直接把下限调到 0**。

## 6. 出场

| 机制 | 参数 | 说明 |
| --- | --- | --- |
| 保护性止损 | `stop_price` | 即 1R |
| 跟踪止盈地板 | `arm 0.5R / giveback 0.5R`，峰值按 1 分钟 K 线极值，触发后下一根开盘市价 +1 跳滑点 | 复用 `engine_components/drawdown.py`，一行引擎代码都不用改 |
| 无进展时间止损 | `no_progress_bars=8`（信号根），峰值未达 0.5R 则平 | **这条要留着** |
| 跟随不足降级目标 | `follow_through_bars=3` 内无同向大实体 → 目标降为 1R | |

> **不要以为放宽时间止损能改善结果。**在 `second_leg_brooks` 上实测过：
> `no_progress_bars` 8 → 20，时间止损从 55 笔降到 12 笔、止盈地板从 37 升到 45，
> 但净盈亏 **−24,843 → −30,846**，胜率 43%→38%。
> 时间止损不是在砍掉好单，是在及时砍掉坏单。

## 10. 前置条件与验收

### 10.1 前置条件（不满足就不要开工）

**这三条在写第一行代码之前必须先做完，顺序不能换。**

1. **换样本区间**。至少再准备两段行情：一段多空平衡、一段商品普跌。
   2026H1 是 88% 品种上涨（§2.4），在它上面调做空或双向策略是在拟合行情。
   数据端要做的事：把分钟数据往前补到覆盖至少一个完整的下跌年度。
2. **把日线方向层先加到 `second_leg_brooks` 上**，用 `--config-override`
   做 A/B，不要写新策略。§0 预测它会把期望 R 从 −0.107 抬到 −0.045 左右；
   如果实跑对不上，说明我的离线拆分口径有问题，先修那个。
3. **在新区间上重跑 `multi_timeframe_trend`**。如果它在多空平衡区间里
   PF 掉到 1.x，那说明 §2.1 的"过滤有效"结论也需要重新称重，
   本策略的方向层就没有可继承的东西。

### 10.2 验收（前置条件满足之后）

- 原型与生产实现的候选数在 ±15% 以内
- 因果性测试：信号之后的 K 线随便改，候选与
  `trigger`/`stop_price`/`quantity` 逐字节不变
- `multi_timeframe_trend` 的 `trades.csv` 在共享层泛化前后**逐字节一致**
- **在至少两段不同行情上，每笔期望 R > 0**，且做多、做空两侧分别看都不是
  单侧贡献全部收益
- 单一区间上的正收益**不构成通过**——这正是本文一开始犯的错

## 11. 已知地雷（都踩过）

1. **时段开盘那一根被丢**。每个 segment 开盘时刻（21:00 / 09:00）的集合竞价
   K 线在加载阶段就被 `_time_in_segment` 的左开区间丢掉了——2026-03 全品种
   1,474 根、268 万手。这会让跨休市的峰值晚一根确认，对 1 分钟出场影响尤其大。
   见 `2026-09-05-profit-floor-session-open-bar-trace.md`。**这个策略上线前
   最好先修它**，或至少知道它在。
2. **时间窗判在形态根还是下单根**。判形态根会把边界上的那一根白白作废，
   而开盘后头十分钟正是形态最密集的区间。
3. **`--top-n` 只按研究排名选池**，不按成交额。要配 `--include-top-turnover 0.8`，
   否则 SN/LC/JD 这类成交额高但排名靠后的品种进不来。
4. **不要用单点参数下结论**。任何过滤必须在两套 `trades.csv` 上同时改善；
   相邻参数格子变号的一律当噪声。

## 13. 这份文档自己的教训

第一版写完之后，用户一句"你写的这个策略跟这个很像"就把它问倒了。复盘：

1. **我把一个已经在跑的策略换了个方向包装成新策略**，而没有先量"新增的那一层
   值多少"。这一层（日线方向）本来就能用现成的 466 笔数据离线拆分出来，
   十分钟的事，我却写了 300 行规格。
   → **任何"组合两个已有部件"的提案，先用已有数据把增量量出来。**
2. **我在一个 88% 品种上涨的窗口里反复评判做空策略**，而且没有先看一眼行情
   背景。相对比较（形态 A vs 形态 B）在这种窗口里仍然有效，绝对判断
   （有没有正期望）完全无效。
   → **动手之前先描述样本区间的行情，写进文档第一节。**
3. **我把"中位 MFE − MAE = +0.05"当成了正期望的证据。**那是无成本、无撮合、
   无时间止损的前瞻统计，落到实盘口径就是 −0.107R。
   → 前瞻统计只能用来**排序**候选口径，不能用来判断**能不能赚钱**。
