# 多周期顺大逆中顺小趋势策略

## 1. 文档定位

本文定义一套面向中国商品期货的双向多周期趋势策略。策略只做以下结构：

```text
顺大：周线与日线方向一致，决定只允许做多或只允许做空
逆中：15 分钟形成与大周期相反的、已经成熟但尚未破坏大结构的回调
顺小：5 分钟回调走出三推楔形，并出现重新顺大周期方向的恢复信号
执行：信号确认后，从下一根 1 分钟 K 线开始下单、成交和管理持仓
```

默认周期为：

| 层级 | 默认周期 | 默认职责 |
| --- | --- | --- |
| 大周期 1 | `1w` | 慢方向许可、长期结构边界 |
| 大周期 2 | `1d` | 快方向许可、近期障碍与失效 |
| 中周期 | `15m` | 识别与大周期相反的回调段 |
| 小周期 | `5m` | 识别三推楔形和趋势恢复信号 |
| 执行周期 | `1m` | 订单激活、成交、止损与退出 |

`1w + 1d / 15m / 5m / 1m` 是首轮研究种子，不是从最终收益中挑出的最优组合。
大、中、小和执行周期均通过配置声明，但一旦进入某个 walk-forward 折，周期组合必须冻结，
不能根据该折最终盈亏临时切换。

本文是一份待实现、待验证的独立策略规格，不是
`multi_timeframe_trend`、`second_leg_down` 或 `second_leg_brooks` 的参数变体，
也不继承这些策略的历史收益结论。文中阈值均为首轮研究参数，不代表最优值，不构成收益、
胜率或回撤承诺。

### 1.1 “顺大、逆中、顺小”的准确含义

以多头为例：

1. 周线和日线均处于多头趋势，策略只寻找做多机会。
2. 15 分钟必须先走出空头方向的回调，而不是在上涨扩张末端直接追高。
3. 5 分钟在该回调内形成三次向下推进；第三推衰竭后，出现向上的恢复信号才允许做多。

空头完全镜像：周线和日线均为空头，15 分钟向上回调，5 分钟三次向上推进，第三推后出现
向下恢复信号才允许做空。

因此，“顺小”指的是三推完成后的 5 分钟恢复方向与大周期一致，不是说三次推进本身与大周期
一致。三次推进属于中周期逆势回调在小周期上的内部结构。

### 1.2 策略目标

1. 用周线和日线共振减少逆大势交易。
2. 用 15 分钟逆势回调避免在大周期趋势扩张末端追价。
3. 用 5 分钟三推楔形区分“普通回调接近衰竭”和“仍在加速的反向趋势”。
4. 用结构止损和账户风险反推手数，使不同价格、乘数和波动水平的品种风险可比。
5. 用实际合约、有效期元数据和 1 分钟事件模拟可实现成交。
6. 保留完整候选漏斗和拒绝码，使低交易数、未成交和元数据缺口可以解释。

### 1.3 非目标

1. 不预测周线或日线顶部、底部。
2. 不把任意三个连续新低或新高称为三推楔形。
3. 不在 15 分钟没有明确逆势回调时，仅凭一根 5 分钟反转 K 线入场。
4. 不要求每个品种、每个方向或每个月都盈利。
5. 不按单品种最终收益定制形态阈值或周期组合。
6. 不使用连续合约价格直接成交。
7. 不把缺少历史手续费、乘数、最小变动价位、保证金、涨跌停或交易时段的区间计入正式绩效。

## 2. 可配置周期架构

### 2.1 配置接口

首版使用统一的周期字符串：

```python
large_slow_timeframe: str = "1w"
large_fast_timeframe: str = "1d"
middle_timeframe: str = "15m"
small_timeframe: str = "5m"
execution_timeframe: str = "1m"
```

支持的单位为 `m`、`h`、`d`、`w`。周期解析器只负责把字符串转换为
`TimeframeSpec`，K 线是否可完整聚合仍由交易日历和 `SessionSpec` 决定。

运行时派生
`large_timeframes=(large_slow_timeframe, large_fast_timeframe)`。两个大周期都必须给出
同一方向，不能以多数票放行。使用两个标量字段可以直接兼容现有 `--config-override`
解析方式，同时允许把周线、日线分别替换为预先声明的其他大周期。

### 2.2 层级约束

配置初始化时必须验证：

1. 两个大周期非空、互不相同，慢大周期严格大于快大周期，快大周期严格大于中周期。
2. 中周期严格大于小周期，小周期不小于执行周期。
3. 分钟或小时周期必须能由执行周期完整聚合。
4. 默认情况下，`middle_minutes % small_minutes == 0`，
   `small_minutes % execution_minutes == 0`。
5. 分钟桶不能跨越 `SessionSpec.segment` 的休市边界。
6. 任一周期无法证明 K 线完整时，该层状态为 `UNAVAILABLE`，不能用残缺桶代替。
7. 同一个 walk-forward 折内，所有品种使用预先冻结的周期配置；若某品种信息密度不足，
   输出 `NO_TRADE`，不能按最终收益换到另一个周期。

周期大小使用交易时段内的有效时长比较，不以自然时间差粗略替代。例如，夜盘到日盘之间的
休市不能被计入一根超长分钟 K 线。

### 2.3 各层职责不得互相替代

| 层级 | 可以决定 | 不可以决定 |
| --- | --- | --- |
| 大周期 | 允许方向、结构失效、障碍空间 | 具体入场时点、成交价格 |
| 中周期 | 回调是否存在、是否成熟、是否过深 | 跳过大周期冲突、直接生成订单 |
| 小周期 | 三推楔形、恢复信号、结构止损锚点 | 使用未完成中周期或大周期 K 线 |
| 执行周期 | 激活、撮合、滑点、涨跌停、退出 | 重新解释已经冻结的形态 |

任何一层缺失都不能由另一层“猜测”补齐。

## 3. 数据、聚合与时间模型

### 3.1 输入数据

每根执行周期 K 线至少包含：

```text
symbol, exchange, contract_code, exchange_trade_date
bar_start, bar_end, open, high, low, close
volume, open_interest, turnover, feature_sequence
```

要求：

1. 时间统一使用带时区的交易所本地时间。
2. 夜盘归属由有效期交易日历给出，不按自然日切分。
3. 主力连续或复权序列只用于形成信号。
4. 订单、成交、费用、保证金和盈亏必须落在当时可交易的实际合约上。
5. 原始数据、聚合缓存和元数据快照均需记录输入指纹和算法版本。

### 3.2 完整 K 线规则

#### 周线

周线按 `exchange_trade_date` 所属的交易周聚合。只有以下条件全部满足才可发布：

1. 该周交易日集合由当时已知的交易日历确定。
2. 每个应交易日的全部 `SessionSpec.segment` 完整。
3. 已到该周最后一个应交易日的最后一个有效事件。
4. 周线 `feature_asof` 等于组成该周线的最后一根已完成执行 K 线。

节假日短周可以是完整周；缺少应有交易日或交易时段的数据不是完整周。当前尚未结束的周线
绝不参与方向判断。

#### 日线

日线按交易所交易日聚合。夜盘和次日日盘只有在同一 `exchange_trade_date` 下全部声明时段
完整后，才形成一根可见日线。

#### 中周期和小周期

15 分钟、5 分钟以及其他可配置分钟周期均以每个 `SessionSpec.segment.bucket_anchor`
为锚点聚合。每个桶必须同时满足：

```text
bar_count == expected_count
span_end - span_start == (expected_count - 1) * execution_interval
span_end == expected_bucket_end
```

不完整桶直接丢弃并记录数据缺口，不使用向前填充或未来价格补齐。

### 3.3 因果时间字段

每个结构、候选、订单和成交必须分别记录：

| 字段 | 含义 |
| --- | --- |
| `pivot_time` | 推进极值实际出现的历史位置，仅用于结构锚点和画图 |
| `feature_asof` | 本次特征使用的最后一个已完成事件 |
| `known_at` | 摆动点或形态首次可以确认的事件 |
| `signal_time` | 5 分钟恢复信号 K 线完成的事件 |
| `decision_asof` | 大中小周期、风险和元数据共同完成判断的事件 |
| `order_active_at` | 订单最早可以参与撮合的 1 分钟事件 |
| `fill_time` | 实际或模拟成交事件 |
| `label_end` | 仅供研究标签使用的未来观察终点 |

同时记录事件序号，并强制：

```text
(feature_asof, feature_sequence)
    <= (known_at, known_sequence)
    <= (signal_time, signal_sequence)
    <= (decision_asof, decision_sequence)
    <  (order_active_at, activation_sequence)
    <= (fill_time, fill_sequence)
```

即使两个事件时间戳相同，也必须用序号证明先后顺序。

### 3.4 高周期快照对齐

在任一 5 分钟决策时刻：

1. 周线快照来自最近一根已经发布的完整周线。
2. 日线快照来自最近一根已经发布的完整日线。
3. 15 分钟快照满足 `middle_bar_end <= signal_time`。
4. 如果信号发生在尚未结束的 15 分钟桶内，只能读取上一根完整 15 分钟线。
5. 对齐采用向后查找，不允许最近邻、前向查找或把高周期状态回填到其开始时间。

### 3.5 滚动特征

用于判断第 `t` 根 K 线是否异常的 ATR、成交量基线和波动分位只读取 `t-1` 及以前：

```text
ATR(t) = RMA(TrueRange through t-1, period)
volume_baseline(t) = mean(eligible volume through t-1)
```

EMA 可以包含已经完成的第 `t` 根收盘价，但状态只从该根 `bar_end` 起可见。任何
`shift(-n)`、居中窗口、未来极值或事后回填确认时间的写法均禁止进入候选生成。

## 4. 统一方向与归一化定义

为保证多空严格镜像，定义方向：

```text
D = +1  表示计划做多
D = -1  表示计划做空
C = -D  表示中周期回调方向
```

### 4.1 K 线定义

对任一已完成 K 线：

```text
range = high - low
directional_body = D * (close - open)

close_location(D=+1) = (close - low) / range
close_location(D=-1) = (high - close) / range
```

`range <= 0` 时不能形成小周期恢复信号。

### 4.2 路径效率

对窗口 `[t-k, t]`：

```text
efficiency(D) = D * (close[t] - close[t-k])
                / sum(abs(close[i] - close[i-1]))
```

分母为零时状态为 `UNAVAILABLE`，不把效率强行记成 0。

### 4.3 参数归一化

价格距离优先用以下单位表达：

1. 同周期的前置 ATR。
2. 实际合约最小变动价位的整数倍。
3. 前一推动段或回调段的比例。

禁止跨品种比较固定点数，也禁止因为某个品种历史盈亏更好而单独修改形态语义。

## 5. 顺大：周线与日线方向许可

### 5.1 大周期趋势不是单一 EMA 条件

EMA 排列是必要方向门，但不能单独代表“可交易趋势”。每个大周期 `h` 使用以下已完成特征：

```text
EMA5_h, EMA10_h, EMA20_h
ATR14_h shifted by 1 bar
ema10_slope_h = (EMA10_h[t] - EMA10_h[t-k]) / ATR14_h[t]
efficiency_h = efficiency(D) over k bars
recent_high/low = extrema over the latest k bars
prior_high/low = extrema over the preceding k bars
daily_structure_low/high = extrema over the latest large_structure_lookback
```

首轮 `k = large_evidence_lookback = 5`。

用于中周期失效的日线边界只取最近 `large_structure_lookback=10` 根完整日线：

```text
long_invalidation = min(daily low over the latest 10 bars)
                    - large_structure_break_buffer_atr * daily_ATR14
short_invalidation = max(daily high over the latest 10 bars)
                     + large_structure_break_buffer_atr * daily_ATR14
```

该边界在每根完整日线发布后才更新，当前未完成日线不得改变它。

### 5.2 单个大周期多头状态

先满足硬方向门：

```text
EMA5 > EMA10 > EMA20
D * ema10_slope >= large_min_slope_atr
```

再计算四项证据：

1. 收盘位于 EMA10 的趋势侧：`close > EMA10`。
2. 方向路径效率：`efficiency(+1) >= large_min_efficiency`。
3. 最近窗口高点高于前窗高点。
4. 最近窗口低点高于前窗低点。

硬方向门成立，且四项中至少 `large_min_evidence_count=3` 项成立，状态才是
`BULL_TREND`。

### 5.3 单个大周期空头状态

完全镜像：

```text
EMA5 < EMA10 < EMA20
-ema10_slope >= large_min_slope_atr
```

四项证据为：

1. `close < EMA10`。
2. `efficiency(-1) >= large_min_efficiency`。
3. 最近窗口低点低于前窗低点。
4. 最近窗口高点低于前窗高点。

满足硬方向门且至少三项证据成立，状态为 `BEAR_TREND`。

### 5.4 其他大周期状态

```text
NEUTRAL      数据充分，但不满足多头或空头趋势
TRANSITION   多空证据接近，或 EMA 排列刚发生切换
UNAVAILABLE  预热、完整性或时间对齐不足
```

大周期状态不使用未来收益定义。

### 5.5 周线和日线共振

默认配置下：

| 周线 | 日线 | 新开仓许可 |
| --- | --- | --- |
| `BULL_TREND` | `BULL_TREND` | 只允许做多 |
| `BEAR_TREND` | `BEAR_TREND` | 只允许做空 |
| 任一 `NEUTRAL/TRANSITION` | 任意 | 禁止新开仓 |
| 任一 `UNAVAILABLE` | 任意 | 禁止新开仓 |
| 多空冲突 | 任意 | 禁止新开仓 |

两个大周期必须给出同一个趋势方向。大周期中性只阻止新开仓，不会自动平掉已有仓位；
任一大周期明确切换到持仓反方向时，触发
`LARGE_DIRECTION_REVERSAL`，从下一可交易执行事件退出。

## 6. 逆中：15 分钟逆势回调

### 6.1 中周期职责

中周期不负责确认最终入场，只负责证明市场确实从大周期趋势中发生了一段反向运动。

```text
大周期做多 D=+1  -> 15 分钟回调方向 C=-1
大周期做空 D=-1  -> 15 分钟回调方向 C=+1
```

一根逆向 K 线不构成“逆中”。中周期必须同时具备方向、持续时间和回调深度。

### 6.2 中周期反向证据

使用已完成中周期 K 线计算：

```text
EMA5_m, EMA10_m, EMA20_m
ATR14_m shifted by 1 bar
counter_slope = C * (EMA10_m[t] - EMA10_m[t-k]) / ATR14_m[t]
counter_efficiency = efficiency(C) over k bars
```

硬方向门为 EMA 按回调方向排列：

```text
大周期多头时：EMA5_m < EMA10_m < EMA20_m
大周期空头时：EMA5_m > EMA10_m > EMA20_m
```

再计算四项证据：

1. 收盘位于 EMA10 的回调方向一侧。
2. `counter_slope >= middle_min_slope_atr`。
3. `counter_efficiency >= middle_min_efficiency`。
4. 最近 `middle_evidence_lookback` 根形成回调方向的新极值结构。

第 4 项的准确公式为：

```text
大周期多头、15 分钟向下回调：recent_low < prior_low and recent_high < prior_high
大周期空头、15 分钟向上回调：recent_high > prior_high and recent_low > prior_low
```

`recent` 和 `prior` 是长度相同、互不重叠的两个窗口，均在当前完整中周期 K 线及以前。

硬方向门成立且至少 `middle_min_evidence_count=3` 项成立，记该根为一根
`countertrend_evidence_bar`。

### 6.3 回调锚点与深度

中周期回调第一次进入 `ACTIVE` 时冻结回调起点：

```text
多头计划：origin = 启动前 middle_anchor_lookback 根的最高价
空头计划：origin = 启动前 middle_anchor_lookback 根的最低价
```

之后只向前更新回调不利极值：

```text
多头计划：depth = origin_high - running_low
空头计划：depth = running_high - origin_low

depth_atr = depth / ATR14_m_at_start
```

ATR 在回调启动时冻结，避免回调本身放大波动后机械降低深度比例。

### 6.4 中周期状态机

```text
WAITING
  -> ACTIVE
  -> MATURE
  -> RELEASED
  -> EXPIRED
  -> INVALIDATED
```

状态转换规则：

#### `WAITING -> ACTIVE`

连续 `middle_confirm_bars=2` 根出现反向证据时，在第二根完成后进入 `ACTIVE`。
状态生效时间是第二根的 `bar_end`，不能回填到第一根。
`episode_start_time` 记录第一根反向证据的 `bar_end`，`episode_bars` 从该根开始计数，
但第一根在第二根确认前不具有可交易状态。

#### `ACTIVE -> MATURE`

必须全部满足：

```text
middle_min_bars <= episode_bars <= middle_max_bars
middle_min_depth_atr <= depth_atr <= middle_max_depth_atr
大周期仍然同向共振
尚未突破大周期结构失效边界
```

小周期三推跟踪器可在 `ACTIVE` 时开始记录第一推，以免遗漏早期结构，但只有中周期达到
`MATURE` 后才允许生成候选。

#### `MATURE -> RELEASED`

中周期不再满足完整反向证据，但尚未明确破坏大周期，说明回调可能正在结束。状态转为
`RELEASED`，并保留 `middle_release_grace_bars=1` 根中周期 K 线的候选窗口。

这样可以接纳“5 分钟恢复信号恰好使当前完整 15 分钟线开始重新顺大”的情形，同时避免在
回调结束很久后把旧楔形重新激活。

#### `EXPIRED`

从回调启动起超过 `middle_max_bars`，或 `RELEASED` 超过宽限窗口仍未形成候选，
该回调过期。必须等待新的中周期回调事件。

#### `INVALIDATED`

以下任一条件立即失效：

1. 任一大周期不再给出原方向的新开仓许可。
2. `depth_atr > middle_max_depth_atr`。
3. 多头计划的中周期收盘低于 `long_invalidation`，或空头计划的中周期收盘高于
   `short_invalidation`。
4. 数据、交易日历、实际合约映射或必要元数据变为不可用。
5. 回调跨越配置不允许的交易日范围。

`INVALIDATED` 后旧的起点、极值和小周期推进全部清空，不能复用。

### 6.5 中周期与交易时段

默认中周期回调可以跨同一 `exchange_trade_date` 内的多个交易时段，但不能把休市跳空
当作一根 15 分钟运动。跨交易日时重置中周期事件。后续若研究跨日回调，必须作为单独消融，
不能静默改变首版口径。

## 7. 顺小：5 分钟三推楔形

### 7.1 三推不是三根同色 K 线

一个有效三推楔形必须包含：

```text
推进 1 -> 可见反弹 1 -> 推进 2 -> 可见反弹 2 -> 推进 3 -> 顺大恢复信号
```

三次推进之间必须由两个独立反弹分隔。连续三根创新低或创新高属于同一推进，不能计为三推。

默认小周期形态限制在同一个 `SessionSpec.segment` 内。这样夜盘、午休或换段跳空不会被当作
楔形内部推进。时段结束仍未完成的形态进入 `WEDGE_EXPIRED_AT_SEGMENT_END`。

### 7.2 因果摆动点

首版使用局部摆动点识别推进极值：

```text
pivot_left = 2
pivot_right = 1
```

多头计划中的摆动低点 `i`：

```text
low[i] < min(low[i-pivot_left : i])
low[i] <= min(low[i+1 : i+pivot_right+1])
```

空头计划中的摆动高点完全镜像。

摆动点画在 `pivot_time = bar_end[i]`，但只有右侧第 `pivot_right` 根完成后才可确认：

```text
known_at = bar_end[i + pivot_right]
```

任何候选、订单和回测成交都只能使用 `known_at`，不得回到 `pivot_time` 入场。若相邻极值相同，
严格左侧、非严格右侧的规则只保留平台的第一个极值，避免重复计推。

推进极值在确认前可以被同方向新极值替换。例如第一推低点尚未确认时又出现更低价格，
仍然只是第一推向下延伸，不增加推进计数。只有合格反弹已经发生并可见后，下一次新极值才有
资格成为下一推。

### 7.3 多头三推楔形

大周期做多、中周期向下回调时，寻找三个摆动低点：

```text
L1 at i1
L2 at i2
L3 at i3
i1 < i2 < i3
```

必须满足：

#### 三个独立推进

```text
wedge_min_push_spacing_bars <= i2-i1 <= wedge_max_push_spacing_bars
wedge_min_push_spacing_bars <= i3-i2 <= wedge_max_push_spacing_bars
L2 <= L1 - min_new_extreme
L3 <= L2 - min_new_extreme
```

其中：

```text
signal_tick_equivalent = actual_tick / abs(adjustment_scale)
min_new_extreme = max(wedge_min_new_extreme_ticks * signal_tick_equivalent,
                      wedge_min_new_extreme_atr * ATR14_s)
```

`adjustment_scale` 必须有限且非零，并且在决策时已经可见。这样形态阈值和复权信号价格处于
同一价格空间，同时仍使用当时实际合约的历史有效 tick。

#### 两次可见反弹

在 `(i1, i2)` 和 `(i2, i3)` 内分别存在已确认摆动高点 `H12`、`H23`，并满足：

```text
H12 - L1 >= wedge_min_rebound_atr * ATR14_s
H23 - L2 >= wedge_min_rebound_atr * ATR14_s
H23 < H12
```

`H23 < H12` 保证回调内部仍保持向下结构。没有足够反弹时，多个新低仍属于同一推进。

#### 楔形减速

```text
extension_12 = L1 - L2
extension_23 = L2 - L3
extension_ratio = extension_23 / extension_12

extension_ratio <= wedge_max_extension_ratio
```

首轮 `wedge_max_extension_ratio=1.25`。第三推可以略长于第二推，但不能明显加速。
同时要求：

```text
wedge_min_total_bars <= i3-i1 <= wedge_max_total_bars
wedge_min_depth_atr <= (L1-L3)/ATR14_s <= wedge_max_depth_atr
```

### 7.4 空头三推楔形

空头规则完全镜像，寻找三个摆动高点 `H1 < H2 < H3` 的价格关系，即时间上依次出现、
价格逐步抬高：

```text
H2 >= H1 + min_new_extreme
H3 >= H2 + min_new_extreme
```

两次回落低点 `L12`、`L23` 必须满足：

```text
H1 - L12 >= wedge_min_rebound_atr * ATR14_s
H2 - L23 >= wedge_min_rebound_atr * ATR14_s
L23 > L12
```

楔形减速为：

```text
extension_12 = H2 - H1
extension_23 = H3 - H2
extension_23 / extension_12 <= wedge_max_extension_ratio
```

除方向和买卖盘取整外，其余阈值与多头共享。

### 7.5 第三推后的顺小恢复信号

第三推摆动点确认后，最多等待 `wedge_signal_max_wait_bars=3` 根已完成小周期 K 线。
恢复信号可以是确认第三推的右侧 K 线本身。

多头恢复信号必须全部满足：

```text
close > open
(close - open) / ATR14_s >= signal_min_body_atr
(close - low) / (high - low) >= signal_min_close_location
close > high[t-1]
close > EMA5_s
```

空头完全镜像：

```text
close < open
(open - close) / ATR14_s >= signal_min_body_atr
(high - close) / (high - low) >= signal_min_close_location
close < low[t-1]
close < EMA5_s
```

这根 K 线证明 5 分钟价格首次重新顺大周期方向，因此是“顺小”的确认事件。

### 7.6 可选质量特征

以下特征首轮只记录，不作为硬过滤：

```text
第三推成交量 / 第二推成交量
第三推实体总和 / 第二推实体总和
第三推路径效率 / 第二推路径效率
价格新极值与动量指标是否背离
楔形上下边界的收敛速度
```

成交量实验有明确但默认关闭的开关。第二推、第三推的平均量按各自推进起点到极值点的已完成
K 线计算，并剔除 segment 首根：

```text
push3_volume_ratio = mean_volume(push3) / mean_volume(push2)

volume_filter_enabled=true 时：
push3_volume_ratio <= wedge_max_push3_volume_ratio
```

任一推进没有合格成交量样本时，开关开启的候选拒绝为 `WEDGE_VOLUME_UNAVAILABLE`；开关关闭时
不影响候选。首轮 `volume_filter_enabled=false`，成交量只审计。动量背离仍不作为首版配置，
若后续加入必须通过独立消融，不能看完整历史收益后只为个别品种打开。

### 7.7 一形态一候选

形态键为：

```text
(symbol, direction, middle_episode_id,
 push1_pivot_time, push2_pivot_time, push3_pivot_time)
```

同一个三推结构只允许生成一个候选。订单未成交、过期或被组合风控拒绝，都不能让同一形态
在后续 K 线上重复发单。只有形成新的第三推，或中周期回调重置，才可产生新候选。

### 7.8 小周期失效

以下任一条件使形态失效：

1. 中周期回调进入 `EXPIRED` 或 `INVALIDATED`。
2. 大周期许可消失。
3. 三推总长度超过 `wedge_max_total_bars`。
4. 任意两推间距超出配置范围。
5. 第三推明显加速，超过 `wedge_max_extension_ratio`。
6. 第三推确认后等待恢复信号超过最大根数。
7. 形态跨越 `SessionSpec.segment` 边界。
8. 数据或元数据状态不可用。

## 8. 候选、入场与成交

### 8.1 候选成立条件

5 分钟恢复信号收盘时，必须同时满足：

1. 所有大周期仍同向共振。
2. 中周期事件为 `MATURE`，或处于未过期的 `RELEASED` 宽限期。
3. 三推楔形全部几何和时间约束成立。
4. 当前 K 线满足顺小恢复信号。
5. 到最近已完成日线障碍至少有 `min_obstacle_space_r=1.5R`。
6. 当前时点位于允许开仓窗口。
7. 实际合约、交易机制和组合风险检查可用。

最近日线障碍使用当前决策前已经完整发布的日线计算：

```text
daily_highs = 最近 obstacle_lookback_daily_bars 根完整日线高点
daily_lows = 最近 obstacle_lookback_daily_bars 根完整日线低点

多头障碍 = daily_highs 中严格高于 actual_trigger 的最小值
空头障碍 = daily_lows 中严格低于 actual_trigger 的最大值
```

存在障碍时，要求触发价到障碍的距离不少于 `min_obstacle_space_r * initial_r_price`。
窗口内不存在趋势前方障碍时记为 `NO_VISIBLE_OBSTACLE` 并放行，不能用未来新高或新低补障碍。

### 8.2 信号空间触发价

多头：

```text
mapped_signal_high = signal_high * adjustment_scale + adjustment_offset
raw_actual_trigger = mapped_signal_high + entry_buffer_ticks * actual_tick
actual_trigger = round_buy_stop_up(raw_actual_trigger, actual_tick)
```

空头：

```text
mapped_signal_low = signal_low * adjustment_scale + adjustment_offset
raw_actual_trigger = mapped_signal_low - entry_buffer_ticks * actual_tick
actual_trigger = round_sell_stop_down(raw_actual_trigger, actual_tick)
```

连续合约或复权信号价格必须先用决策时已知的比例或价差映射到实际合约，再使用实际合约 tick
增加缓冲并做方向取整。不能把实际合约 tick 直接加到复权信号价格上。

映射参数必须同时记录 `adjustment_scale`、`adjustment_offset` 和 `adjustment_known_at`：

```text
actual_price = signal_price * adjustment_scale + adjustment_offset
adjustment_known_at <= decision_asof
```

不能使用回测结束后统一计算的最终复权映射。

### 8.3 订单激活与有效期

```text
signal_time = 恢复信号 5 分钟 K 线的 bar_end
decision_asof = 完成上下文、元数据和风险判断的事件
order_active_at = decision_asof 之后第一根可交易 1 分钟事件
expiry = min(3 根小周期 K 线, 当前 segment 结束, 上下文失效)
```

禁止在信号 K 线内部或其收盘价成交。挂单期间若大周期许可、中周期事件、实际合约映射或
风险预算变化导致计划不再有效，应先取消订单，不能继续等待触发。

### 8.4 允许开仓时段

默认阻止：

```text
每个 SessionSpec.segment 开始后的前 10 分钟
每个 SessionSpec.segment 结束前的最后 20 分钟
```

窗口按 segment 相对位置计算，不写死 `09:01`、`21:01`、`15:00` 或夜盘收盘时间。
判断对象是订单首次激活时点，不是形态第三推的历史极值时点。

### 8.5 1 分钟成交模型

订单激活后的每根实际合约 1 分钟 K 线按以下顺序处理：

1. 校验交易时段、涨跌停、订单能力、价格和成交量。
2. 若开盘已经越过触发价，按不优于开盘对手价并加滑点成交。
3. 否则只有当分钟高低价真实触及触发价时才可能成交。
4. 价格按订单方向和角色做 tick 取整。
5. 成交量不足时按引擎既有部分成交策略处理，未成交余量保留到过期或取消。

同一根 1 分钟 K 线同时触及入场和止损、或止损和利润地板时，优先使用更细数据；没有更细
数据时采用对策略不利的事件顺序，不能选择更高收益路径。

### 8.6 涨跌停与跳空

1. 跳空越过入场触发价时，不得按较优的原触发价成交。
2. 跳空越过保护止损时，按首个可交易对手价处理，不保证止损价成交。
3. 涨跌停锁死、零成交量或无对手盘时，订单保持未成交并记录原因。
4. 交易机制不能从 OHLC 推断时，订单状态为不可判定，不能默认成交。

## 9. 初始止损、R 与仓位

### 9.1 结构止损

多头：

```text
actual_push3_low = push3_low * adjustment_scale + adjustment_offset
actual_atr_s = abs(adjustment_scale) * ATR14_s
raw_actual_stop = actual_push3_low - max(actual_tick,
                                         stop_buffer_atr * actual_atr_s)
actual_stop = round_sell_stop_down(raw_actual_stop, actual_tick)
```

空头：

```text
actual_push3_high = push3_high * adjustment_scale + adjustment_offset
actual_atr_s = abs(adjustment_scale) * ATR14_s
raw_actual_stop = actual_push3_high + max(actual_tick,
                                          stop_buffer_atr * actual_atr_s)
actual_stop = round_buy_stop_up(raw_actual_stop, actual_tick)
```

止损距离必须满足：

```text
min_stop_atr * actual_atr_s
    <= abs(actual_trigger - actual_stop)
    <= max_stop_atr * actual_atr_s
```

不允许缩短结构止损来强行获得更大仓位。

### 9.2 R 的定义

在计划创建时冻结：

```text
initial_r_price = abs(actual_trigger - actual_stop)
initial_r_cash_per_lot = initial_r_price * contract_multiplier
                         + stressed_round_trip_cost_per_lot
```

后续止损上移、波动变化、部分成交或加减仓均不能改写该计划的原始 `R`。首版不加仓，
也不做部分止盈，以避免同时改变入场假设和退出口径。

### 9.3 风险定仓

```text
risk_budget = current_equity * risk_per_trade
quantity_by_risk = floor(risk_budget / initial_r_cash_per_lot)
```

再依次受以下约束：

```text
历史有效保证金占用 <= max_capital_share
组合总初始风险 <= max_total_open_risk
同时持仓数 <= max_concurrent_positions
同板块持仓数 <= max_positions_per_sector
单品种和相关性集群风险上限
```

资金占用按历史有效保证金计算，不按名义本金直接封顶：

```text
margin_per_lot = actual_trigger * contract_multiplier * historical_margin_rate
                 + estimated_entry_fee
quantity_by_capital = floor(
    current_equity * max_capital_share / margin_per_lot
)
final_quantity = min(quantity_by_risk, quantity_by_capital, portfolio_limits)
```

一手合约的压力损失超过单笔风险预算时，拒绝交易并记录
`RISK_ONE_LOT_EXCEEDS_BUDGET`。不能缩短止损、使用未知乘数或用当前保证金回填历史。

### 9.4 信号竞争

同一执行事件出现多个候选时，只能使用决策时已知的质量字段排序。首轮排序键为：

```text
1. 大周期最低趋势证据分数，降序
2. 楔形减速程度，升序
3. 到障碍空间的 R 倍数，降序
4. 压力成本 / R，升序
5. symbol，稳定字典序
```

不得使用未来 MFE、最终盈利或回测结束后的品种排名竞争仓位。

## 10. 持仓管理与退出

### 10.1 管理模式

首版固定为 `SWING`，计划创建后不可把亏损交易临时改成更长周期持仓，也不可因为普通回调
把原计划改成短线。首版不做加仓和部分止盈。

### 10.2 保护性止损

结构止损在入场计划中预先计算，并以 contingent bracket 随入场单提交。只有入场发生后，
保护单才在更大的事件序号上激活，不能在入场之前成交。

若同一根 1 分钟 OHLC 同时覆盖入场价和止损价，又没有更细数据证明顺序，则采用不利路径：
先成交入场，再成交保护止损。若当时的交易所、网关或回放能力不支持 contingent bracket，
保护单只能从下一可执行事件激活，并必须记录 `unprotected_until`；不能假定成交前已有保护单。

### 10.3 保本与利润地板

使用初始 `R` 计算已实现前的最大有利波动：

```text
peak_r = favorable_price_move / initial_r_price
```

默认规则：

```text
peak_r >= 1.0  -> 候选止损不低于 0R
peak_r >= 2.0  -> profit_floor_r = peak_r - 1.0R
```

多头最终候选止损取现有止损、保本价、利润地板和已确认 5 分钟摆动低点跟踪止损中的最大值；
空头取最小值。止损只能向盈利方向移动。

任何由当前 1 分钟 K 线新峰值计算出的止损，只能从下一根 1 分钟事件生效。不能用当根新峰值
形成的新地板，再按同一根 K 线内的较优价格退出。

### 10.4 5 分钟结构跟踪

只有已经因果确认的顺势摆动点才能更新跟踪止损：

```text
多头：confirmed_swing_low - trailing_buffer
空头：confirmed_swing_high + trailing_buffer
```

摆动点仍须记录 `pivot_time` 和 `known_at`。新止损在 `known_at` 后的下一执行事件生效，
不能回填到摆动点发生时。

### 10.5 无进展时间止损

持仓达到 `time_stop_small_bars=12` 根完整小周期 K 线后，若：

```text
MFE < time_stop_min_mfe_r * initial_r_price
```

则在下一可交易 1 分钟事件退出。时间窗口按已完成小周期 K 线计数，休市时间不计入。

### 10.6 大周期反转与换月

1. 任一大周期明确切换到持仓反方向时，下一执行事件退出。
2. 大周期仅变为中性时停止新增风险，不强制立即退出已有仓位。
3. 实际合约临近交割或主力映射切换时，按有效期规则关闭旧合约。
4. 首版不进行“平旧开新”的无条件合成移仓；新合约需要新的可交易计划。

### 10.7 退出优先级

同一执行事件可能触发多个退出时，按以下顺序：

```text
1. 交割、交易禁令、元数据或合约生命周期强制退出
2. 已生效保护性止损
3. 已生效利润地板或结构跟踪止损
4. 大周期明确反转退出
5. 无进展时间止损
6. 回测区间结束的强制结算
```

若 OHLC 无法证明事件先后，采用不利成交或标记不可判定，不能以最高收益路径排序。

## 12. 状态机总览

策略主状态与订单、持仓状态分离：

```text
WAIT_LARGE_ALIGNMENT
  -> WAIT_MIDDLE_COUNTERTREND
  -> TRACK_SMALL_PUSH_1
  -> TRACK_SMALL_PUSH_2
  -> TRACK_SMALL_PUSH_3
  -> WAIT_SMALL_RESUMPTION
  -> CANDIDATE_READY
  -> ORDER_WORKING
  -> POSITION_OPEN
  -> COOLDOWN
```

关键原则：

1. 市场形态状态不依赖是否下单或是否成交。
2. 订单过期不改变已经发生的三推计数，但该形态不能重复发单。
3. 组合风控拒绝候选时，形态仍保留为完整候选并记录拒绝码。
4. MFE、MAE、止损和最终盈亏不能反过来决定某个历史结构是否是三推。
5. 大周期或中周期失效时，取消挂单并重置未完成小周期结构。

## 13. 候选、拒绝码与审计字段

### 13.1 何时生成候选行

为避免每根 K 线产生大量无意义拒绝，首版在以下时点生成可审计候选：

1. 第三推已经因果确认，并进入恢复信号等待窗口。
2. 恢复信号出现，或等待窗口结束。

中周期和小周期尚未达到该阶段的普通状态变化写入 `setup_state_events.csv`，不伪装成交易候选。

## 15. 测试设计

### 15.1 周期和聚合测试

1. 默认和自定义周期能正确解析。
2. 大、中、小、执行周期顺序错误时配置失败。
3. 15 分钟和 5 分钟桶不跨 segment，缺一分钟即不发布。
4. 夜盘正确归属交易日。
5. 正常周、节假日短周和缺数据周分别形成完整、完整和不可用状态。
6. 当前未完成周线、日线和 15 分钟线不能进入小周期决策。

### 15.2 大周期趋势测试

1. EMA 排列成立但斜率、效率和结构不足时不得放行。
2. 周线多头、日线空头时不得生成任一方向候选。
3. 两层多头与两层空头样本严格镜像。
4. 大周期中性只阻止新开仓，大周期反向才触发上下文退出。
5. 预热不足和 ATR 不可用时为 `UNAVAILABLE`。

### 15.3 中周期状态机测试

1. 单根逆向 K 线不能进入 `ACTIVE`。
2. 第二根确认后状态只在第二根 `bar_end` 生效。
3. 回调长度不足、深度不足、过深和超时分别给出稳定状态与拒绝码。
4. `MATURE -> RELEASED` 的一根宽限可接纳恢复信号，超过宽限必须过期。
5. 大周期失效后中周期锚点和小周期推进全部清空。
6. 多空镜像序列产生镜像状态和深度。

### 15.4 三推楔形测试

至少构造以下确定性 K 线序列：

1. 标准三推向下楔形加多头恢复信号，产生一个候选。
2. 标准三推向上楔形加空头恢复信号，产生一个候选。
3. 三个连续新低但无两次反弹，只算一个推进。
4. 只有两推，不生成候选。
5. 第三推明显加速，拒绝为 `WEDGE_GEOMETRY_INVALID`。
6. 三推合格但无恢复信号，等待期后拒绝为 `WEDGE_SIGNAL_MISSING`。
7. 同一楔形多根恢复 K 线只生成一个候选。
8. 跨 segment 的三推失效。
9. 相同价格平台按确定性 tie-break 只记一个摆动点。

### 15.5 因果性测试

#### 前缀不变性

```python
full = compute_all_events(frame)
for end in sampled_prefix_ends:
    prefix = compute_all_events(frame.iloc[:end])
    assert prefix.equals(full.loc[full["known_at"] <= prefix_end])
```

比较键使用 `known_at`，不能使用事后摆动点位置。

#### 未来扰动

任意修改 `signal_time` 之后的 OHLCV、换月和元数据，不得改变该时点及以前的：

```text
大周期状态、中周期事件、三推计数、候选 ID
signal_extreme、raw_actual_trigger、actual_trigger、actual_stop、quantity
```

#### 时间顺序

逐候选断言：

```text
feature_asof <= known_at <= signal_time <= decision_asof
decision_asof < order_active_at <= fill_time
```

### 15.6 成交和风险测试

1. 信号 K 线不能成交。
2. 跳空穿越触发价和止损价使用不利对手价。
3. 同根触及入场与止损采用不利顺序。
4. 当前 K 线新峰值计算出的利润地板下一根才生效。
5. 买卖停止单和限价单按订单角色正确 tick 取整。
6. 一手超过风险预算时拒绝，不缩短结构止损。
7. 缺手续费、乘数、保证金、涨跌停或实际合约映射时正式区间为
   `BLOCKED_METADATA`。

### 15.7 共享层回归

若实现需要修改现有数据加载、聚合、执行引擎、报表或图表：

1. 修改前先保存 `multi_timeframe_trend` 和 `second_leg_brooks` 的金标准。
2. 共享层纯通用化后，对其关键 CSV 做逐字节对比。
3. 默认配置下现有策略候选、交易和退出顺序必须不变。
4. 新逻辑放在新策略目录或 `engine_components/`，不能通过抬高结构测试阈值解决文件膨胀。

## 16. 回测与验证方案

### 16.1 数据切分

采用滚动 walk-forward：

```text
训练区间：确定共享规则的合理参数邻域
验证区间：在少量预声明组合中选择一个冻结配置
锁定测试区间：只运行一次，作为 OOS
```

周期组合也属于参数。不得在锁定测试区间按品种挑选最赚钱周期，也不得把全历史拟合结果称为
样本外。

### 16.2 必做消融

所有消融使用相同品种、区间、元数据、执行和成本：

1. `周线+日线` 对比 `仅日线`，衡量双大周期许可的边际作用。
2. `要求15分钟逆势成熟` 对比 `不要求中周期回调`。
3. `三推楔形` 对比 `两推`，检验第三推是否提供增量而非只减少样本。
4. `要求楔形减速` 对比 `只数三推`。
5. `恢复信号确认` 对比 `第三推确认即挂单`。
6. 成交量过滤关闭与开启。
7. 默认周期组合与预先声明的邻近周期组合。

消融是研究诊断，不能拿最赚钱分支替换已经锁定的 OOS 主结果。

### 16.3 压力测试

至少运行：

```text
基础成本、1.5 倍、2 倍和 3 倍成本
订单延迟 1 根和 2 根执行 K 线
所有 OHLC 同根歧义采用不利顺序
涨跌停无法成交和跳空越过止损
参数邻域扰动
leave-one-symbol-out
leave-one-sector-out
组合相关性和板块集中度压力
```

### 16.4 完整漏斗

按方向、品种、板块、周期配置和 walk-forward 折报告：

```text
middle episodes
-> mature middle episodes
-> three-push structures
-> resumption signals
-> candidates
-> eligible plans
-> orders
-> fills
-> round trips
```

并报告：

```text
总收益、年化收益、最大回撤、Sharpe、Calmar
胜率、平均盈亏比、profit factor、每笔净期望
手续费、滑点、成本/R、中位 MFE、MAE、持仓时间
品种和板块风险贡献、最大集中度、未成交率、拒绝码分布
```

### 16.5 研究晋级条件

进入下一阶段至少要求：

1. 所有因果、聚合、镜像、成交和元数据测试通过。
2. 锁定 OOS 在真实成本后具有正净期望，而不是依赖单一品种或少数交易。
3. 1.5 倍成本和一根执行延迟下核心结论不翻转。
4. 参数邻域不存在孤立收益尖峰。
5. 多头、空头、品种、板块和年份失败样本全部保留并解释。

这些是验证门，不是预先承诺的结果。

## 18. 可能失效的市场环境

1. 周线和日线均线滞后，趋势已经末期但仍保持多头或空头排列。
2. 15 分钟回调实际是大周期反转初段，三推后只有短暂反弹。
3. 极窄交易区间频繁生成局部摆动点，但交易空间不足以覆盖成本。
4. 单边加速行情没有两个合格反弹，策略会主动错过，而不是追价。
5. 突发政策、库存、宏观或海外事件造成跳空穿越结构止损。
6. 涨跌停、夜盘流动性下降或主力迁移使理论触发无法成交。
7. 过大的 `pivot_right` 和恢复确认造成入场过晚，过小则增加噪声三推。
8. 周线样本少，参数搜索自由度相对过高，容易产生不稳定结论。
9. 同板块品种同步出现候选，若组合限制不足，会把一个主题风险重复下注。

## 19. 策略流程伪代码

```python
for execution_event in replay:
    publish_new_completed_bars(execution_event)

    large = latest_complete_large_contexts()
    direction = require_all_large_timeframes_aligned(large)
    if direction is None:
        cancel_unfilled_plans(reason="LARGE_NOT_ALIGNED")
        manage_existing_positions(execution_event)
        continue

    middle_event = advance_middle_countertrend(
        latest_complete_middle_bar(),
        large_direction=direction,
    )

    wedge_event = advance_three_push_tracker(
        latest_complete_small_bar(),
        middle_event=middle_event,
        large_direction=direction,
    )

    if wedge_event.resumption_confirmed:
        candidate = build_candidate(
            large=large,
            middle=middle_event,
            wedge=wedge_event,
        )
        plan = validate_metadata_risk_and_session(candidate)
        if plan.accepted:
            activate_no_earlier_than_next_execution_event(plan)

    match_orders_with_actual_contract(execution_event)
    manage_positions_with_previously_active_stops(execution_event)
    schedule_new_stops_for_next_event(execution_event)
    append_audit_rows()
```

## 20. 首版验收标准

### 20.1 工程验收

1. 默认 `1w+1d / 15m / 5m / 1m` 与自定义合法周期均可构建完整因果事件流。
2. 所有高周期快照满足 `feature_asof <= signal_time`。
3. 所有摆动点同时保存 `pivot_time` 和 `known_at`，不存在历史回填交易。
4. 每个三推结构最多一个候选，所有拒绝均可从稳定拒绝码解释。
5. 实际合约、手续费、滑点、保证金、涨跌停、部分成交和换月全部进入回放。
6. 共享层改动不改变现有策略默认回测产出。
7. 全部既有测试和新增测试保持通过。

### 20.2 研究验收

1. 先报告完整漏斗，再报告收益指标。
2. 多头和空头、品种和板块分别报告，不用组合总收益掩盖集中度。
3. 默认策略与每项消融只改变一个因素。
4. 正式结果只来自元数据完整的实际合约回放。
5. 锁定 OOS、压力成本和执行延迟结果均保留，不因亏损删除品种或区间。

## 21. 一句话总结

这套策略不是“周日线多头就逢低买”，而是一个严格的四层事件链：

```text
周线与日线共同确认大方向
-> 15 分钟形成真正的反向回调
-> 5 分钟回调内部完成三次、由反弹分隔且逐步减速的推进
-> 5 分钟重新顺大方向
-> 下一根 1 分钟事件才允许在实际合约上成交
```

任何一环缺失、未完成或无法审计，都不产生正式交易。
