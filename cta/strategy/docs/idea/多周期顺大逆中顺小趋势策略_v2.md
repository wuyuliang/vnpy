## 1. 给"顺大"定价：周线共振实测为负

v1 §5 把"周线与日线共振"作为方向许可的硬条件，这是它区别于其他几份文档的
核心设计。**这一层可以用现有数据直接定价，不需要写代码。**

`second_leg_brooks`（5 分钟回调做空，无任何大周期许可层）的 466 笔已经在盘上。
按入场日**前一日收盘**的日线 EMA、**前一根已完成周线**的周线 EMA 分组：

| 许可层 | n | 净 | 期望 R | 胜率 | PF |
| --- | ---: | ---: | ---: | ---: | ---: |
| 无（全样本） | 466 | −114,260 | −0.107 | 39% | 0.58 |
| **只要日线空头** | **162** | −9,782 | **−0.045** | 43% | 0.88 |
| 只要周线空头 | 70 | −27,783 | **−0.173** | 33% | 0.38 |
| **周线 ∧ 日线共振** | **24** | −11,361 | **−0.236** | 29% | **0.29** |
| 周线多头（大逆势） | 311 | −66,039 | −0.094 | 39% | 0.62 |

**三个读法：**

1. **日线层有效**：−0.107 → −0.045，砍掉 65% 的交易和 91% 的亏损。
2. **周线层不但没有叠加，反而把结果拉回去**：单用周线是 −0.173，
   共振是 −0.236 —— 全表最差。
3. **共振把样本从 162 砍到 24**，减少 85%。

### 1.1 必须说清的三条保留

这个结果**不足以判死刑**，但足以否定"共振是免费的正收益"这个前提：

- **n=24 太小**，本身不构成结论。
- **2026H1 是 88% 品种上涨的单边行情**（上涨品种占比 88%、涨幅中位 +9.2%），
  周线空头只占 15% 的交易日。在这种环境里"周线空头"往往意味着**逆着主升浪的
  个别弱势品种**，而不是"确认的大周期下跌"——这正是它表现更差的可能原因。
- 用一个做**空**策略去给"共振"定价，只测到了共振的空头一侧。多头一侧
  （周线∧日线多头，占 34.2% 的交易日）**没有可用的样本**——
  `multi_timeframe_trend` 只有日线层，没有周线层。

**但第 3 条保留反过来是更强的警告**：共振多头占 34.2%、共振空头只占 5.9%
（全品种 3,800 个交易日样本）。也就是说在当前数据上，**这个策略的空头一侧
天然只有多头一侧的 1/6 机会**，而 v1 §1.1 是按完全镜像设计的。

## 2. 样本量算术：这是最可能的失败方式

v1 从 §5 到 §7 串了四层硬门：

```
顺大：周线 ∧ 日线共振
逆中：15 分钟逆势回调成熟且未破坏大结构
顺小：5 分钟三推楔形
恢复：第三推后的顺大方向恢复信号
```

**没有人算过这四层乘完还剩多少。**用手边的实测基数估一遍：

| 层 | 存活率 | 依据 |
| --- | ---: | --- |
| 起点：5 分钟回调结构候选 | 1,232 | `brooks_v1` 实测（40 品种 / 半年） |
| × 顺大（共振） | ~5% | §1 实测 24/466 |
| ≈ | **~62** | |
| × 顺小（三推楔形 / 普通回调） | 1/5 ~ 1/10 | 保守估计，三推远比"一次回抽"罕见 |
| ≈ | **6 ~ 12** | |

**落点 6~12 笔 / 40 品种 / 半年。**

这个量级已经踩过一次：`second_leg_down` 第一版就是 9 笔，当时的结论是
"半年 9 笔，统计上什么都说明不了"，随后花了好几轮把它放宽。
**v1 的默认配置会把这个坑原样再踩一遍，而且更深**——因为它多了周线层。

> 更糟的是它**不可救**：放宽三推楔形就不是三推了，放宽共振就不是"顺大"了。
> 这两个都是 v1 的定义性特征，不像 `big_body_atr_mult` 那样可以调。

### 2.1 所以先量，不要先写

v1 §17.1 的实现顺序是"周期与聚合 → 大周期 → 中周期 → 小周期 → 候选 → runner"。
**在这之前插一步 §4.1 的漏斗估算**，成本是几小时，能省掉整个实现周期。

## 3. 数据能不能支撑 v1 的验证方案

v1 §16.1 要求滚动 walk-forward（训练 / 验证 / 锁定 OOS）。实测数据现状：

### 3.1 分钟数据：61/69 个品种只有 7 个月

`cta/data/origin/minute` 实测：

| 起始日早于 | 品种数 |
| --- | ---: |
| 2025-01-01 | **3**（AG 2020-01、CU 2010-01、RB 2010-01） |
| 2025-07-01 | 7 |
| 2026-01-01 | 8 |

其余 61 个品种都从 2026-01-05 开始。**一折 walk-forward 都跑不出来。**

### 3.2 周线层的额外约束：只有 21 根

这是 v1 独有的问题。2026H1 每个品种的**已完成周线根数中位是 21**。

`daily_ema_slow = 20` 的周线版本需要至少 20 根才刚刚能定义，
**这半年只够定义一次，谈不上"状态切换"的统计**。周线层的迟滞、
共振切换、失效判定（v1 §5.4、§5.5）在这个样本上**全都无法验证**。

> 一句话：**周线层需要至少 3~5 年的历史才谈得上验证。**
> 日线数据够（RB 回到 2009-03），但信号层要的分钟数据不够。

### 3.3 这决定了改造顺序

在补数据之前，**唯一能做的有意义验证是"同区间、同品种、同逻辑下的相对比较"**。
绝对收益判断（"这个策略能赚钱"）在 2026H1 上一律不成立。

## 4. 建议的改造：把共振从硬门降级为审计列

### 4.1 第一步：漏斗估算（不写策略）

扩 `cta/analysis/second_leg_down_funnel_scan.py`，在 15 分钟上复刻
v1 §7.3 的三推楔形判据，数一下四层各自的存活数。判据：

- 最终候选 **≥ 300** → v1 的默认配置可行，按原计划实现
- 60 ~ 300 → 可行但需要放宽某一层，**先决定放宽哪层再写代码**
- **< 60** → 默认配置不可行，走第二步

按 §2 的估算，大概率落在第三档。

### 4.2 第二步：把顺大层做成可分级的配置（不写新策略）

不要写死"周线 ∧ 日线共振"。改成：

```python
trend_permission_mode: str = "daily"   # daily | weekly | both | audit_only
```

- `daily`（**建议首轮默认**）：只用日线许可。§1 实测这一层是有效的。
- `both`：v1 的原设计。
- `audit_only`：不做过滤，只把周线状态写进候选表的审计列。

**`audit_only` 是最有价值的一档**：它让每一轮回测都在积累"共振到底值不值"的
证据，而不用牺牲样本量。等积累到几百笔共振样本，再决定要不要把它升级成硬门。

这正是本仓库已经用过一次的模式——追高影子单（`chase_high_virtual_enabled`）：
真实追高关掉，但影子单继续跑，用来持续观察"现在追高到底灵不灵"。

### 4.3 第三步：先在日线单层上跑通三推楔形

`trend_permission_mode="daily"` + 15 分钟逆中 + 5 分钟三推。
这条链的样本量估算是 ~62 × (1/5~1/10) 的 5 倍 ≈ **30~60 笔**，
勉强够看趋势，且每一层都能单独消融。

**只有这条链跑出正期望，才值得回头加周线层。**

## 5. 参数纪律：三类参数，不要混

v1 §4.3 只说了"价格距离优先用 ATR / tick / 比例表达"，方向对但不够。
移植周期或改周期组合时，参数必须先分类——混淆这三类是最常见的错误：

### A 类：按"根数"定义 → 换周期必须重标

三推楔形的推进根数、回调根数上下限、摆动点确认的左右根数、订单有效期根数、
无进展时间止损根数。

**例外：分位数的样本量不要跟着除。**`volume_lookback` 这类参数是分位数的
样本量而不是时间窗，从 20 根除到 7 根之后 `quantile(0.80)` 基本等于
"取第二大"，噪声极大。

### B 类：按 ATR 归一化 → **分母是哪个周期的 ATR 决定要不要改**

这是 v1 §4.3 漏掉的关键区分。`multi_timeframe_trend` 上有现成的教训：

- `trailing_buffer_atr = 0.2` 的分母是**入场周期自己的 ATR**
  → 换周期时**数值不改**，含义自动跟着放大（15 分钟 ATR ≈ √3 × 5 分钟 ATR）。
- `max_entry_stop_distance_atr = 0.8` 的分母是**日线 ATR**
  → 换到更大的入场周期后，分子（结构止损距离）变大而分母不变，
  **沿用原值会把大量合格信号判成"止损太远"**，必须放宽。

**v1 §9.1 的结构止损、§10.4 的 5 分钟结构跟踪都涉及这个区分，
实现时要逐个标注分母。**

### C 类：按"分钟"或"天"定义 → 一律不改

交易时段窗、`order_max_recess_minutes`、隔夜减仓提前量、区间回看天数、
组合风控（并发数、板块集中度、日内熔断、风险比例、保证金利用率）。

## 7. 工程地雷（都踩过，v1 §18 只列了市场层面的）

1. **时段开盘那根集合竞价 K 线被丢。**21:00 / 09:00 的成交回报在加载阶段被
   `_time_in_segment` 的左开区间丢掉——2026-03 全品种 1,474 根 / 268 万手。
   跨休市的峰值会晚一根确认。见 `../2026-09-05-profit-floor-session-open-bar-trace.md`。
2. **入场时间窗要判在下单那一刻**，不是形态收尾那一根。判形态根会把边界上
   那一根白白作废，而开盘后头十分钟正是形态最密集的区间。
3. **同一结构会连续开单。**结构成立后的几根都会重新匹配同一个摆动点和同一个
   回抽极值，止损位完全相同——同一笔交易下三次、风险三倍。必须去重
   （v1 §7.7 的"一形态一候选"要落到实现，不能只写在文档里）。
4. **资金上限会和风险下限打架。**结构止损越贴身 → R 越小 → 手数越多 →
   先撞资金上限；截断后总风险掉到下限以下就整单作废。
   `brooks_v1` 里 `RISK_BELOW_MINIMUM` 62 次、`CAPITAL_LIMIT` 82 次。
   **不要靠把下限调到 0 来"解决"。**
5. **闸门会静默失效。**`brooks_v1` 报告里
   `high_gap_classification: fail-open 40/40（100%）`——同类缺陷在
   `multi_timeframe_trend` 上修过一次又复现了。
   **每轮回测都要确认"闸门降级警告"那一节为空。**
6. **日内熔断会截断样本。**`brooks_v1` 里 `DAILY_LOSS_CIRCUIT_BREAKER`
   拒绝 315 次，是最大单项。策略亏钱时它不断触发，会让漏斗看起来像形态问题。
   **做消融时要单独关掉跑一次**，否则分不清是形态差还是被风控挡住。

## 8. 验收（收紧 v1 §16.5 / §20）

沿用 v1 的工程验收，补四条：

- 原型（向量化复刻）与生产实现的候选数在 **±15%** 以内
- `multi_timeframe_trend` 与 `second_leg_brooks` 的 `trades.csv`
  在共享层泛化前后**逐字节一致**
- 每轮回测报告的"闸门降级警告"一节为空，或每条都有解释
- **候选数 ≥ 60**，否则后面的指标不必看

研究晋级门槛改成：

- **在至少两段行情性质不同的区间上，组合每笔期望 R > 0**
- 多头、空头分别看都不是单侧贡献全部收益
- 成本 1.5x 压力下期望 R 仍 > 0
- **单一区间上的正收益不构成通过**

最后一条是本轮最贵的教训：前作 `多周期趋势回调策略_claude.md` 就是拿单一
上涨区间的相对比较，推出了一个绝对水平的结论。
