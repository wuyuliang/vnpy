# 浮盈回吐与跨休市减仓方案

基准运行：`20260904_161925_372443_20260101_20260701_1d_5m_1m`
（55 笔，+217,013 / +21.70%，PF 3.18，回撤 5.32%）

起因：3 月 9 日两笔持仓浮盈巨大，3 月 10 日开盘跌很多。
本文先把这件事量化，再给方案。**只写方案，不含代码改动。**

仍然只往 `summary` 里塞旧键，导致新标签取不到值（下一次跑会全部显示 `N/A`）。已一并补齐：

## 三、⚠️ 样本极其单薄，必须说在前面

上面两张表最刺眼的那一档（峰值 >8R、休市浮盈 >6R）**本质上就是 L 和 PP 这两笔，
就是 3 月 9 日那一个晚上**。">6R" 那 5 个时点里有 4 个是同样这两个持仓在不同断点被重复计数。

所以：

- **现象是真的**，用户直接观察到了，逐笔数据也对得上；
- **机制讲得通**（陡峭拉升 → 结构止损远离 → 跳空一次性打穿）；
- **但统计上是 n=1 个事件**。任何在这上面拟合出来的阈值都不可信。

因此下面的方案按"机制是否成立"来设计，**不按这两笔去调参**，
并且必须在 2025 区间做样本外验证之后才能定稿。

## 四、方案

### 方案 A（主）：浮盈锁定 —— 峰值回撤保护

不管在不在休市前，只要浮盈到过一定高度，就不允许回吐超过一定比例。

```python
profit_lock_arm_r: float = 3.0        # 浮盈达到 3R 后启动锁定；0 表示关闭
profit_lock_giveback: float = 0.4     # 最多回吐峰值的 40%（即至少留住 60%）
```

语义：记录持仓期间的峰值浮盈 `peak_r`；一旦 `peak_r >= profit_lock_arm_r`，
把止损上移到不低于 `entry + peak_r * (1 - profit_lock_giveback) * R`，
与结构移动止损取**更有利的一个**（只上移、不下移）。

选这个当主方案的理由：

- 覆盖面比"跨休市"宽。L 从 03-06 起就一直在 6R 以上待着，
  中间经过 4 个休市断点，问题不是某一个断点，而是**整段持有期都没有利润保护**。
- 用现成的 60% 留存做锚：2–8R 档位实测留存就是 0.60，
  取 `giveback=0.4` 相当于把高浮盈档拉回到中浮盈档已经在做到的水平，
  **不是凭空拟合出来的数字**。
- 盘中连续生效，不依赖一天两次的检查点。

### 方案 B（辅）：跨休市前的高浮盈减仓 —— 用户原提案

现有 `pre_break_protection` 已经在做"休市前浮盈不足就平掉"，
方案 B 是它的**镜像**：休市前浮盈过高也要处理，因为跳空是双向的，
而浮盈越厚意味着敞口越大、跳空的绝对损失越大。

```python
pre_break_max_unrealized_r: float = 4.0    # 休市前浮盈超过该值触发；0 表示关闭
pre_break_profit_take_scale: float = 0.5   # 减到原仓位的一半
```

在已有的 `overnight_reduction_minutes` 检查点上判定，落 `PRE_BREAK_PROFIT_TAKEN` 出场码。
减仓而不是全平，是因为 3–6R 那一档跨休市其实是赚的（平均跳空 +1.72R，最终 +2.73R），
一刀全平会把这部分也砍掉。

### 关于"当日涨幅过大"这个触发条件

数据上它确实和坏跳空相关（当日涨幅 >4% 的 7 个时点平均跳空 -2.85R），
但它和"休市时浮盈高"高度重合——L 在 3/9 是涨幅 5.2% 且浮盈 12.2R，两个条件同时命中。

用**浮盈**而不是**涨幅**作触发更好，理由是：浮盈直接刻画我们自己的敞口和风险，
而涨幅刻画的是市场，同样的涨幅对早入场和晚入场的持仓意味着完全不同的风险。
建议把当日涨幅留作**观察指标**写进审计，先不做成触发条件。

## 五、不要相信的数字

我算过一个"如果每笔至少留住峰值的 X%"的估算：

```
至少留存 50%: 395,523
至少留存 60%: 456,618      (当前 217,013)
至少留存 70%: 523,130
```

**这个数字是假的，不能拿来当预期收益。** 它用了事后才知道的峰值，
相当于假设每次都能在峰值附近精准离场。真实的锁定规则只能在**回撤发生之后**才触发，
拿到的一定明显少于这里。它唯一的用途是说明**上限空间有多大**（约 18 万到 30 万），
证明这个方向值得做，仅此而已。

真实效果**只能靠重跑回测测量**，因为：

- 提前离场会释放持仓槽位，改变后续成交集合；
- 锁定止损会改变 `mfe_r` / `mae_r` 本身；
- 减仓会与 `RISK_BELOW_ONE_LOT`、保证金上限互相作用。

## 六、建议顺序与验收

1. **方案 A 单独跑一次**（`profit_lock_arm_r=3, giveback=0.4`），与基线对比。
2. **方案 B 单独跑一次**（`pre_break_max_unrealized_r=4, scale=0.5`），与基线对比。
3. 两者都为正再合起来跑。**不要一次同时上**——它们作用在同一批交易上，
   混在一起就分不清谁的贡献。
4. 参数敏感性：`arm_r` 扫 2/3/4/6，`giveback` 扫 0.3/0.4/0.5。
   **看的是曲线是否平缓，不是找最优点**；只在某一个点好看就是拟合。

验收指标（除总收益外必须一起看）：

- 峰值 >4R 那几笔的**留存比例**是否从 0.20 提升到 0.5 以上；
- 最大回撤不劣化；
- **成交笔数不应明显下降**——如果掉很多，说明锁定止损被过早触发，
  把本来能跑的趋势提前砍了，那是反效果；
- `mfe_r` 分布整体左移是正常的（提前离场本来就会压低峰值），
  但 `net_r` 的均值必须上升，否则规则没有意义。

## 七、局限

1. 全部结论基于 55 笔、单个 6 个月区间，且最关键的证据集中在 **1 个交易日**。
2. 该区间多品种单边上行，高浮盈样本天然偏多；震荡或下行区间里
   "浮盈到 3R"本身就很罕见，方案 A 可能几乎不触发。
3. 方案 A 与既有的结构移动止损、`pre_break_protection`、回撤减仓三者叠加后的
   交互没有验证过，必须逐条上。
4. 上一轮文档里提到的月度集中度问题（40/55 笔来自 3 月）依然存在，
   这仍然是比本文任何方案都更值得优先解决的稳健性问题。
