# PROFIT_FLOOR 晚成交 14 分钟：L-000167 逐根 K 线追踪

## 1. 结论先说

**引擎没有延迟成交。** 从触发到成交严格是"下一根开盘"，一根不多。

真正的问题在更上游：**每个交易时段开盘那一刻的集合竞价成交价，在加载阶段就被
丢掉了**。夜盘 21:00 那根（L2605 在 2026-03-09 是 8627，成交量 10575 手）从来
没有进入引擎，所以 21:01 那根用来判定的地板，还是六个小时前 15:00 收盘算出来
的 7823——而不是按 8627 应该算出的 8335。8325 的暴跌因此没有击穿地板。

## 2. 追踪方法

给引擎加了逐根埋点（`--trace-candidate`），把每根 K 线上"这根**进来时**已经
确认的状态"和"这根的判定结果"各记一行到 `position_trace.csv`。

```bash
python3 -m cta.strategy.multi_timeframe_trend_backtest.runner \
  --start 2026-01-01 --end 2026-04-01 --initial-equity 1e+06 \
  --symbols L --meta-root cta/strategy/brooks/cycle_v1/meta_cache/43a865c1... \
  --no-auto-metadata --chart-outcomes none \
  --trace-candidate L-000158 --run-id t_trace3
```

单品种复跑时候选编号会变（同一笔在 40 品种跑里是 `L-000167`，单品种跑里是
`L-000158`），但是同一笔、同一个现象：03-06 入场，03-09 夜盘 PROFIT_FLOOR 出场。

## 4. 缺的那根是什么

原始分钟文件 `cta/data/origin/minute/L/2026-03-09.parquet` 里有这一行：

```
2026-03-09 21:00:00  o=8627 h=8627 l=8627 c=8627  vol=10575
```

四价相同、成交量上万——这是**夜盘集合竞价的成交回报**，交易所在 21:00 打出来。

它被 `cta/strategy/brooks/cycle_v1/instruments/sessions.py` 的
`_time_in_segment` 丢掉了：

```python
def _time_in_segment(value, start, end):
    if start < end:
        return start < value <= end      # 左开右闭
    return value > start or value <= end
```

夜盘 segment 是 21:00–23:00，左端开区间，所以 `21:00:00` 不属于任何 segment，
整根被丢。这个左开右闭是**有意的**：`_complete_minute_segment` 明确要求一个
segment 恰好有 `duration` 根、第一根是 `start+1min`、最后一根是 `end`——也就是
说全套代码按"K 线以结束时刻标注"的口径写的，21:00 的标注在这个口径下等于
"20:59–21:00 这一分钟"，落在开盘之前。

问题是数据不是这个口径：开盘竞价那笔就是标在 21:00。

一个月 1,474 根开盘竞价、268 万手成交量，从来没进过回测。

## 5. 如果这根不丢会怎样

1R = (8612−7460)/12.886 = 89.40 点。

- peak 用 8627：peak_r = (8627−7460)/89.40 = **13.054R**
- 回吐 = max(1R, 0.25×13.054) = **3.264R**
- 地板 = 13.054 − 3.264 = 9.791R → 7460 + 9.791×89.40 = **8335**
- 21:01 最低 8325 ≤ 8335 → **击穿**
- 21:02 开盘 8378 成交（1 跳滑点后 8377）

正是你预期的 21:02 / 8378。相对实际的 8329，这一笔多 48 点 × 22 手 × 5 =
**+5,280 元**。按 40 品种那次跑的参数（1R=66 点、剩 24 手）算，地板是 8351.5，
同样在 21:01 击穿，8377 vs 8338 = **+4,680 元**。

## 6. 修法不是改 `_time_in_segment` 一行

把左端改成闭区间，夜盘每段就会变成 `duration+1` 根，
`_complete_minute_segment` 会把**所有**夜盘段判成不完整——5 分钟和日线聚合会
整片消失。这比现在的问题严重得多。

可行的方向，按侵入性排序：

1. **只在回放流里补这根**（推荐）。聚合用的 minute 序列保持现状（`duration`
   根、bar-end 口径不变），回放驱动的 `events` 额外接纳开盘竞价那根。地板、
   MFE/MAE、保护性止损都能第一时间看到开盘价，聚合契约一行不改。
   风险：开盘竞价那根会变成可成交的一分钟，挂单可能在竞价成交——这更贴近实盘，
   但会改变一部分入场，需要跑 A/B。
2. **把开盘竞价并进 segment 第一根**（21:00 并进 21:01）。聚合契约同样不动，
   但对本案**无效**——并进 21:01 之后，8627 仍然是"当根"高点，当根不能用来判当根。
3. 改口径为左闭右开并同步改 `_complete_minute_segment`。改动面最大，会重算
   历史上每一根 5 分钟和日线，不建议在这个问题上动。

## 7. 顺带确认的两点

- `_manage_open_position` 的"击穿只挂起、下一根开盘成交"逻辑本身是对的，
  逐根记录里每次都严格隔一根。
- 这一笔没有触发过 `ROLL_MAPPING_CHANGED`，也没有 limit-lock；14 分钟里
  `pending_reason_in` 一直是空。之前怀疑的换月/涨跌停两条路径都排除了。
