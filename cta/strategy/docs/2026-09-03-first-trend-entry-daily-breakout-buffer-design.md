# 趋势首笔日线实体突破缓冲设计

## 目标

在现有前五根已完成日线实体极值过滤基础上，为多头趋势段尚未发生任何已成交开仓时的候选增加可配置突破缓冲，并比较 AG 与 top5 在 `0%`、`0.05%`、`0.1%`、`0.15%`、`0.2%` 下的净收益和最大回撤。

## 现有行为

- 日线实体最高值使用 `max(open, close)`，并通过 `shift(1).rolling(5)` 只读取当前日线以前的五根已完成日线。
- 多头候选当前仅在 `trigger < prior_5d_high` 时被拒绝，因此 `trigger == prior_5d_high` 会放行。
- 当前配置默认屏蔽空头和 `pullback_breakout`，但新规则按候选统一实现，不绑定具体信号类型。

## 参数

在 `MultiTimeframeTrendConfig` 增加标量参数：

```python
first_trend_entry_daily_breakout_buffer_ratio: float = 0.0005
```

参数必须是有限数且位于 `[0, 1)`。不增加 CLI 参数。研究比较直接用配置对象分别设置：

```python
(0.0, 0.0005, 0.0010, 0.0015, 0.0020)
```

`0.0` 表示关闭新增规则，并完整保留现有“等于前五日实体最高值时放行”的基线行为。

## 趋势段与首笔成交

多头趋势段由连续已完成日线满足 `EMA5 > EMA10 > EMA20` 定义。候选只能使用其信号时刻已经完成并可见的日线，不使用当前未完成日线。

对每个品种和候选时刻，语义等价于从后往前检查：

1. 只考虑候选时刻以前的开仓成交，不能使用同日但晚于候选的成交。
2. 如果先遇到当前连续多头趋势段内更早的开仓成交，则该候选不是趋势首笔，不应用新增缓冲。
3. 如果先遇到首个不满足 `EMA5 > EMA10 > EMA20` 的已完成日线，则当前趋势段尚无开仓成交，对该候选应用新增缓冲。
4. 被过滤、未触发或撤单的候选都不算开仓成交。只有实际开仓 fill 才会结束该趋势段的“首笔未成交”状态，即使该仓位之后已经平仓也不恢复该状态。

实现上为连续多头日线生成因果趋势段标识，并在事件回放中记录 `(品种, 趋势段)` 是否已有开仓 fill；该状态机与逐日回扫语义一致，但不会为每个候选重复扫描完整历史。

## 过滤公式

现有基础过滤保持不变。仅当参数大于零、候选方向为多头且当前趋势段尚无已成交开仓时，额外要求：

```text
trigger > prior_5d_high * (1 + buffer_ratio)
```

不满足严格大于关系时，以独立拒绝码 `FIRST_TREND_ENTRY_DAILY_BREAKOUT_BUFFER_NOT_MET` 拒绝。`trigger` 是下单前已知且按最小变动价位对齐的入场触发价；实际 `entry_price` 只有成交后才知道，不能用于事前过滤。

当前策略不交易空头，因此本次不新增空头趋势段规则。

## 数据流与审计

1. 日线上下文为每根日线计算连续多头趋势段标识。
2. 候选行携带其可见日线的趋势段标识和 `prior_5d_high`。
3. 单品种与组合事件回放在提交订单前执行新增动态过滤。
4. 开仓成交后，将该品种当前趋势段记录为已有成交。
5. 报告上下文记录配置比例，`rejections.csv` 汇总新增拒绝码。

## 测试

- 配置默认值、字符串归一化、零值和非法值校验。
- 参数为零时，相等触发价继续放行。
- 参数大于零时，严格边界及高于边界的候选分别拒绝和放行。
- 同一趋势段中，被过滤或未成交的候选不会解除缓冲。
- 同一趋势段首次开仓成交后，后续候选恢复现有无缓冲规则。
- EMA 多头排列中断后重新进入时，新的趋势段重新启用缓冲。
- 同一交易日只计算候选时刻以前的开仓成交。
- 单品种与组合回放保持一致，并在报告中记录参数和拒绝原因。

## 参数比较

对 `2025-01-01` 至 `2026-07-01` 使用同一数据、元数据、手续费、滑点、组合风控和 top5 品种集合，分别运行 AG 与 top5 的五个参数值。至少汇总：参数、交易数、净收益、总收益率、最大回撤、期末权益和新增规则拒绝数。

参数扫描使用了完整研究区间，结果属于样本内敏感性分析，不标记为 OOS。任一参数运行如存在历史交易机制或元数据缺口，按现有报告契约标记 `BLOCKED_METADATA`，不得与完整结果混合比较。

## 不在范围内

- 不增加 CLI 参数。
- 不改变现有日线 EMA、五日窗口、入场触发、手续费、滑点、仓位或隔夜保证金规则。
- 不根据扫描结果自动修改参数默认值，也不把收益最高的参数声明为正式或 OOS 最优参数。
