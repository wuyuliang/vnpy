# 多周期趋势策略跟踪止损、动态仓位与图表升级设计

## 目标

在现有多周期趋势回测中增加四项因果行为：

1. 回调突破持仓保留按实际成交价计算的 2R 目标，同时使用与 Always-In 相同的已确认摆动点跟踪止损。
2. 日线方向许可增加候选触发价突破此前五根已完成日线的条件。
3. 每张日线、1 小时和 5 分钟机会图都显示适用的最终目标，并把信号固定在图形中央。
4. 品种连续亏损或组合已实现权益回撤达到条件后，后续开仓动态减仓；两个独立系数可以叠加为 25%。

实现继续复用现有策略配置、事件引擎、图表渲染器、报告和测试，不新增通用风险框架。

## 因果时间模型

- 日线 EMA 和五日极值只使用已完成日线。
- 候选在其 5 分钟信号 K 线完成后才能决策。
- 订单最早在下一可实现的分钟事件激活。
- 跟踪止损只能在已完成的 5 分钟管理事件暴露已确认摆动点后推进。
- 仓位缩放状态只能在交易平仓且包含手续费的净盈亏已知后变化。
- 同一时间戳先处理已有持仓退出，再处理待入场订单。因此，该时间戳刚平仓产生的亏损可以限制随后入场，但未来交易不能影响更早的成交。

## 日线五日突破许可

日线 EMA 规则继续保持多空对称：

```text
long_ema_permission  = EMA5 > EMA10 > EMA20
short_ema_permission = EMA5 < EMA10 < EMA20
```

为每个 5 分钟候选附加信号时刻已知的日线极值：

```text
prior_5d_high = 此前 5 根已完成日线开盘价和收盘价的最大值
prior_5d_low  = 此前 5 根已完成日线开盘价和收盘价的最小值
```

候选的最终许可为：

```text
long_allowed  = long_ema_permission  and trigger >= prior_5d_high
short_allowed = short_ema_permission and trigger <= prior_5d_low
```

`trigger` 是候选停止单的触发价，不是未来成交价。在现有不利跳空模型下，多头停止单不会在触发价下方成交，空头停止单不会在触发价上方成交。若不足 5 根已完成日线，记录 `DAILY_FIVE_BAR_HISTORY_UNAVAILABLE`；若 EMA 已排列但触发价没有突破相应极值，记录 `DAILY_FIVE_BAR_BREAKOUT_NOT_MET`。两类候选都必须保留在漏斗中，不能静默消失。

审计字段包括 `prior_5d_high`、`prior_5d_low` 和本次使用的突破边界。

## 回调突破退出管理

入场时：

- Always-In 继续不设置固定止盈目标。
- 回调突破根据实际成交价和结构止损，以配置的 2R 倍数冻结 `final_target`。

每个已完成的 5 分钟管理事件到达后，两种入场模式都调用现有已确认摆动点跟踪止损规则。止损只能向有利方向移动。回调突破持仓在移动后的止损或冻结的 2R 目标首次可实现触发时退出。若同一分钟同时触及止损和目标且没有更细粒度数据，继续采用保守的止损优先结果。

计划表保留按触发价推导的计划目标；交易表记录 `final_target`，从而在报告和图表中区分计划目标与实际成交后的目标。

## 仓位缩放状态

### 配置

以下参数只写入 `MultiTimeframeTrendConfig`，不增加 CLI 参数：

```text
symbol_loss_streak = 2
symbol_position_scale = 0.5
portfolio_drawdown_threshold = 0.01
portfolio_position_scale = 0.5
```

连续亏损笔数必须为正整数，组合回撤阈值必须为正数，缩放系数必须位于 `(0, 1]`。回测上下文和汇总报告必须保存本次实际使用值。虽然复现命令不覆盖这些值，报告仍能暴露所使用的配置。

### 品种状态

每个品种维护确定性的连续净亏损、是否处于缩放状态和待恢复缺口。

- 正常状态下，`net_pnl < 0` 时追加一笔连续亏损。
- 正常状态下，`net_pnl >= 0` 时清空连续亏损。
- 连续亏损达到配置笔数后，在该笔交易平仓后激活缩放，待恢复缺口为这些连续亏损绝对值之和。
- 缩放状态下，该品种以后每笔已平仓交易都执行 `deficit = deficit - net_pnl`。
- 后续亏损扩大缺口，部分盈利缩小缺口。
- 只有缺口严格小于 0 时才恢复正常仓位，并重置连续亏损。

触发缩放的亏损交易使用其平仓前已知的仓位，只有后续入场才减仓。

### 组合状态

组合使用扣除手续费后的已实现现金权益，不使用持仓的盘中未实现盯市权益，避免未平仓价格波动导致状态反复触发和恢复。

- 已实现权益高水位从初始权益开始。
- 正常状态下，已实现现金权益创新高时更新高水位。
- 每笔交易平仓后，若 `(high_water - cash) / high_water` 严格大于配置阈值，则激活组合缩放。
- 初始待恢复缺口为 `high_water - cash`；缩放期间冻结该高水位。
- 缩放状态下，以后所有品种的已平仓交易都执行 `deficit = deficit - net_pnl`。
- 只有缺口严格小于 0 时才恢复正常仓位。此时现金权益已经超过冻结的高水位，因此将当前现金权益更新为新高水位。

### 入场手数

在可实现的入场事件上：

```text
base_quantity = 按实际成交价和结构止损计算的风险手数
symbol_factor = 品种缩放生效时取 symbol_position_scale，否则取 1.0
portfolio_factor = 组合缩放生效时取 portfolio_position_scale，否则取 1.0
quantity_scale = symbol_factor * portfolio_factor
scaled_quantity = floor(base_quantity * quantity_scale)
```

两个默认缩放同时生效时，最终系数为 `0.25`。随后再对缩放后的手数应用现有单品种保证金、组合保证金和最大持仓数限制。缩放后不足一手时，记录 `DYNAMIC_RISK_SCALE_BELOW_ONE_LOT`；不得缩小结构止损来强制成交。

交易审计字段包括 `base_quantity`、`symbol_quantity_scale`、`portfolio_quantity_scale`、`quantity_scale`、生效原因和入场时待恢复缺口。

## 仓位缩放事件审计

新增 `position_scaling_events.csv`，每次状态变化或恢复进度写一行：

```text
event_time, sequence, scope, symbol, event_type, candidate_id,
net_pnl, realized_cash, high_water, drawdown_fraction,
position_scale, recovery_deficit
```

`event_type` 取值为 `TRIGGER`、`EXTEND`、`PROGRESS` 或 `RECOVER`。报告按品种和组合范围汇总触发次数、恢复次数和使用缩放仓位入场的次数。

## 机会图表

每张机会卡片继续包含实际合约日线、1 小时线和 5 分钟线。

- 已成交的回调突破候选使用交易记录中按实际成交价计算的 `final_target`。
- 未成交的回调突破候选使用按触发价推导的计划目标。
- Always-In 没有固定目标，因此显示 `N/A`。
- 每个面板的价格范围都纳入入场价、止损价和有限的目标价，因此即使行情尚未触及目标，也必须显示相应水平线。
- 每个面板在信号两侧预留相同数量的绘图槽位。回测区间边界缺少数据时保留空白槽位而不是移动信号，确保信号标记固定在中央。
- 信号标记右侧的 K 线继续明确标记为仅供事后复盘的数据。

现有共享蜡烛图工具增加可选的绘图槽位位置和价格范围水平线参数。其他调用方不传这些选项时保持原有行为。

## 报告

保留全部现有输出文件，并新增：

- `position_scaling_events.csv`；
- `trades.csv` 中的仓位缩放字段；
- `trades.csv` 和图表索引中的 `final_target`；
- `summary.json` 和 `report.md` 中的有效缩放配置、触发次数和恢复次数。

历史执行机制缺失时，正式区间仍必须标记为 `BLOCKED_METADATA`；新的风险逻辑不得填补或假设历史机制。

## 测试与验收标准

1. 回调突破持仓只能在已完成的 5 分钟管理事件后推进止损，并保留按实际成交价冻结的 2R 目标。
2. 止损和目标同时触及时继续采用止损优先。
3. 多头和空头候选必须分别满足对称的此前五根已完成日线突破条件，不得读取当前或未来日线。
4. 三个面板都能看到每个有限目标，且信号标记使用中央绘图槽位。
5. 品种连续两笔亏损触发缩放；触发前出现零收益或盈利会打断连续亏损。
6. 缩放状态下的亏损扩大恢复缺口，部分盈利不能恢复，只有严格超额追回后才能退出缩放状态。
7. 组合已实现权益回撤只有严格大于配置阈值时才触发缩放。
8. 品种与组合系数独立叠加为 25%；不足一手时必须明确拒绝。
9. 同一时间戳的退出必须先更新缩放状态，随后入场读取最新系数。
10. 候选、图表、交易、缩放事件和复现产物必须一一对应且结果确定。
11. 聚焦测试、受影响策略与元数据测试、Ruff 和 compileall 全部通过。
12. 重新生成 AG 和 AG+CU 报告，核对机会图、目标值、缩放手数、手续费、保证金峰值和缩放事件数。
