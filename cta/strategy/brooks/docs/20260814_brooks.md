# 中国期货 Brooks Price Action CTA 设计规范

## 0. 文档状态

- 日期：2026-08-14
- 状态：研究与实现规范，尚未构成实盘有效性证明
- 目标：把 Al Brooks 的 Market Cycle 和 Price Action 思想转成可编码、可回测、无未来函数、可跨品种验证的中国期货 CTA 系统
- 交付边界：本文件定义后续代码契约、规则、测试和研究顺序；本阶段不宣称任何收益率、胜率或特定品种必然有效
- 兼容原则：不修改 `cta/strategy/brooks/brooks.md`、`brooks_v2.md`、`brooks_v3.md`，优先复用现有 `core/`、`scalp/`、`cta/feature/` 与 `cta/risk/`

本系统只研究最容易因果化和跨品种泛化的 Brooks 思想。核心优先级固定为：

```text
Robustness > Complexity
Out-of-Sample > In-Sample
Risk Management > Entry Accuracy
Market Context > Individual Signal
真实可交易合约 > 连续合约漂亮曲线
```

本文不是投资建议。所有概率、形态优势和参数都必须由含真实成本的样本外结果确认。

## 1. 资料依据与证据边界

### 1.1 Brooks 公开资料

本规范只依据公开可访问页面和公开索引 PDF，不绕过会员限制，也不复制课程内容。主要资料包括：

3. [Coaching Session 4: Breakouts](https://www.brookstradingcourse.com/wp-content/uploads/2025/10/250906-Coaching-Session-4-Breakouts.pdf)，用于提炼强突破立即参与、缩小仓位、Always-In 和第二段行情思想。

6. [Trading ranges](https://www.brookstradingcourse.com/how-to-trade-manual/trading-ranges/)，用于提炼区间边缘交易、中部不交易、紧区间等待突破。
7. [Trend channels](https://www.brookstradingcourse.com/futures-market/trade-trend-channels/)，用于提炼紧通道、宽通道、趋势 swing 和结构止损。
8. [How to trade price action manual](https://www.brookstradingcourse.com/how-to-trade-price-action-manual/)，用于确认 context 优先、stop entry 和仓位由止损距离决定。
9. [Price Action Trading Glossary](https://www.brookstradingcourse.com/price-action-trading-terms-glossary/)，用于确认 H1/H2 是价格在回调中第一次/第二次恢复尝试，而不是交易盈亏标签。

### 1.2 中国期货规则依据

交易机制参数不能写死在策略里，原因是交易所会调整保证金、涨跌停、手续费和指令类型。例如：

- [郑州商品交易所交易规则](https://www.czce.com.cn/cn/content_file/flfg/zcjywgz/zcjjygz/2026/3/68c0dce01f984475be768ed93afd9b4f.pdf)明确交易单位、最小变动价位和涨跌停制度属于合约及交易规则。
- [上海期货交易所公告](https://www.shfe.com.cn/publicnotice/)持续发布保证金、涨跌停和手续费调整。
- [上期所 2026 年引入市价指令的通知](https://www.shfe.com.cn/eng/CircularNews/Circular/202606/t20260618_832181.html)说明订单能力本身也会随时间变化。
- [广州期货交易所碳酸锂合约](https://www.gfex.com.cn/gfex/sytslqhhy/202307/9ad927b8ec4c458594e172fd1ada2a9b.shtml)同时给出交易单位、tick、交易时段、涨跌停和保证金，并注明交易所可调整参数。

因此，历史回测必须按 `effective_from/effective_to/known_at` 使用当时可知的元数据。找不到历史证据时必须 `BLOCKED_METADATA`，不能用当前值回填。

### 1.3 三类陈述必须分开

| 类型 | 含义 | 文档写法 | 验证方式 |
|---|---|---|---|
| Brooks 思想 | 公开资料中的市场解释 | 标注为“思想来源” | 来源链接 |
| 程序化定义 | 本项目对主观概念的因果化近似 | 标注为“v0 定义” | 单元测试、前缀不变性 |
| 待回测参数 | 窗口、阈值、持有期 | 全部进入配置 | walk-forward、敏感性、锁定 OOS |

不得把 Brooks 的经验概率直接当作中国期货的先验胜率，也不得把本项目的量化近似称为 Brooks 的唯一原意。

## 2. 系统目标与非目标

### 2.1 目标

```text
大周期：决定方向许可和总风险
    -> 中周期：识别 Market Cycle 和交易模式
        -> 小周期：生成 Setup、触发价和结构止损
            -> 执行层：按真实合约、tick、时段和价格限制成交
                -> 风险层：计算仓位、组合敞口和退出
```

每根已完成小周期 bar 最终输出：

```python
@dataclass(frozen=True)
class DecisionSnapshot:
    feature_asof: datetime
    feature_sequence: int
    large_cycle: CycleSnapshot
    medium_cycle: CycleSnapshot
    small_cycle: CycleSnapshot
    always_in: AlwaysIn
    trade_mode: TradeMode
    candidates: tuple[SetupCandidate, ...]
    risk_state: PortfolioRiskState
```

### 2.2 非目标

- 不把所有 Brooks 图形术语全部程序化。
- 不追求每个品种、每年或每个 setup 都盈利。
- 不用单个 K 线或单个 EMA 交叉替代市场上下文。
- 不为了达到目标胜率反复筛选阈值。
- 第一阶段不用 ML 决定交易；ML 仅作为后续候选质量过滤器。
- 不使用连续合约直接撮合成交。
- 不在元数据、流动性或价格限制不完整时猜测成交。

## 4. 数据与时间契约

### 4.1 最小 bar schema

```text
source_calendar_date, exchange_trade_date, session_id,
bar_start, bar_end, feature_asof, feature_sequence,
root_symbol, vt_symbol, contract_code, exchange,
open, high, low, close, volume, turnover, open_interest,
pre_settlement, limit_up, limit_down,
source_path, source_row
```

约束：

1. `bar_end` 为 Asia/Shanghai 时区感知时间，表示该 bar 完整可用的最早时刻。
2. 统一比较事件键 `(timestamp, sequence)`：`feature_event <= signal_known_event <= decision_event < order_active_event`。同一时间戳时必须靠 sequence 保证先完成计算、后激活订单。
3. 夜盘通过版本化交易所日历映射到 `exchange_trade_date`，不能把文件自然日直接当交易日。
4. 真实成交必须使用 `contract_code`；`RB0` 只用于研究连续序列。
5. `(contract_code, bar_end)` 唯一且递增。
6. 缺失 bar 不向后填充 OHLCV；缺口跨 session 时不得制造虚假连续 bar。

元数据查询失败时：

```python
raise BlockedMetadataError("effective metadata is unavailable for this order time")
```

查询键至少包含实际合约和订单事件时刻；订单能力还包含 gateway/order type。`effective_from <= order_event < effective_to` 且 `known_at <= decision_asof` 才可用。订单能力按 `contract_code > root_symbol > exchange` 的特异性选择；同级重叠记录直接报错，不能任意取最后一条。`ExecutionMetadataSnapshot` 只组装同一 decision event 可知的记录，并将费用与滑点统一成 PlanGeometry 所需的 cash/tick 口径。

缺少生命周期、交易状态或订单能力分别返回 `BLOCKED_LIFECYCLE`、`BLOCKED_TRADING_STATUS`、`BLOCKED_ORDER_CAPABILITY`。不允许默认值、不允许最近值回填、不允许用昨收代替昨结算。

### 4.3 因果聚合

从基础分钟数据聚合任意周期 `T`：

```text
open_T   = first(open)
high_T   = max(high)
low_T    = min(low)
close_T  = last(close)
volume_T = sum(volume)
oi_T     = last(open_interest)
bar_end_T = 最后一根实际基础 bar 的 bar_end
```

- 不跨午休、收盘、夜盘断点制造完整 bar。
- 不完整高周期 bar 不能参与决策。
- 对齐使用 `merge_asof(direction="backward")` 或等价逻辑。
- 在小周期时刻 `t`，只允许读取 `bar_end <= t` 的大、中周期快照。
- 日线由 `exchange_trade_date` 聚合，周五夜盘应归属下一交易日，而不是自然日周五。

### 4.4 连续合约与换月

信号研究不能使用会在未来换月后重写历史前缀的传统全样本后复权序列。允许使用 point-in-time 的不可变前缀连续序列，并同时保存：

```text
raw_contract_price, adjusted_signal_price,
adjustment_scale, adjustment_offset, adjustment_known_at,
active_contract, mapping_known_at, roll_reason, adjustment_version
```

定义 `adjusted = raw * scale + offset`。换月时只用 `mapping_known_at` 已知的新旧合约同期价格更新之后 bar 的 `scale/offset`；已落盘历史 bar 永不重写。前缀不变性测试必须同时覆盖 active-contract map 和 adjustment event stream。

信号层价格映射回当前真实合约：

```python
raw_level = (adjusted_level - adjustment_offset_asof) / adjustment_scale_asof
tradable_level = round_for_order(raw_level, order_side, order_kind, order_role, tick)
```

entry、stop、target 分别映射并重新计算真实合约上的 R 和成本，不允许把连续合约点位直接发单。订单和 PnL 始终使用真实合约价格。换月规则在交易前冻结，例如按前一交易日成交量/持仓量决定下一交易日主力，禁止用当日收盘后才知道的数据回填早盘。

持仓换月状态机固定为：

```text
HOLD_OLD -> CLOSE_OLD_PENDING -> CLOSE_OLD_FILLED
         -> OPEN_NEW_PENDING  -> ROLLED
```

两腿分别撮合、收费并记录部分成交。旧仓未安全平掉时禁止先开等风险的新仓；旧仓已平而新仓未成交时保持空仓，不能假设原子换月。任一腿涨跌停锁定、临近交割、流动性迁移或映射不确定时进入 `ROLL_BLOCKED` 并禁止新 setup，不能在连续序列跳点上触发虚假 stop。

## 5. 多周期架构

### 5.1 周期角色

```python
@dataclass(frozen=True)
class TimeframeConfig:
    base_tf: str
    large_tf: str
    medium_tf: str
    small_tf: str
    execution_tf: str
```

| 层级 | 作用 | 禁止事项 |
|---|---|---|
| 大级别 | 方向许可、主要支撑阻力、风险倍率 | 不直接用未完成日线开仓 |
| 中级别 | Market Cycle、Always-In、Scalp/Swing | 不读取未来小周期结果修正状态 |
| 小级别 | Setup、signal bar、trigger、结构 stop | 不覆盖大级别硬性方向禁令 |
| 执行级别 | 订单激活、滑点、止损/目标先后顺序 | 不用 OHLC 猜同 bar 内有利成交 |

`Daily/4H -> 60m/30m -> 15m/5m -> 1m` 只是 RB/CU 研究起点，不是硬编码。

### 5.2 周期选择原则

不同品种允许不同周期，但候选集合和选择规则必须在 OOS 前冻结。v0 角色候选不是按 PnL 产生：

```text
execution/base: 最细的真实可审计数据，通常 1m
small:          5m, 15m, 30m
medium:         30m, 60m, 4h
large:          4h, 1d
```

对每个候选周期计算：

```text
bars_per_session
median_ATR_in_ticks = median(ATR / price_tick)
median_cost_to_ATR = round_trip_cost_price / ATR
zero_volume_ratio
bar_gap_ratio
```

结构周期可用门槛按角色判断，不能用日内 `bars_per_session` 淘汰日线或 4h：

```python
required_history_bars = (
    cfg.min_large_history_bars
    if role == "large"
    else cfg.min_intraday_history_bars
)
role_bar_density_ok = (
    True
    if role == "large"
    else bars_per_session >= (
        cfg.min_small_bars_per_session
        if role == "small"
        else cfg.min_medium_bars_per_session
    )
)
cost_ok = role == "large" or median_cost_to_ATR <= cfg.max_cost_to_atr

usable_for_structure = (
    complete_history_bars >= required_history_bars
    and role_bar_density_ok
    and median_ATR_in_ticks >= cfg.min_atr_ticks
    and cost_ok
    and zero_volume_ratio <= cfg.max_zero_volume_ratio
    and bar_gap_ratio <= cfg.max_gap_ratio
)
```

等价条件是：`history_ok AND role_bar_density_ok AND atr_ticks_ok AND cost_ok AND volume_ok AND gap_ok`。

选择过程是确定性的：

```python
def choose_ratio(pool, base_tf, target):
    longer = [tf for tf in pool if duration(tf) > duration(base_tf)]
    if not longer:
        return None
    return min(
        longer,
        key=lambda tf: (
            abs(log(duration(tf) / duration(base_tf) / target)),
            -duration(tf),
        ),
    )

small_tf = min(usable_small_candidates, key=duration, default=None)
medium_tf = (
    choose_ratio(usable_medium_candidates, small_tf, cfg.target_medium_small_ratio)
    if small_tf is not None
    else None
)
large_tf = (
    choose_ratio(usable_large_candidates, medium_tf, cfg.target_large_medium_ratio)
    if medium_tf is not None
    else None
)
```

`choose_ratio` 最小化 `abs(log(actual_duration_ratio / target))`；并列时选更长周期。任一角色无可用候选则输出 `UNAVAILABLE`，不回退到某个品种的“历史最赚钱周期”。`execution_tf` 始终保留最细真实成交证据；若该层数据缺失，订单标记无法判定或不成交，不能靠聚合成 5m 来制造确定成交。周期一旦进入锁定评估，不得按品种结果临时更改。

### 5.3 多周期冲突

| 大周期 | 中周期 | 许可 |
|---|---|---|
| bull | bull breakout/channel | 做多 swing；禁止做空 |
| bull | trading range | 仅底部做多 scalp/小 swing；顶部不追多 |
| bull | bear broad channel | 默认观望；只允许经验证的区间底部反转多 |
| neutral | strong breakout | 跟随突破但降低风险，等待 follow-through |
| bear | 任意 bull setup | 对称拒绝，除非独立 MTR 模块通过 OOS |

空头规则完全镜像。若大周期 `confidence` 低于门槛，不能靠小周期高分绕过。

## 6. 因果 Price Action 特征

以下全部只使用截至 `t` 已完成 bar。`eps = max(price_tick, 1e-12)`。

### 6.1 Bar 与波动

```python
bar_range = high - low
body = close - open
body_ratio = abs(body) / max(bar_range, eps)
close_pos_long = (close - low) / max(bar_range, eps)
close_pos_short = (high - close) / max(bar_range, eps)
upper_wick_ratio = (high - max(open, close)) / max(bar_range, eps)
lower_wick_ratio = (min(open, close) - low) / max(bar_range, eps)
```

ATR 使用 Wilder 递推；初始化仅用最早 `cfg.atr_period` 个已完成 TR。所有固定价格距离转成 `ATR` 或 `tick` 比例。

ADX 也只用 Wilder 递推，不能用全样本初始化：

```python
up_move = high.diff()
down_move = -low.diff()
plus_dm = where((up_move > down_move) & (up_move > 0), up_move, 0.0)
minus_dm = where((down_move > up_move) & (down_move > 0), down_move, 0.0)
plus_di = 100 * wilder_mean(plus_dm, cfg.adx_period) / (atr + eps)
minus_di = 100 * wilder_mean(minus_dm, cfg.adx_period) / (atr + eps)
dx = 100 * abs(plus_di - minus_di) / (plus_di + minus_di + eps)
adx = wilder_mean(dx, cfg.adx_period)
atr_compression = atr / (
    atr.shift(1).rolling(cfg.atr_compression_window).median() + eps
)
```

`adx` 只表示方向运动强弱，不提供方向；`atr_compression < 1` 表示当前 ATR 低于此前窗口中位数。二者第一版只作为 Trading Range 辅助门和消融项，不能覆盖价格结构。

动量衰减使用相邻、互不重叠的过去窗口：

```python
momentum_now = abs(body.rolling(cfg.momentum_window).sum()) / (
    cfg.momentum_window * atr + eps
)
momentum_prior = momentum_now.shift(cfg.momentum_window)
momentum_decay = ((momentum_prior - momentum_now) / (momentum_prior + eps)).clip(0, 1)

bull_trend_bar = (body > 0) & (body_ratio >= cfg.trend_bar_min_body_ratio)
bear_trend_bar = (body < 0) & (body_ratio >= cfg.trend_bar_min_body_ratio)
bull_trend_bar_ratio = bull_trend_bar.rolling(cfg.structure_window).mean()
bear_trend_bar_ratio = bear_trend_bar.rolling(cfg.structure_window).mean()
close_pos_long_mean = close_pos_long.rolling(cfg.structure_window).mean()
close_pos_short_mean = close_pos_short.rolling(cfg.structure_window).mean()
```

### 6.2 重叠与趋势效率

```python
overlap_i = max(0, min(high_i, high_prev) - max(low_i, low_prev))
union_i = max(high_i, high_prev) - min(low_i, low_prev)
overlap_ratio = rolling_mean(
    overlap_i / max(union_i, eps), cfg.structure_window
)

trend_efficiency = abs(close - close.shift(cfg.structure_window)) / (
    rolling_sum(abs(close.diff()), cfg.structure_window) + eps
)

direction_change_ratio = rolling_mean(
    sign(body) * sign(body.shift(1)) < 0, cfg.structure_window - 1
)
overlap_ratio_recent = rolling_mean(
    overlap_i / max(union_i, eps), cfg.bo_recent_window
)
```

### 6.3 EMA 与距离

```python
ema_fast = ema(close, cfg.ema_fast)
ema_slow = ema(close, cfg.ema_slow)
ema_slope = (ema_fast - ema_fast.shift(cfg.ema_slope_lookback)) / (
    cfg.ema_slope_lookback * atr + eps
)
ema_distance = (close - ema_fast) / (atr + eps)
ema_separation = (ema_fast - ema_slow) / (atr + eps)
```

EMA 只作为平衡区和斜率证据，不单独决定趋势。

### 6.4 结构与 swing

确认 swing 可用 `left/right` pivot，但必须记录：

```text
pivot_bar_end = 极值 bar 时间
known_at = pivot 右侧第 cfg.pivot_right 根 bar 的 bar_end
```

策略只能在 `known_at` 后使用该 swing。实时状态表按 `known_at` 写入，禁止把特征回填到 `pivot_bar_end`。另设无需等待未来 bar 的即时结构：

```python
new_high = high > high.shift(1).rolling(cfg.structure_window).max()
new_low = low < low.shift(1).rolling(cfg.structure_window).min()
```

HH/HL 分数只统计在当前时刻已确认的最近 `cfg.structure_pivot_count` 个 pivot：

```text
hh_score = higher_high_count / comparable_high_pairs
hl_score = higher_low_count / comparable_low_pairs
```

样本不足输出 `NaN`，不能输出乐观默认值。

### 6.5 突破

边界必须冻结到前一根：

```python
prior_high = high.shift(1).rolling(cfg.structure_window).max()
prior_low = low.shift(1).rolling(cfg.structure_window).min()
breakout_distance_long = (close - prior_high) / (atr + eps)
breakout_distance_short = (prior_low - close) / (atr + eps)
bull_trend_bar_count_recent = bull_trend_bar.rolling(cfg.bo_recent_window).sum()
bear_trend_bar_count_recent = bear_trend_bar.rolling(cfg.bo_recent_window).sum()
```

强度组成：突破距离、body、收盘位置、连续趋势 bar、突破层级数量、micro-gap、follow-through、低 overlap。volume 仅作辅助：

```python
bucket_history = same_session_bucket_volume.shift(1).tail(
    cfg.volume_bucket_lookback
)
volume_ratio = volume / median(bucket_history)
```

不得把夜盘开盘量与午后同一窗口直接比较。没有可靠 volume 时价格规则仍可计算，但流动性门控必须单独通过。

### 6.6 回调与通道

方向 `d in {+1, -1}`，以下以多头为例，空头镜像：

```python
impulse_range = impulse_high - impulse_origin_low
pullback_depth = (impulse_high - pullback_low_so_far) / max(impulse_range, eps)
pullback_bars = completed bars since impulse extreme
breakout_hold = pullback_low_so_far >= breakout_level - cfg.breakout_tolerance_atr * atr
```

通道特征：

```text
channel_slope_atr, pullback_count,
median_pullback_bars, max_pullback_bars,
median_pullback_depth, ema_cross_count,
opposite_trend_bar_ratio, overlap_ratio, hh_score, hl_score
```

其中 `ema_cross_count` 固定为 `cross(close, ema_fast)` 在最近 `cfg.tight_ema_cross_window` 根完成 bar 的次数；其余 rolling 结构量默认使用 `cfg.structure_window`，不得另藏未配置窗口。

回归通道只能使用截至当前的 rolling window；任何线性回归参数都随时间重算，不延长到未来。

### 6.7 分位数归一化

跨品种阈值优先使用仅含过去数据的分位数：

```python
pctl_t = rank(value_t among values[t-lookback:t])
```

当前值不能参与历史分布拟合。warmup 不足时输出 `UNAVAILABLE`，不能用全样本分位数。

### 7.2 统一评分

每项先压缩至 `[0, 1]`。所有 rolling 量均截至当前完成 bar，所有 percentile 的历史窗都排除当前值：

```python
def q_pos(value, history):
    return percentile_rank(value, history) / 100.0

def q_neg(value, history):
    return percentile_rank(-value, [-x for x in history]) / 100.0

def required_mean(*values):
    if not all(isfinite(x) for x in values):
        return float("nan")
    return sum(values) / len(values)
```

方向统一用 `d in {+1, -1}`。实现只写一个 `directional_view(features, d)`；多头的 HH/HL 在空头镜像为 LL/LH，收盘强度在空头镜像为 `(high-close)/range`：

```python
@dataclass(frozen=True)
class DirectionalView:
    d: int
    pressure: float
    breakout_distance: float
    structure_score: float
    close_pos: float
    close_strength: float
    trend_bar_ratio: float
    trend_bar_count_recent: int
    channel_age: int
    channel_slope_strength: float
    median_pullback_bars: float
    median_pullback_depth: float
    max_pullback_depth: float
    ema_cross_count: int
    opposite_trend_bar_ratio: float
    parts: Mapping[str, float]

def directional_view(f, d, history):
    structure_a = f.hh_score if d == 1 else f.ll_score
    structure_b = f.hl_score if d == 1 else f.lh_score
    channel = f.channel[d]
    close_strength = (
        f.close_pos_long_mean if d == 1 else f.close_pos_short_mean
    )
    close_pos = f.close_pos_long if d == 1 else f.close_pos_short
    trend_bar_ratio = (
        f.bull_trend_bar_ratio if d == 1 else f.bear_trend_bar_ratio
    )
    trend_bar_count_recent = (
        f.bull_trend_bar_count_recent
        if d == 1
        else f.bear_trend_bar_count_recent
    )
    breakout_distance = (
        f.breakout_distance_long if d == 1 else f.breakout_distance_short
    )

    parts = {
        "ema_slope": q_pos(d * f.ema_slope, history.signed_ema_slope[d]),
        "ema_separation": q_pos(
            d * f.ema_separation, history.signed_ema_separation[d]
        ),
        "ema_distance": q_pos(d * f.ema_distance, history.signed_ema_distance[d]),
        "structure_a": structure_a,
        "structure_b": structure_b,
        "trend_bars": trend_bar_ratio,
        "close_strength": close_strength,
        "efficiency": q_pos(f.trend_efficiency, history.trend_efficiency),
        "low_overlap": 1.0 - f.overlap_ratio,
    }
    pressure = required_mean(*parts.values())
    return DirectionalView(
        d=d,
        pressure=pressure,
        breakout_distance=breakout_distance,
        structure_score=required_mean(structure_a, structure_b),
        close_pos=close_pos,
        close_strength=close_strength,
        trend_bar_ratio=trend_bar_ratio,
        trend_bar_count_recent=trend_bar_count_recent,
        channel_age=channel.age,
        channel_slope_strength=d * channel.slope_atr,
        median_pullback_bars=channel.median_pullback_bars,
        median_pullback_depth=channel.median_pullback_depth,
        max_pullback_depth=channel.max_pullback_depth,
        ema_cross_count=channel.ema_cross_count,
        opposite_trend_bar_ratio=channel.opposite_trend_bar_ratio,
        parts=parts,
    )

bull = directional_view(features, +1, causal_history)
bear = directional_view(features, -1, causal_history)
bull_pressure = bull.pressure
bear_pressure = bear.pressure
directional_strength = abs(bull_pressure - bear_pressure)
margin_passes = directional_strength >= cfg.direction_min_pressure_margin
direction = sign(bull_pressure - bear_pressure) if margin_passes else 0
```

v0 对 pressure 九项证据等权；已有 `[0,1]` 的结构、bar ratio、close position、overlap 不再分位化。trend bar 定义为方向一致且 `body_ratio >= cfg.trend_bar_min_body_ratio`，其比例和 close strength 均在 `cfg.structure_window` 内计算。

七个可交易状态使用唯一评分函数。`gate_*` 是 7.3~7.7 的硬性定义；评分只在 gate 成立时有效：

```python
def score_state(f, view, state, history, directional_strength, direction):
    if state == "STRONG_BREAKOUT":
        raw = required_mean(
            q_pos(view.breakout_distance, history.breakout_distance[view.d]),
            q_pos(f.body_ratio, history.body_ratio),
            view.close_strength,
            view.trend_bar_ratio,
            1.0 - f.overlap_ratio_recent,
            view.pressure,
        )
        eligible = gate_breakout(f, view)
    elif state == "TIGHT_CHANNEL":
        raw = required_mean(
            view.pressure,
            q_pos(view.channel_slope_strength, history.signed_channel_slope[view.d]),
            q_neg(view.median_pullback_bars, history.median_pullback_bars),
            q_neg(view.max_pullback_depth, history.max_pullback_depth),
            q_neg(view.ema_cross_count, history.ema_cross_count),
            q_neg(view.opposite_trend_bar_ratio, history.opposite_trend_bar_ratio),
            view.structure_score,
        )
        eligible = gate_tight_channel(f, view, direction)
    elif state == "BROAD_CHANNEL":
        broadness = required_mean(
            q_pos(view.median_pullback_bars, history.median_pullback_bars),
            q_pos(view.median_pullback_depth, history.median_pullback_depth),
            q_pos(view.ema_cross_count, history.ema_cross_count),
        )
        raw = required_mean(
            view.pressure,
            q_pos(view.channel_slope_strength, history.signed_channel_slope[view.d]),
            view.structure_score,
            broadness,
            q_pos(f.trend_efficiency, history.trend_efficiency),
        )
        eligible = gate_broad_channel(f, view, direction)
    elif state == "TRADING_RANGE":
        raw = required_mean(
            q_neg(abs(f.ema_slope), history.abs_ema_slope),
            f.overlap_ratio,
            f.direction_change_ratio,
            q_neg(f.trend_efficiency, history.trend_efficiency),
            q_neg(directional_strength, history.directional_strength),
        )
        eligible = gate_trading_range(f, directional_strength)
    else:
        raise ValueError(state)
    if not isfinite(raw):
        return None
    return raw if eligible else 0.0

state_scores = {
    STRONG_BULL_BREAKOUT: score_state(features, bull, "STRONG_BREAKOUT", causal_history, directional_strength, direction),
    BULL_TIGHT_CHANNEL: score_state(features, bull, "TIGHT_CHANNEL", causal_history, directional_strength, direction),
    BULL_BROAD_CHANNEL: score_state(features, bull, "BROAD_CHANNEL", causal_history, directional_strength, direction),
    TRADING_RANGE: score_state(features, None, "TRADING_RANGE", causal_history, directional_strength, direction),
    BEAR_BROAD_CHANNEL: score_state(features, bear, "BROAD_CHANNEL", causal_history, directional_strength, direction),
    BEAR_TIGHT_CHANNEL: score_state(features, bear, "TIGHT_CHANNEL", causal_history, directional_strength, direction),
    STRONG_BEAR_BREAKOUT: score_state(features, bear, "STRONG_BREAKOUT", causal_history, directional_strength, direction),
}

classification_available = all(score is not None for score in state_scores.values())
if not classification_available:
    return unavailable_cycle_snapshot(reason="NON_FINITE_REQUIRED_STATE_INPUT")
```

方向状态必须通过 `view.d` 镜像同一函数，禁止复制一套 bear 阈值。七状态完整比较所需的任一输入缺失时，在 winner 计算前直接输出 `UNAVAILABLE`，不把缺失折成零分，也不按剩余项重加权。`TRANSITION` 和 `UNAVAILABLE` 先按 7.9 判定；其余状态按有限的 `state_scores` 选最大值，同分严格使用 7.8 的固定 precedence，不使用未来收益或 symbol 名称打破平局。状态置信度为：

```python
confidence = data_completeness * min(
    1.0,
    max(0.0, top_state_score - second_state_score) / cfg.confidence_full_margin,
)
```

通过 `classification_available` 后 `data_completeness=1.0`；否则已直接进入 `UNAVAILABLE`。v0 不用“缺一项就按比例打折”掩盖缺失。

输出接口：

```python
@dataclass(frozen=True)
class CycleSnapshot:
    cycle: MarketCycle
    direction: int
    strength: float
    confidence: float
    bull_pressure: float
    bear_pressure: float
    range_subtype: str | None
    feature_asof: datetime
    feature_sequence: int
    evidence: Mapping[str, float]
```

`strength` 表示方向性强弱，`confidence` 表示第一名状态分数与第二名的可分离程度及数据完整性，不是未来盈利概率。

### 7.3 强上涨突破

v0 候选条件，所有阈值均配置化，多空调用同一 gate：

```python
def gate_breakout(f, view):
    d = view.d
    broke_boundary = (
        f.close > f.prior_high if d == 1 else f.close < f.prior_low
    )
    return (
        broke_boundary
        and view.breakout_distance >= cfg.bo_min_distance_atr
        and d * f.body > 0
        and f.body_ratio >= cfg.bo_min_body_ratio
        and view.close_pos >= cfg.bo_min_close_pos
        and view.trend_bar_count_recent >= cfg.bo_min_trend_bars
        and f.overlap_ratio_recent <= cfg.bo_max_overlap
        and view.pressure >= cfg.bo_min_pressure
    )
```

以下证据增加分数但不全部设为硬条件：连续强阳、多个阻力层被突破、micro-gap、同 session 成交量异常、最近 1~2 根 follow-through、突破前有足够压缩或趋势回调背景。

允许追涨仅当；其中 geometry 统一调用 9.1，不在 breakout 模块另算 R：

突破失败也使用方向参数：

```python
def strong_directional_bar(f, d):
    close_pos = f.close_pos_long if d == 1 else f.close_pos_short
    return (
        d * f.body > 0
        and f.body_ratio >= cfg.strong_opposite_body_ratio
        and close_pos >= cfg.strong_opposite_close_pos

def gate_breakout_failure(f, previous_f, d):
    lost_level = (
        f.close < f.breakout_level - cfg.breakout_tolerance_atr * f.atr
        if d == 1
        else f.close > f.breakout_level + cfg.breakout_tolerance_atr * f.atr
    )
    opposite_follow_through = (
        strong_directional_bar(previous_f, -d)
        and strong_directional_bar(f, -d)
```

### 7.4 Bull Tight Channel

```python
def gate_tight_channel(f, view, direction):

    continuation_structure = f.hl_score if d == 1 else f.lh_score
    return (
        direction == d
        and view.channel_age >= cfg.channel_min_bars
        and view.channel_slope_strength >= cfg.tight_min_slope
        and view.median_pullback_bars <= cfg.tight_max_median_pb_bars
        and view.max_pullback_depth <= cfg.tight_max_pb_depth

        and view.opposite_trend_bar_ratio <= cfg.tight_max_opposite_ratio

```

交易原则：只顺势；在 1~2 根浅回调、H1/H2 或 EMA 附近恢复时做多；逆势 signal 只用于减仓或收紧风险，不直接做空。若回调次数、深度、EMA 穿越和双向 trend bar 增加，则向宽通道迁移。

### 7.5 Bull Broad Channel

```python
def gate_broad_channel(f, view, direction):
```

### 7.6 Trading Range

先冻结边界：

```python
range_high = high.shift(1).rolling(cfg.range_window).max()
range_low = low.shift(1).rolling(cfg.range_window).min()
range_mid = (range_high + range_low) / 2
range_pct = (close - range_low) / max(range_high - range_low, eps)
```

候选条件：

```python
def gate_trading_range(f, directional_strength):
    structural_gate = (
        abs(f.ema_slope) <= cfg.range_max_abs_slope
        and f.overlap_ratio >= cfg.range_min_overlap
        and f.direction_change_ratio >= cfg.range_min_direction_changes
        and f.trend_efficiency <= cfg.range_max_efficiency
        and directional_strength <= cfg.range_max_directional_strength
    )
    return structural_gate and (not cfg.use_range_aux_gate or f.range_aux_gate)

range_aux_gate = (
    causal_percentile_rank(adx, cfg.percentile_lookback)
        <= cfg.range_max_adx_percentile
    and causal_percentile_rank(atr_compression, cfg.percentile_lookback)
        <= cfg.range_max_atr_compression_percentile
)

features.range_aux_gate = range_aux_gate
```

`use_range_aux_gate=False` 是 v0 基线；只在 A9 消融中开启。这样 ADX/ATR 压缩有明确可编码口径，但不会在证明增益前被偷偷加入基线。

行为规则：

```text
range_pct <= cfg.range_lower_zone        -> 只寻找多头反转/空头止盈
cfg.range_lower_zone < range_pct < cfg.range_upper_zone -> NO_TRADE
range_pct >= cfg.range_upper_zone        -> 只寻找空头反转/多头止盈
```

range subtype 按可执行空间定义：

```python
range_width = range_high - range_low

    range_subtype = "UNTRADEABLE_TIGHT"
elif range_width_atr <= cfg.range_tight_max_width_atr:
    range_subtype = "TIGHT_BREAKOUT_MODE"
else:
    range_subtype = "BROAD"
```

紧区间 breakout mode 只挂双向条件 stop，首个成交后撤销另一侧。宽区间才允许边缘 fade。边界若被强突破并有 follow-through，转入突破状态；单根刺破后收回不迁移。

### 7.7 空头状态

`STRONG_BEAR_BREAKOUT`、`BEAR_TIGHT_CHANNEL`、`BEAR_BROAD_CHANNEL` 对所有价格关系、bar 方向、结构和订单进行严格镜像。实现必须使用方向参数 `d` 共享算法，避免多空两套代码逐渐不一致。

### 7.8 分类优先级与滞回

每根中周期 bar 计算所有状态分数：

```text
UNAVAILABLE/数据阻断
    > 极端行情 TRANSITION
    > STRONG_BREAKOUT
    > TIGHT_CHANNEL
    > BROAD_CHANNEL
    > TRADING_RANGE
```

实现中的唯一 winner/tie-break 入口：

```python
precedence = [
    STRONG_BULL_BREAKOUT,
    STRONG_BEAR_BREAKOUT,
    BULL_TIGHT_CHANNEL,
    BEAR_TIGHT_CHANNEL,
    BULL_BROAD_CHANNEL,
    BEAR_BROAD_CHANNEL,
    TRADING_RANGE,
]
precedence_rank = {state: -i for i, state in enumerate(precedence)}
assert classification_available
challenger = max(
    state_scores,
    key=lambda state: (state_scores[state], precedence_rank[state]),
)
challenger_score = state_scores[challenger]
current_score = state_scores.get(current_cycle, 0.0)
```

状态切换必须同时满足：

```python
switch = (
    challenger_score >= cfg.enter_score
    and challenger_score - current_score >= cfg.switch_margin
    and consecutive_confirmations >= cfg.confirm_bars
    and bars_in_current_state >= cfg.min_state_bars
)
```

初次分类时 `challenger_score < cfg.enter_score` 则进入 `TRANSITION`；已有状态未通过 switch 时保持原状态。若当前状态 hard gate 已失效，仍至少经过普通 `confirm_bars` 或 7.9 的极端反向路径，不能用 `current_score=0` 在单 bar 内静默翻向。`top_state_score/second_state_score` 来自同一个 `state_scores` 排序结果。

v0 不为状态机另设隐藏的“单 bar 快速切换”参数；强突破即时参与由 7.3 的 `BREAKOUT` candidate 路径处理，Market Cycle 仍遵守上述滞回。`min_state_bars` 防止状态逐 bar 抖动；极端反向突破只可跳过普通滞回进入 `TRANSITION`，不能在同一 bar 从 Always-In Long 直接翻成满仓 Short。

### 7.9 Transition 与 Unavailable

`UNAVAILABLE` 只表示输入不足或不可审计：warmup 不足、关键特征非有限值、元数据缺失、周期对齐失败或合约切换 warmup 未完成。

`TRANSITION` 是可计算但暂时不交易的周期过渡：

```python
climax = (
    bar_range_percentile >= cfg.climax_range_percentile
    and abs(ema_distance) >= cfg.climax_ema_distance_atr
    and cumulative_move_atr >= cfg.climax_cumulative_move_atr
)
opposite_shock = (
    current_direction != 0
    and opposite_breakout_score >= cfg.transition_opposite_score
    and opposite_pressure_delta >= cfg.transition_pressure_delta
)
ambiguous_winner = top_state_score - second_state_score < cfg.transition_score_margin

transition = (
    (climax and momentum_decay >= cfg.transition_min_momentum_decay)
    or opposite_shock
    or (current_cycle_is_directional and ambiguous_winner)
)
```

进入 `TRANSITION` 后取消新订单；至少等待 `confirm_bars` 个完成 bar，由普通状态切换规则决定进入 range、反向趋势或恢复原趋势。climax 不是自动反转信号。

### 8.2 Always-In 状态

```python
class AlwaysIn(str, Enum):
    LONG = "ALWAYS_IN_LONG"
    NEUTRAL = "NEUTRAL"
    SHORT = "ALWAYS_IN_SHORT"
```

状态机使用中周期已完成 bar：

```text
NEUTRAL -> LONG
  gate_breakout(+1) 且 breakout score >= enter_score；
  或 BULL_TIGHT_CHANNEL 已连续 confirm_bars；
  且大周期不为 bear，bull_pressure-bear_pressure >= direction_min_pressure_margin。

LONG -> NEUTRAL
  收盘跌破最近已确认 major HL；或 TRADING_RANGE 连续 confirm_bars；
  或 bear_pressure-bull_pressure >= direction_min_pressure_margin 连续 confirm_bars；
  或 gate_failed_breakout(-1) 成立。

LONG -> SHORT
  默认必须先经过 NEUTRAL；
  仅“gate_breakout(-1) + 下一完成 bar bear follow-through + 大周期不反对”可快速翻转，
  但旧多仓先平，空仓最早在下一独立订单事件建立。
```

SHORT 完全镜像。状态保存：

```text
entered_at, last_changed_at, bars_in_state,
trigger_evidence, invalidation_price, prior_state
```

禁止因单根普通反向 bar 翻转。Always-In 是方向许可和持仓管理上下文，不等于每根 bar 都必须持仓。

所有已启用 setup 共用唯一的交易几何，禁止各模块各自解释“空间足够”或“成本可接受”：

```python
@dataclass(frozen=True)
class PlanGeometry:
    entry: float
    stop: float
    stop_distance: float
    target: float
    nearest_obstacle: float
    gross_space_R: float
    cost_R: float
    net_space_R: float
    net_reward_R: float
    near_price_limit: bool

def build_plan_geometry(f, d, entry, structural_stop_candidate, planned_target, meta):
    structural_distance = d * (entry - structural_stop_candidate)
    stop_distance = max(
        structural_distance,
        cfg.stop_atr_floor * f.atr,
        cfg.stop_min_ticks * meta.price_tick,
    )
    stop = entry - d * stop_distance

    obstacle_candidates = [
        meta.limit_up if d == 1 else meta.limit_down,
        *f.confirmed_directional_swing_obstacles[d],
        f.range_high if d == 1 else f.range_low,
        *f.completed_higher_tf_obstacles[d],
    ]
    ahead = [
        p
        for p in obstacle_candidates
        if p is not None and isfinite(p) and d * (p - entry) > 0
    ]
    if not ahead:
        raise BlockedPlanError("NO_CAUSAL_DIRECTIONAL_OBSTACLE")
    nearest_obstacle = min(ahead, key=lambda p: d * (p - entry))

    target_candidates = [
        p
        for p in (planned_target, nearest_obstacle)
        if p is not None and isfinite(p) and d * (p - entry) > 0
    ]
    if not target_candidates:
        raise BlockedPlanError("NO_CAUSAL_POSITIVE_TARGET")
    effective_target = min(target_candidates, key=lambda p: d * (p - entry))
    entry_exit_fee_price = meta.stressed_round_trip_fee_cash / meta.contract_size
    slippage_price = meta.stressed_round_trip_slippage_ticks * meta.price_tick
    all_in_cost_price = entry_exit_fee_price + slippage_price
    gross_space_price = d * (nearest_obstacle - entry)
    gross_reward_price = d * (effective_target - entry)
    directional_limit = meta.limit_up if d == 1 else meta.limit_down
    exit_side = "SELL" if d == 1 else "BUY"
    rounded_stop = round_for_order(
        stop, exit_side, "stop", "protective_stop", meta.price_tick
    )
    rounded_target = round_for_order(
        effective_target, exit_side, "limit", "profit_target", meta.price_tick
    )
    actual_stop_distance = abs(entry - rounded_stop)

    return PlanGeometry(
        entry=entry,
        stop=rounded_stop,
        stop_distance=actual_stop_distance,
        target=rounded_target,
        nearest_obstacle=nearest_obstacle,
        gross_space_R=gross_space_price / actual_stop_distance,
        cost_R=all_in_cost_price / actual_stop_distance,
        net_space_R=(gross_space_price - all_in_cost_price) / actual_stop_distance,
        net_reward_R=(gross_reward_price - all_in_cost_price) / actual_stop_distance,
        near_price_limit=(
            d * (directional_limit - entry)
            <= cfg.limit_entry_buffer_atr * f.atr
        ),
    )
```

障碍只使用 `known_at <= decision_event` 的最近 `structure_pivot_count` 个确认 swing、冻结 range 边界、已完成高周期支撑阻力和当日真实 limit；先过滤方向前方，再选价格距离最近者。若同价，记录优先级 `PRICE_LIMIT > CONFIRMED_SWING > RANGE_BOUNDARY > HIGHER_TF` 作为 reason code，不改变价格。entry/stop/target tick 取整后必须重建 geometry；gap 后实际 entry 若不再满足以下条件则取消，不沿用 signal bar 的乐观 R：

```python
def geometry_tradeable(geometry):
    return (
        geometry.net_space_R >= cfg.min_space_R
        and geometry.cost_R <= cfg.max_cost_R
        and geometry.net_reward_R >= cfg.min_net_reward_R
        and not geometry.near_price_limit
    )
```

所有候选必须包含“为什么允许”和“什么情况下失效”。不能只输出一个布尔 signal。

### 9.2 Setup 与 Market Context

| Setup | 允许状态 | 方向 | Trigger | Entry | Stop | 初始目标/管理 |
|---|---|---|---|---|---|---|
| BREAKOUT | `gate_breakout` 成立（可早于状态滞回完成）、tight breakout mode | 突破方向 | 收盘突破冻结边界且质量通过 | market/stop，下一可交易时刻 | 突破段起点外 | swing，measured move 候选或结构 trail |
| FIRST_PULLBACK | strong breakout、tight channel | 趋势方向 | 首次 1~3 bar 浅回调后恢复 | signal bar 外 1 tick stop | 回调极值外 | swing，至少测试前极值 |
| H1 | strong breakout/tight channel | 趋势方向 | 回调中第一次恢复尝试 | signal bar 外 stop | 回调极值外 | 只在强 context；可 swing |
| H2 | tight/broad channel | 趋势方向 | H1 失败后第二次恢复尝试 | signal bar 外 stop | 第二段回调极值外 | broad channel 首选 |
| WEDGE_PULLBACK | broad channel、range edge | 大 context 方向或边缘反转 | 三次已确认 push + reversal bar | stop entry | wedge 极值外 | 前极值、range mid 或 runner |
| EMA_PULLBACK | tight/broad channel | 趋势方向 | 回调触及 EMA 区后恢复 | stop entry | 结构低/高点外 | 前极值；不得仅因触 EMA 入场 |
| FAILED_BREAKOUT | broad range | 向区间内部 | 刺破冻结边界后收回且有确认 | stop/limit，按执行证据 | 假突破极值外 | range mid，scalp |
| RANGE_REVERSAL | broad range 边缘 | 向中线 | 边缘 reversal + 空间/成本通过 | limit 或 stop | range 外结构点 | range mid/对侧前减仓 |
| TREND_RESUMPTION | broad channel 回调结束 | 大方向 | 两段回调后突破小通道 | stop entry | 回调极值外 | 前高/低后 trail |

枚举表示长期研究词汇，不表示都能在 v0 下单。首版只启用：

```python
V0_ENABLED_SETUPS = {BREAKOUT, H1, H2, FAILED_BREAKOUT}
```

`FIRST_PULLBACK/WEDGE_PULLBACK/EMA_PULLBACK/RANGE_REVERSAL/TREND_RESUMPTION` 在补齐独立 Rule Card、prefix invariance 和成交测试前统一返回 `RESEARCH_ONLY_NOT_ENABLED`。其中 first pullback 暂由强突破 context 下的 H1 覆盖，range reversal 暂由下面定义的 failed breakout 覆盖，避免同一风险事件重复命名。

### 9.3 Failed Breakout Rule Card

以宽区间下沿做多为 `d=+1`、上沿做空为 `d=-1`，多空共用：

```python
def gate_failed_breakout(f, d):
    excursion = (
        f.range_low - f.low if d == 1 else f.high - f.range_high
    )
    reclaim = (
        f.close - f.range_low if d == 1 else f.range_high - f.close
    )
    close_pos = f.close_pos_long if d == 1 else f.close_pos_short
    return (
        f.cycle == TRADING_RANGE
        and f.range_subtype == "BROAD"
        and excursion > 0
        and excursion <= cfg.failed_breakout_max_excursion_atr * f.atr
        and reclaim >= cfg.failed_breakout_min_reclaim_atr * f.atr
        and d * f.body > 0
        and f.body_ratio >= cfg.failed_breakout_min_body_ratio
        and close_pos >= cfg.failed_breakout_min_close_pos
    )

trigger = f.high + meta.price_tick if d == 1 else f.low - meta.price_tick
structural_stop_candidate = (
    f.low - cfg.stop_min_ticks * meta.price_tick
    if d == 1
    else f.high + cfg.stop_min_ticks * meta.price_tick
)
failed_breakout_geometry = build_plan_geometry(
    f,
    d,
    trigger,
    structural_stop_candidate,
    f.range_mid,
    meta,
)
failed_breakout_tradeable = (
    gate_failed_breakout(f, d)
    and geometry_tradeable(failed_breakout_geometry)
)
```

Rule Card：边界来自 `shift(1)` 冻结窗口；signal bar 收盘时才 `known_at`。多头 trigger 为 signal high 上 1 tick，空头镜像为 signal low 下 1 tick，均从下一执行事件激活。结构 stop 放在本次刺破极值外 `stop_min_ticks`，初始 target 为冻结的 `range_mid`；取整后仍需通过净 R、成本和空间门。订单按 `setup_expiry_bars` 过期；边界被更深突破、状态离开 broad range、进入中间区域、跨 session/roll 或元数据阻断时撤销。candidate、order、fill 分开记录，刺破 bar 内不得按收盘前已知处理。

### 9.4 H1/H2 的因果状态机

不能先看到完整回调再给过去的 bar 编号。以多头为例：

```python
class SecondEntryState(str, Enum):
    IDLE = "IDLE"
    PULLBACK = "PULLBACK"
    ATTEMPT_1_ARMED = "ATTEMPT_1_ARMED"
    ATTEMPT_1_CONFIRMED = "ATTEMPT_1_CONFIRMED"
    RESET_AFTER_1 = "RESET_AFTER_1"
    ATTEMPT_2_ARMED = "ATTEMPT_2_ARMED"
    ATTEMPT_2_CONFIRMED = "ATTEMPT_2_CONFIRMED"
    COMPLETE = "COMPLETE"
    INVALID = "INVALID"
```

必须维护两个独立对象：`SecondEntryPatternTracker` 只读取价格并计数恢复尝试；`OrderState/TradeState` 只记录计划、订单、成交和持仓。setup 编号不得依赖策略是否下单、是否成交、MFE、止盈或止损。

多头实时流程：

1. bull flag/context 中出现 `low_t < low_t_minus_1` 的 bar pullback，进入 `PULLBACK` 并更新 `pullback_low_so_far`。
2. 每根完成的 pullback bar `s` 都形成“下一次恢复尝试”的价格观察点 `raw_trigger = high_s + tick`。当后续真实价格首次交易到该 trigger，`attempt_count += 1`；第一次是 H1，之后必须先 reset 才可能出现 H2。触发时刻是实际 crossing event，不回填到 `s`。
3. 若尚未 crossing 又出现更低 high 的新 pullback bar，只更新同一 ordinal 的观察 trigger，仍是 H1，不因旧条件单过期、撤单或未下单而变成 H2。
4. H1 crossing 后，只有至少一根已完成 bar 满足 `high_t < high_t_minus_1`，才进入 `RESET_AFTER_1`。随后形成新的观察 trigger；下一次 `price > prior_completed_bar_high` 的 crossing 才是 H2。
5. pattern crossing 无论策略订单是否存在都必须计数。订单引擎可因信号质量、元数据、风险或流动性拒绝 H1，但若市场随后完成 H1，下一次价格形态仍按 H2 处理。
6. 只有准备交易时才按下面的共享 geometry 计算 `signal_eligible`。合格订单从下一执行事件激活；order fill 与 pattern crossing 分别记录。
7. H2 crossing 后 `COMPLETE`。跌破大 context 失效位、`pullback_bars > cfg.max_pullback_bars`、状态转 range/bear 或 session/roll 阻断时 `INVALID`。

H1/H2 多空共用的可交易计划：

```python
trigger = (
    signal_bar.high + meta.price_tick
    if d == 1
    else signal_bar.low - meta.price_tick
)
structural_stop_candidate = (
    pullback_low_so_far - cfg.stop_min_ticks * meta.price_tick
    if d == 1
    else pullback_high_so_far + cfg.stop_min_ticks * meta.price_tick
)
planned_target = pullback_origin_extreme
geometry = build_plan_geometry(
    features_asof,
    d,
    trigger,
    structural_stop_candidate,
    planned_target,
    metadata_asof,
)

signal_eligible = (
    current_cycle not in {TRANSITION, UNAVAILABLE, TRADING_RANGE}
    and current_trade_mode != NO_TRADE
    and signal_bar.range <= cfg.max_signal_bar_atr * features_asof.atr
    and not strong_directional_bar(signal_bar.features, -d)
    and geometry_tradeable(geometry)
)
```

`pullback_low/high_so_far` 和 `pullback_origin_extreme` 只由 tracker 截至 signal bar 收盘的状态给出；gap 触发后按真实 fill 重建 geometry，不通过则不假设成交。H1 只在 strong breakout/tight channel 许可，H2 只在 tight/broad channel 许可，具体使用 9.2 矩阵。

事件流至少保存：`attempt_ordinal`、`signal_bar_end`、`trigger_price`、`crossed_at/cross_sequence`、`candidate_id | None`、`order_id | None`。空头严格镜像为 lower-low bar pullback、价格跌破前一完成 bar low 的 L1/L2 尝试。任何 MFE 只属于成交后的管理和标签，不得参与 H1/H2 编号。

### 9.5 Wedge 的因果定义

三次 push 只使用 `known_at <= current_bar_end` 的 pivot。要求：

```python
push_2_atr = (preceding_confirmed_high_2 - confirmed_low_2) / atr_at_low_2
push_3_atr = (preceding_confirmed_high_3 - confirmed_low_3) / atr_at_low_3
bull_reversal_bar_now = (
    close > open
    and body_ratio >= cfg.wedge_min_reversal_body_ratio
    and close_pos_long >= cfg.wedge_min_reversal_close_pos
)
wedge_long = (
    len(confirmed_lows) >= 3
    and push_spacing_each >= cfg.wedge_min_spacing
    and total_span <= cfg.wedge_max_span
    and push_3_atr <= push_2_atr * cfg.wedge_max_push_acceleration
    and bull_reversal_bar_now
    and context_allows_long
)
```

第三个 pivot 若需要右侧确认，则只能在确认时刻以后交易；更早入场必须使用“不依赖 pivot 确认”的实时三推 tracker，并作为不同 setup 单独回测。

### 9.6 候选去重与优先级

同一 symbol、方向、signal bar 可能同时满足多个 setup。只生成一个订单计划：

```text
BREAKOUT > FIRST_PULLBACK > H2 > H1 > TREND_RESUMPTION
FAILED_BREAKOUT > RANGE_REVERSAL
```

优先级不是优势排名，只用于避免重复风险。`candidate_id` 对输入快照和规则版本做稳定 hash。相同风险事件不得以多个 setup 名称重复下单。

## 10. Scalp、Swing 与 No Trade

```python
class TradeMode(str, Enum):
    SCALP = "SCALP"
    SWING = "SWING"
    NO_TRADE = "NO_TRADE"
```

| Market Cycle | 默认模式 | 说明 |
|---|---|---|
| Strong Breakout | SWING | 强趋势的主要价值来自第二段和 runner，不应只拿微小利润 |
| Tight Channel | SWING | 顺势回调入场，容忍 1~2 bar 小回调 |
| Broad Channel | SWING，风险折扣 | 低位/高位结构入场，不追通道末端；止损更宽、仓位更小 |
| Broad Trading Range | SCALP | 只在边缘向中线，目标必须覆盖真实成本 |
| Tight Breakout Mode | 等待后 SWING | 双向 stop，确认方向后跟随 |
| Untradeable Tight/Middle Third | NO_TRADE | 空间不足或没有方向优势 |
| Transition/Unavailable | NO_TRADE | 等待状态稳定或数据恢复 |

模式在入场计划生成时冻结。禁止：

- 原计划 scalp，亏损后扩大止损改成 swing。
- 原计划 swing，出现普通 1~2 bar 回调就改成 scalp 过早退出。
- 盈利后临时把固定目标改 runner，除非 runner 比例在入场前已写入计划。

净 Trader's Equation 门槛：

```python
net_reward_R = gross_target_R - round_trip_cost_R - slippage_stress_R
tradeable = net_reward_R >= cfg.min_net_reward_R
```

只有锁定 OOS 中有稳定分组样本后，才可增加：

```python
ev_R = p_win_lower_bound * avg_win_R - (1 - p_win_lower_bound) * avg_loss_R
```

`p_win` 必须来自当前 walk-forward 训练窗的同类历史，不能用当前测试窗，也不能直接采用课程经验概率。

## 11. Entry 与订单生命周期

### 11.1 订单类型

| 场景 | 首选订单 | 原因 |
|---|---|---|
| 强突破已确认 | marketable limit；交易所和历史阶段支持时可 market | 尽快参与，但限制极端滑点 |
| H1/H2/回调恢复 | stop 或 stop-limit | 只有价格向预期方向运动才激活 |
| 宽区间边缘 | limit 或 reversal stop | limit 需要更保守的成交模型 |
| 紧区间 breakout mode | OCO 双向 stop | 两腿均通过风险门才建组；一侧首次真实成交（含 partial）立即撤另一侧 |

订单能力由当日交易所和网关元数据决定。历史上不支持的订单类型不能在回测中假装可用。
OCO 计划禁止逐腿调用普通撮合入口；若同一根 OHLC 同时触及上下 stop 且没有更细粒度
数据，统一返回 `OCO_AMBIGUOUS_NO_FILL`，不能按遍历顺序选择方向。

### 11.2 价格取整

```python
import math

def round_for_order(
    raw: float,
    order_side: str,
    order_kind: str,
    order_role: str,
    tick: float,
) -> float:
    if order_side not in {"BUY", "SELL"}:
        raise ValueError("invalid order side")
    if order_kind not in {"stop", "limit"}:
        raise ValueError("invalid order kind")
    if order_role not in {"entry", "protective_stop", "profit_target"} or tick <= 0:
        raise ValueError("invalid order rounding input")
    if order_role == "protective_stop" and order_kind != "stop":
        raise ValueError("protective stop requires stop order semantics")
    units = raw / tick
    round_up = (order_kind == "stop" and order_side == "BUY") or (
        order_kind == "limit" and order_side == "SELL"
    )
    rounded_units = math.ceil(units - 1e-12) if round_up else math.floor(units + 1e-12)
    return rounded_units * tick
```

因此 buy stop/short protective stop 向上，sell stop/long protective stop 向下；buy limit 向下，sell limit 向上。所有 entry、protective stop、target 必须落在 tick 网格。实现至少测试 long/short entry stop、long/short protective stop、long/short target limit 六种镜像组合；取整后重新计算风险收益，若低于门槛则拒绝。

### 11.3 激活与过期

```text
SIGNAL -> PLANNED -> ACTIVE -> PARTIAL/FILLED -> CANCELLED/EXPIRED
```

- `known_at` 前不得创建订单。
- 默认 `order_active_at` 是下一基础执行 bar 开始。
- setup 订单有效期按小周期 bar 数配置；context 变化、跨 session、临近涨跌停、换月或数据断流立即撤单。
- 部分成交按真实已成交数量建仓，剩余订单是否保留必须预定义。

### 11.4 回测成交保守原则

OHLC 同一 bar 同时碰到 stop 和 target 时，必须使用更细粒度真实数据决定；仍无法决定则采用对策略不利的顺序或标记 `AMBIGUOUS_NO_FILL`，不能选择有利路径。limit 触价不等于成交，至少加入排队/穿价规则；涨跌停板上无对手盘时不得假设平仓成功。

## 12. Stop Loss

### 12.1 先算距离，再算价格

以多头为例：

```python
structural_distance = entry - structural_stop_candidate
volatility_floor = cfg.stop_atr_floor * atr
minimum_tick_distance = cfg.stop_min_ticks * tick
stop_distance = max(structural_distance, volatility_floor, minimum_tick_distance)
stop_price = round_down(entry - stop_distance, tick)
```

空头镜像：`stop_price = round_up(entry + stop_distance, tick)`。不能对多空直接使用同一个 `max(stop_price)` 公式。

### 12.2 结构 stop 选择

| Setup/状态 | 结构止损 |
|---|---|
| Strong Breakout | 突破段起点或最新 micro channel 结构外 |
| First Pullback/H1/H2 | 当前 pullback 极值外加 buffer |
| Tight Channel | 最近主要 HL/LH 外，不因普通单 bar 反转退出 |
| Broad Channel | 已确认 major HL/LH 或完整两段回调极值外 |
| Range Fade | 假突破极值或 range 边界外 |

若结构 stop 导致 1 手风险超过单笔预算，则不交易，不能把 stop 强行缩窄到预算内。

### 12.3 Tight 与 Wide Stop

- scalp 的 tight stop 只适用于失败应迅速暴露、且目标较短的区间边缘交易。
- swing 和 broad channel 使用 wide structural stop，同时降低 quantity。
- 极端波动时 ATR floor 扩大仓位风险距离，quantity 自动下降。
- stop 触及涨跌停且无法成交时，账面风险按 limit lock stress 继续计提，不视为已止损。

## 13. Position Sizing

### 13.1 单笔风险

```python
confidence_gate = int(
    large_cycle.confidence >= cfg.min_cycle_confidence
    and medium_cycle.confidence >= cfg.min_cycle_confidence
)
risk_budget = min(
    equity * cfg.max_trade_risk,
    equity * cfg.risk_per_trade
    * cycle_multiplier
    * drawdown_multiplier
    * new_order_risk_multiplier
    * confidence_gate,
)
loss_per_lot = (
    abs(entry - stop) * contract_multiplier
    + estimated_entry_cost
    + stressed_exit_cost
)
raw_qty = floor(risk_budget / loss_per_lot)
qty = floor_to_lot_step(raw_qty)
```

其中 ATR 已通过 `stop_distance` 进入 `loss_per_lot`：波动越大，每手风险越大，仓位自然越小。第一版不再叠加一个未定义的 volatility multiplier，避免同一风险重复降权。

再依次应用硬约束：

```text
symbol/sector/portfolio remaining risk
margin and liquidity cap
```

当前 cycle_v1 风险配置而非收益承诺：

```text
risk_per_trade = 2.00% equity
hard maximum = 2.00% equity
```

周期风险倍率保持不变。20 万账户在其他倍率均为 1 时，强突破、窄通道、宽通道、
震荡的预算分别为 4000、3200、2400、1600 元。单品种、板块、组合和保证金上限
仍单独检查，因此通过单笔 sizing 不等于订单必然进入计划。任何参数调整必须在
walk-forward 训练窗完成。

### 13.2 Market Cycle 风险倍率

初始研究值：

| 状态 | 倍率 | 原因 |
|---|---:|---|
| Strong Breakout | 1.00 | 方向优势强，但 stop 常较宽 |
| Tight Channel | 0.80 | 顺势，仍防止后期高潮 |
| Broad Channel | 0.60 | 双向波动和深回调更多 |
| Broad Range Edge | 0.40 | scalp 对成本和成交更敏感 |
| Transition/Low Confidence | 0.00 | 不交易 |

倍率必须作为消融项验证；不得因为某品种历史表现差就单独降到零并仍称为通用策略。

### 13.3 保证金约束

```python
margin_required = qty * entry * multiplier * margin_rate_side
margin_after_order <= equity * cfg.max_margin_utilization
```

保证金检查不能替代风险仓位。高杠杆但 stop 很远的交易仍按 stop loss 风险限制。

## 14. Trade Management 与 Exit

### 14.1 退出优先级

```text
1. 数据/元数据/合约安全阻断
2. 交易所涨跌停和真实可成交检查
3. 硬性保护 stop
4. setup failure / opposite strong breakout
5. 预定义 scalp target / partial target
6. structural trailing stop
7. time/session/roll exit
```

### 14.2 Break-even

默认不在刚达到微小浮盈时移动到成本。只有同时满足以下条件才允许：

```python
allow_break_even = (
    running_mfe_R_asof >= cfg.break_even_min_mfe_R
    and favorable_structure_confirmed
    and remaining_space_R >= cfg.runner_min_space_R
)
```

`running_mfe_R_asof` 只使用截至当前决策事件已发生的价格；完整交易结束后的 MFE label 不可导入管理模块。

强突破和 tight channel 优先把 stop 放在最新 major HL/LH 后，而不是机械成本价。break-even 作为消融项独立比较。

### 14.3 Trailing

| 状态 | 首选 trail |
|---|---|
| Strong Breakout | 每个新强突破段起点/major HL-LH |
| Tight Channel | 最近主要结构，必要时 EMA/ATR 只作更宽保护 |
| Broad Channel | major swing trail，避免普通 EMA 穿越洗出 |
| Range Scalp | 固定 target 或 range mid，不使用长 runner |

trail 只能朝降低风险方向移动。使用 pivot 时，移动时刻必须是 `known_at`，不是 pivot bar。

### 14.4 Partial Exit 与 Runner

第一版比较两个简单版本：

```text
A. 全仓结构退出
B. 1R 或前极值减仓固定比例，剩余按结构 trail
```

不默认假设分批一定更优。少于 2 手时不能模拟不存在的 partial。手续费和滑点按每次真实成交计入。

### 14.5 顺势加仓

v0 设置 `max_add_ons=0`，不加仓。后续只把以下版本作为 A7 内的独立管理消融，不能和其他退出改动同时引入：

```python
add_on_allowed = (
    cfg.max_add_ons > 0
    and add_on_count < cfg.max_add_ons
    and cycle in {
        STRONG_BULL_BREAKOUT,
        BULL_TIGHT_CHANNEL,
        BEAR_TIGHT_CHANNEL,
        STRONG_BEAR_BREAKOUT,
    }
    and always_in_unchanged
    and running_mfe_R_asof >= cfg.add_on_min_mfe_R
    and new_causal_pullback_setup
    and not session_roll_or_limit_block
)
```

`running_mfe_R_asof` 只累计到当前决策事件的已发生价格，不是回测结束后计算的 label。add-on 必须生成新的候选、结构 stop、订单和审计记录；只允许盈利后顺势增加，禁止向亏损仓摊平。新增后的最坏可执行 `open_risk` 不得超过单品种、板块、组合上限，也不得超过原计划单笔预算；若要靠过早收紧原仓 stop 才能腾出预算，则拒绝加仓。`add_on_risk_fraction` 只缩小新增风险，不能放大初始风险。

### 14.6 趋势持有与衰减退出

延长持有：状态仍是 breakout/tight channel、Always-In 未变、major structure 未破、反向 pressure 未连续确认。

提前退出：`gate_breakout_failure`、进入 trading range 且持仓位于不利边缘、可用净空间低于成本、临近强制换月或 session 风险窗口。反向 follow-through 统一调用 7.3 的定义，不得在退出模块另造阈值。

禁止用未来 MFE 找“最佳退出 bar”。所有退出只能由当时状态触发。

## 15. Portfolio Risk Management

### 15.1 风险口径

```python
open_risk = sum(
    qty * abs(mark_price - executable_stop_price) * multiplier
    + stressed_exit_cost
)
```

若 stop 因涨跌停可能无法执行，使用压力价格而不是 nominal stop。

### 15.2 限额

至少配置：

```text
max_trade_risk
max_symbol_open_risk
max_sector_open_risk
max_total_open_risk
max_margin_utilization
max_daily_loss_soft / hard
max_drawdown_soft / hard
```

板块映射至少覆盖：黑色、有色、贵金属、能源、化工、油脂油料、谷物、软商品、畜牧、航运、股指、国债。相关品种不能各自占满风险，例如 `RB/HC/I/J/JM`、`P/Y/OI`、`CU/BC`。

### 15.3 相关性与集中度

相关性估计只用过去收益，采用滚动窗口并设置最小样本。组合风险采用较保守者：静态产业链组上限与动态相关簇上限。任何单 symbol 的 OOS PnL 贡献超过组合阈值都要在报告中披露，不能让一个品种掩盖其他品种无效。当前 locked fold 只能诊断，禁止看完该 fold 后重算权重；任何降权规则必须形成新版本并在下一未见 fold 前预注册。

### 15.4 日亏损与回撤

统一使用扣除当日外部出入金后的权益：

```python
daily_loss_ratio = max(0.0, day_start_adjusted_equity - adjusted_equity) / day_start_adjusted_equity
drawdown_ratio = max(0.0, high_watermark_equity - adjusted_equity) / high_watermark_equity

if daily_loss_ratio >= cfg.max_daily_loss_hard:
    new_order_risk_multiplier = 0.0
elif daily_loss_ratio >= cfg.max_daily_loss_soft:
    new_order_risk_multiplier = 0.0
else:
    new_order_risk_multiplier = 1.0

if drawdown_ratio >= cfg.max_drawdown_hard:
    drawdown_multiplier = 0.0
elif drawdown_ratio <= cfg.max_drawdown_soft:
    drawdown_multiplier = 1.0
else:
    span = cfg.max_drawdown_hard - cfg.max_drawdown_soft
    progress = (drawdown_ratio - cfg.max_drawdown_soft) / span
    drawdown_multiplier = 1.0 - progress * (1.0 - cfg.drawdown_floor_multiplier)
```

达到日亏损 soft limit：取消新订单，现有仓按原 stop 管理；hard limit 额外触发人工/系统风险告警，但不能仅为让回测好看而假设所有仓位可立即成交。达到回撤 hard limit 后停止新仓，老仓按极端市场安全规则处置。回撤倍率只减不加；恢复须在下一交易日且低于 soft limit，或经过版本化冷静期，不能盘中因短暂反弹重新放大。不得为了追回损失提高 risk per trade。

## 16. 中国期货特殊适配

### 16.1 必须处理

- 夜盘属于下一交易日，且不同品种夜盘结束时间不同。
- 午间休市和交易小节不能被普通 resample 跨越。
- 涨跌停可能使 stop 无法成交。
- 保证金、手续费、平今费和限仓可能按日期、合约、方向变化。
- 主力换月和临近交割会改变流动性，连续合约跳点不能成交。
- 不同 tick、乘数和价格量级要求 ATR/tick 归一化。
- 政策、产业和外盘事件可造成 session gap 与流动性断层。
- 新上市和低流动性品种历史短，不能因为回测样本少而降低门槛。

### 16.2 Brooks 方法适配结论

| 方法 | 结论 | 中国期货调整 |
|---|---|---|
| Market Cycle/context | 可直接使用思想 | 周期、session 和状态阈值需归一化 |
| Strong breakout/follow-through | 可重点实现 | 检查涨跌停、夜盘 gap、真实可成交空间 |
| Tight/broad channel | 可重点实现 | 使用 ATR/tick、结构和成本，不使用固定点数 |
| H1/H2/two-legged pullback | 可实现 | 必须用实时 tracker，禁止 pivot 回填 |
| Range edge scalp | 有条件使用 | 仅高流动性、宽度覆盖成本时开放 |
| Limit-order scaling in | 第一版不采用 | 排队成交和风险尾部难以可靠模拟 |
| Fixed Emini scalp size | 不适合 | 按合约成本、ATR、tick 动态决定 |
| Always-In | 可作为方向状态 | 不解释为始终满仓，需滞回和大周期约束 |

### 16.3 极端市场 fail-closed

以下任一成立时禁止新仓：

```text
metadata_missing
calendar_ambiguous
contract_mapping_unknown
near_delivery_block
volume_or_open_interest_below_gate
spread_or_slippage_above_gate
price_at_or_too_near_limit
data_gap_above_gate
order_type_not_supported
portfolio_risk_unavailable
```

已有仓位进入风险处置状态，但不能在回测中假设一定能按 stop 平仓。

## 17. 不同品种的交易机会

### 17.1 核心原则

跨品种不是“给每个 symbol 找一组最赚钱参数”，而是：

```text
共享市场周期和 setup 语义
    + 品种真实交易机制
    + 仅由过去数据形成的信息密度/流动性画像
    + 统一的样本外启用门槛
```

所有可交易品种先运行相同候选生成器，完整保存候选和拒绝原因。某品种候选少是研究结果，不得为增加交易数放宽规则。

### 17.2 Instrument Research Profile

```python
@dataclass(frozen=True)
class InstrumentResearchProfile:
```

下表是待验证研究假设，不是已证明结论，也不是静态 allowlist。

| 谷物软商品 | C、CS、CF、SR、AP、CJ、PK | 日线/较大周期 broad channel、range edge | 季节和政策、部分品种流动性/跳空、短周期成本 |

| 国债 | T、TF、TS、TL | 低波动趋势/通道、突破后回调 | tick/久期差异、宏观事件、短周期 ATR 可能不足以覆盖成本 |
| 新上市/低流动性 | 按画像动态识别 | 默认只记录候选，不实盘 | 样本不足、零成交、规则变化、回测成交偏乐观 |

### 17.4 Setup 开放矩阵

每个 fold 先按画像检查，不按该 fold 未来 PnL 检查：

```python
eligibility = (
    history_sessions >= cfg.min_history_sessions
    and median_atr_ticks >= cfg.min_atr_ticks
    and median_cost_to_atr <= cfg.max_cost_to_atr
    and zero_volume_ratio <= cfg.max_zero_volume_ratio
    and metadata_coverage == 1.0
)
```

| 条件 | Breakout | Pullback/H2 | Range Scalp |
|---|---:|---:|---:|
| 高流动性、ATR/tick 充足 | 开放 | 开放 | 宽度覆盖压力成本时开放 |
| session gap 高 | follow-through 后开放 | 降风险 | 默认关闭隔夜边缘单 |
| limit event 高 | 远离 limit 才开放 | 降风险 | 关闭 |
| 历史短 | 研究记录 | 研究记录 | 关闭 |
| 成本/ATR 高 | 仅大周期 | 仅目标空间充足 | 关闭 |
| 元数据不完整 | 全部关闭 | 全部关闭 | 全部关闭 |

### 17.5 允许与禁止的品种差异

允许差异化：

```text
contract multiplier, tick, lot step, sessions,
fees, close-today fees, margin, limits, delivery/roll,
base slippage ticks, liquidity gates,
按信息密度规则选出的 timeframe,
由过去波动与 gap 得到的风险上限
```

默认禁止差异化：

```text
为单品种修改 breakout body threshold
为亏损品种改 H2 定义
按全历史最优利润选择 EMA/ATR 窗口
降低低流动性品种成交要求以增加交易
测试后删除亏损方向、年份、session 或 setup
```

只有“共享规则失败但某个预先定义品种簇存在稳定、可解释的微观结构差异”时，才允许新增 profile-level 参数。必须新增策略版本、独立消融，并在未参与决策的品种和时间上复验。

### 17.6 机会报告

报告必须同时输出：

```text
symbol x cycle x setup x direction 候选数
通过流动性/元数据/风险后的计划数
订单数、成交数、完整 round-trip 数
每层减少的数量和 reason_code
毛/净结果、成本占毛利润比例
按品种与产业链的 PnL 和风险贡献
```

不能只展示成交；候选到成交的漏斗是判断不同品种为何没有机会的必要证据。

## 18. Lookahead Bias / Label Leakage Audit

### 18.1 核心审计表

| 对象 | 允许信息 | 最早可用时刻 | 禁止做法 |
|---|---|---|---|
| 原始 bar | 当前已完成 OHLCV | `bar_end` | 使用当前未完成 high/low |
| EMA/ATR/rolling | 当前及过去完成 bar | 当前 `bar_end` | centered rolling、全样本归一化 |
| range 边界 | `shift(1)` 后过去窗口 | 当前 `bar_end` | 让当前突破 bar 抬高自己的边界 |
| breakout | 当前收盘与过去边界 | 当前 `bar_end` | 按当前收盘无滑点成交 |
| follow-through | 下一根完成 bar | 下一根 `bar_end` | 回填到 breakout bar |
| pivot swing | 左右 bar | 右侧第 `r` 根 `bar_end` | 回填到 pivot 时间用于成交 |
| H1/H2 | 实时 tracker 状态 | 尝试实际触发/信号确认时 | 看完整回调后重编号 |
| wedge | 已确认 pushes 或实时 tracker | 第三推确认以后 | 用未来极值选择三推 |
| Market Cycle | 当前前缀特征 | 当前状态快照时刻 | 用未来收益定义当前状态 |
| Higher TF | 已完成高周期 bar | 高周期真实 `bar_end` | forward fill 未完成日线 |
| 主力映射 | 决策前已公布/可知数据 | `mapping_known_at` | 用当日收盘量决定当日早盘合约 |
| 费率/保证金/limit | 当时已知版本 | `known_at` | 当前规则回填历史 |
| MFE/MAE/return label | 未来路径 | 仅训练标签 | 进入实时 feature 或状态阈值 |

### 18.2 Prefix invariance

每个在线特征、状态和候选函数必须通过：

```python
full = compute(frame)
for end in sampled_prefix_ends:
    prefix = compute(frame.iloc[:end])
    assert_frame_equal(
        prefix,
        full.iloc[:end],
        check_exact=False,
        rtol=1e-12,
        atol=1e-12,
    )
```

允许的例外只有显式带 `known_at` 的确认事件；比较时按 known-at 事件流，而不是 pivot bar 索引。

### 18.3 决策与成交时间不变量

```python
feature_event = (feature_asof, feature_sequence)
known_event = (signal_known_at, known_sequence)
decision_event = (decision_asof, decision_sequence)
active_event = (order_active_at, activation_sequence)
fill_event = (fill_time, fill_sequence)

assert feature_event <= known_event <= decision_event < active_event <= fill_event
assert (metadata_known_at, metadata_sequence) <= decision_event
assert metadata_effective_from <= order_active_at < metadata_effective_to
assert (mapping_known_at, mapping_sequence) <= decision_event
```

其中 `effective_to=None` 按正无穷处理。任何违反直接使回测失败，不能只写 warning。必须覆盖“signal bar 的 `bar_end` 与下一 execution bar 的 `bar_start` 相同”场景，证明同时间戳下仍由 sequence 阻止订单参与已经结束的 bar。

### 18.4 标签隔离

训练数据分为：

```text
X: 截至 candidate.known_at 的因果 feature snapshot
y: known_at 之后固定 horizon 的 MFE/MAE/net R/是否先到 target
```

构造标签的模块不能被在线策略导入。数据集输出保留 `feature_end`、`label_start`、`label_end`，交叉验证对重叠 horizon 做 purge/embargo。

## 21. 回测与研究方案

### 21.1 Level 1：Market Cycle

不先看策略 PnL，验证：

```text
状态覆盖率、UNAVAILABLE 比例、平均持续 bar、切换矩阵、
bull/bear 镜像性、跨品种状态分布、参数扰动稳定性、
prefix invariance、人工抽样图表与 evidence 一致性
```

人工图表只用于发现定义错误，不能据此调到每张图都“看起来正确”。状态分类不使用未来收益作为特征。

### 21.2 Level 2：Setup x Cycle

对所有候选输出矩阵：

```text
setup x cycle x direction x symbol x sector x timeframe
```

统计：候选数、计划数、成交数、win rate、avg win/loss、expectancy R、profit factor、MFE、MAE、持有期、费用、滑点、失败原因。重点比较：

```text
H2 x Broad Channel
H2 x Trading Range
First Pullback x Strong Breakout
Breakout x Tight Breakout Mode
Failed Breakout x Range Edge
```

若 setup 只在一个 symbol 或一个年份有效，不进入组合生产版本。

### 21.3 Level 3：完整 Portfolio

使用真实合约映射、历史元数据、基础执行周期、板块风险和现金/保证金账本。至少报告：

```text
Trade Count, Win Rate, Average Win, Average Loss,
Profit Factor, Expectancy R, Annualized Return,
Sharpe, Sortino, Max Drawdown, Calmar,
MFE, MAE, Holding Period, Turnover,
Fees, Slippage, Cost/Gross Profit,
Margin Utilization, Open Risk, Tail Loss,
symbol/sector PnL and risk contribution
```

日收益分母包含零交易日。所有收益默认净收益，毛收益只能作为成本分析附表。

### 21.4 数据切分

按每个品种共同可审计区间选择 fold，不强行让新品种拥有不存在的历史。推荐：

```text
rolling train: 5 years
validation:    1 year
locked test:   next 1 year
step:          1 year
embargo:       >= max label/holding horizon
```

示例仅用于说明：

```text
Train 2015-2019 -> Validate 2020 -> Test 2021
Train 2016-2020 -> Validate 2021 -> Test 2022
后续 fold 继续按一年步长滚动
```

最终参数只能由 train/validation 产生。test 一经生成不得回头修改该版本；修改后必须产生新策略版本和未来锁定区间。

### 21.5 成交与成本压力

每个结果至少比较：

```text
base cost
1.5x slippage
2.0x total cost
one-bar delayed entry
adverse OHLC ambiguity
limit-lock exit stress
```

压力后完全失效的 setup 不进入实盘候选。

### 21.6 跨品种稳健性门槛

进入下一阶段前应同时满足：

1. 组合锁定 OOS 净 expectancy 为正，且置信区间/重采样结果不依赖少数异常交易。
2. 品种净 expectancy 中位数不为负；不得要求每个品种都盈利。
3. 单一品种 PnL 贡献不超过预注册集中度；当前 locked OOS 超限即本版本晋级失败并原样披露，禁止事后降权使其通过。
4. 主要产业簇至少两个具有独立有效证据，避免只得到黑色单板块策略。
5. 成本和延迟压力后风险收益仍可接受。
6. 参数附近形成平台而不是尖峰。
7. 多空分别报告；一侧无效不能被另一侧掩盖。
8. 候选到成交漏斗完整且无事后删除。

阈值必须在第一次正式锁定评估前写入研究协议。降权只能作为新策略版本，在下一未见 fold 前预注册；原 locked OOS 结果永久保留。

## 22. Ablation Test

固定加入顺序：

| 版本 | 新增模块 | 要回答的问题 |
|---|---|---|
| A0 | 单 setup，无 context | 原始形态是否有任何 edge？ |
| A1 | + 大周期方向 | 趋势许可是否减少逆势损失？ |
| A2 | + Market Cycle | edge 是否只存在于特定周期？ |
| A3 | + Always-In 滞回 | 是否减少方向抖动？ |
| A4 | + 多周期对齐 | 是否提高净 expectancy 而非仅减少交易？ |
| A5 | + 结构 stop | 是否改善尾部和实际风险？ |
| A6 | + ATR 风险仓位 | 是否降低品种量级偏差？ |
| A7 | + trade mode/management | swing 是否抓住主要趋势段？ |
| A8 | + portfolio/sector risk | 是否降低集中回撤？ |
| A9 | + volume/ADX 辅助 | 辅助指标是否真的增益？ |

每次只增加一个模块，输出：净收益、expectancy、Sharpe、最大回撤、交易数、成本和各品种贡献变化。复杂度增加但 OOS 无稳定改善时删除该模块。

## 23. Walk-Forward 与防过拟合

- 共享参数在跨品种 train 集统一估计，不对每个 symbol 搜索独立阈值。
- 品种画像和 eligibility 只用 fold 训练窗末日前数据。
- 同一产业链的高度相关样本不能被当成大量独立证据。
- 参数搜索记录全部 trial，不只保存赢家；报告搜索空间和试验数。
- 优先选择中位 OOS、回撤、成本压力和参数平台，不按最高净利润选择。
- 新增例外规则必须有经济/微观结构原因和独立 OOS，不接受“因为该品种亏损”。
- 可增加 leave-one-symbol-out：在其余品种定参数，在被留出的 symbol 检验泛化。
- 可增加 leave-one-sector-out：验证规则不是依赖单产业链。
- 锁定 test 不参与状态阈值、setup 开关、品种筛选、持有期或风险倍率决策。

## 24. 后续 ML 扩展

### 24.1 边界

第一阶段完全规则化。第二阶段才允许：

```text
Rule-based Candidate Generator
    -> ML Trade Quality Filter
    -> 原规则 Entry/Risk/Execution
```

ML 不能生成原规则没有的订单，也不能放大单笔风险。

### 24.2 目标

可预测：

```text
P(target before stop)
Expected net R
MFE / MAE quantiles
Trade quality rank within same timestamp
```

算法保持可替换，不预设 XGBoost。先用逻辑回归/单调模型作为基线，再比较复杂模型是否有稳定 OOS 增益。

### 24.3 防泄漏

- feature 只能来自 candidate `known_at` 快照。
- label 可以使用未来，但必须隔离模块并记录 horizon。
- purged walk-forward 防止持有区间重叠。
- scaler、缺失值处理、特征选择都只 fit train。
- SHAP/feature importance 只用于解释，不能替代消融和 OOS。
- 模型失败或版本不匹配时 fail-closed，不能退回未经审计的默认概率。

`cta/strategy/brooks/report/cycle_v1/<run-id>/`。CLI 现已接入实际合约 lifecycle、
逐日 trading status、保守 bar matcher 的 STOP capability、保证金、涨跌停、费用、
下一分钟激活、OCO 和实际合约账本。合约切换仅在新合约首根 bar 到达后可见，先
取消旧挂单；若仍有旧合约持仓但没有旧合约执行 bar，则返回
`BLOCKED_ROLL_EXECUTION_BAR`，禁止预读下一根 bar 并在旧 bar 回填退出。覆盖审计按每个实际合约交易日输出
`instrument/daily/lifecycle/status/cost/capability:STOP` 六类字段；任一缺失仍保持
`BLOCKED_METADATA`，不得拼接子区间收益。

选择顺序是显式、Top-N、EMA 扩展，按根品种首次出现去重；EMA 扩展只使用请求日之前
最近一根完整日 K。显式 LC 可通过有效期合约参考解析为 GFEX。单品种映射或分钟下载
失败进入审计并继续其他品种，已有可识别 alias 目录继续复用；下载结束后若 selected
根品种仍不可发现，回测在加载前阻断，不能静默缩池。只有显式提供
`--download-minute-data` 才联网；不提供时 runner 仍按原本的本地 `--symbols/all` 运行。
下载模式中单独的 `--symbols all` 表示空显式池，必须同时提供正数 `--top-n` 或
`--include-ema-eligible`，不会展开成本地全部目录或意外触发全市场下载。
完整下载审计写入 `summary.json.minute_data_update`，也可由 `--download-audit-output`
独立保存。行情完成后，runner 从同一 selected 并集的 parquet 提取精确历史实际合约日，
自动在 `--metadata-cache-root` 构建并验证内容寻址 mechanics bundle。Tushare
`fut_basic/trade_cal/fut_settle` 与 Jin10 历史交易参数镜像按前一开市日对齐；合约身份、
前结算和多空保证金必须跨源一致，开仓、平昨、平今手续费不得互相代填，价格与手续费
公布时间必须早于 session open。当前账户无 Tushare `ft_limit` 权限，因此镜像涨跌停仅在
上述独立对账通过后使用；既有 RB/CU 直接官方行保持优先。

缓存只在四张 canonical CSV、manifest 和原始响应 gzip 审计全部校验后原子发布；重复输入
直接复用，base `--meta-root` 永不原地修改。紧凑审计写入
`summary.json.execution_metadata_update` 和 `report.md` 的 `Execution Metadata Update`。
任一网络、权限、字段、公布时间或跨源冲突仍生成 `BLOCKED_METADATA` 报告，正式绩效为
`null`，禁止默认 mechanics、当前值回填和静默缩池。

EMA 无合格日期记录 `NO_EMA_ELIGIBLE_DATE`，与缺日线、坏日线和合约参考 API 失败分离；
局部异常不移除其他来源已选品种。目录身份扫描失败时禁止猜测 alias 落盘。审计 `files`
对 `downloaded/skipped/converted_schema` 均记录实际合约、路径和 SHA256；既有 CU
schema 修复失败只阻断该文件并继续其他品种。普通已有文件必须读取出与当日 mapping
一致的唯一实际合约，否则记录 `existing_identity` 且禁止把 mapping 值冒充文件身份；
普通文件不覆盖，历史 CU generic schema 的受控等价迁移单独记为 `converted_schema`。

报告同时输出 `candidates/plans/orders/fills/trades/daily_equity`、分组绩效、拒绝原因、
来源文件和 metadata coverage。`report.md` 顶部先输出 `Trading Summary`，并在启用自动构建时
