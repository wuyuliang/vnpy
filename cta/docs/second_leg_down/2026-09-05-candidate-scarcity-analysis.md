# 半年只有 9 笔：哪个门在卡，以及放宽哪个才有用

`report/second_leg_down/sld_v1`（2026-01-01 ~ 2026-07-01，40 品种）只成交 9 笔，
候选表只有 16 行。问题不在仓位或出场，**在候选生成之前就没东西了**。

## 1. 方法

一笔一笔猜参数、每猜一次跑一次全量回测太贵。写了
`cta/analysis/second_leg_down_funnel_scan.py`：直接扫原始分钟分区，用**向量化
复刻**的入场谓词数各道门的存活数，整个参数扫描几秒钟跑完。

复刻刻意不 import `cta.strategy.second_leg_down`——它从 K 线间隔重新推交易
时段，而不是读元数据 sessions，所以顺带交叉验证了生产代码。
**标定：在出厂参数下它预测 40 品种 9 个候选，实际成交 9 笔。**

它没有撮合、手续费、滑点、仓位和资金上限，所以绝对值是上界，
**只能用来做参数之间的相对比较**。

## 2. 漏斗（21 个品种 / 876,779 根 1 分钟 K 线 / 2026H1）

| 门 | 存活根数 | 占比 |
| --- | ---: | ---: |
| EMA5<EMA10<EMA20 | 354,482 | 40.4% |
| 交易时间窗（开盘后 10 / 收盘前 20 分钟） | 565,003 | 64.4% |
| **实体 ≥ 3×ATR14 的阴线** | **1,508** | **0.17%** |
| 放量 ≥ 2× 基线 | 91,998 | 10.5% |
| 大阴线 **且** 放量 | 1,468 | — |
| 再加下影线约束 | 919 | — |
| **相邻两根同时满足（两根形态）** | **5** | — |

## 3. 结论：卡住的是 N，不是成交量

**放量那道门根本不是约束。** 1,508 根大阴线里有 1,468 根（97.3%）本来就已经满足
2× 放量——大阴线天生带量。所以：

> **把成交量基线从 20 根移到 60 根，没有用。** 实测 73 → 69 命中，反而略少
> （窗口拉长把基线抬高了一点）。120 根 → 70，240 根 → 71。全在噪声里。

真正的绞索是 **`big_body_atr_mult = 3.0`**，而且要求**相邻两根都**达标。
单根 3×ATR14 已经是千分之一点七的事件，两根挨着就是十万分之一量级。

单参数敏感度（其余保持出厂值，21 品种）：

| N | 命中 | | M | 命中 | | 影线比 | 命中 |
| ---: | ---: | --- | ---: | ---: | --- | ---: | ---: |
| 3.00 | 5 | | 2.5 | 59 | | 0.15 | 73 |
| 2.50 | 13 | | 2.0 | 73 | | 0.25 | 111 |
| 2.00 | 29 | | 1.5 | 94 | | 0.40 | 133 |
| 1.75 | 46 | | 1.2 | 104 | | 0.60 | 152 |
| 1.50 | 73 | | 1.0 | 108 | | 1.00 | 159 |
| 1.25 | 131 | | | | | | |
| 1.00 | 227 | | | | | | |

（M 和影线比那两列在 N=1.5 下扫，否则基数太小看不出斜率。）

N 每降 0.25，命中大约翻倍。影线比是第二根杠杆：0.15 → 0.40 命中翻倍——
0.15 对一根 3×ATR 的大阴线其实相当苛刻。

## 4. 放宽之后样本会不会变差

对每个命中点算入场后的正向/反向行程（entry = 最后一根收盘，
R = 形态区间最高价 − entry）：

| 参数组 | n | 5 根内 MFE≥0.5R | 10 根内 MFE≥0.5R | 20 根内 MFE≥1R | 20 根内 MAE≥1R | 中位 MFE20 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 出厂 N=3.0 | 5 | 0.0% | 0.0% | 0.0% | 20.0% | 0.30R |
| A N=2.0 | 52 | 34.6% | 38.5% | 30.8% | 15.4% | 0.48R |
| B N=1.5 | 153 | 28.8% | 39.2% | 24.8% | 17.0% | 0.47R |
| C N=1.25 | 425 | 35.1% | 46.1% | 31.5% | 24.5% | 0.57R |

**放宽没有让样本变差。** N=3 那 5 个样本的正向行程反而是最差的一档
（中位 MFE20 只有 0.30R，20 根内没有一个走到 1R）。极端阈值买到的不是"更好的
形态"，只是"更少的形态"——而且 5 个样本本来也说明不了任何事。

C 组的反向行程确实更大（MAE≥1R 从 15% 涨到 24.5%），所以不是越松越好；
**A/B 是这次扫描里性价比最高的区间。**

## 5. 顺带发现：5 根无进展止损才是出场端的绞索

9 笔里有 8 笔是 `NO_PROGRESS_TIME_STOP`，全部在第 6 根平掉，
`mfe_r` 一大半是 `-0.00`（从来没有向有利方向走过一次）。

上表也印证了：**只有 29%~35% 的入场能在 5 根内摸到 0.5R。**
按设计，其余三分之二在第 5 根被砍掉——止盈地板几乎永远没机会启动。

放到 10 根，摸到 0.5R 的比例从 28.8% 升到 39.2%（B 组）。但中位 MFE20 只有
0.47R，说明"1R 跟随目标"本来就很少够得着。**`no_progress_bars` 从 5 放到
8~10 值得和入场参数一起 A/B**，否则候选变多了照样在第 6 根全被砍。

## 6. 建议的下一步

按顺序跑 A/B，每次只动一组：

```bash
# A 组（保守放宽）——先跑这个
python3 -m cta.strategy.second_leg_down.backtest.runner \
  --start 2026-01-01 --end 2026-07-01 --initial-equity 1e+06 \
  --download-minute-data --top-n 40 --include-top-turnover 0.8 \
  --allow-missing-symbols --output-root cta/strategy/report/second_leg_down \
  --config-override big_body_atr_mult=2.0 \
  --config-override volume_surge_mult=1.5 \
  --config-override wick_body_ratio=0.25 \
  --run-id sld_A

# B 组（中等放宽）
  --config-override big_body_atr_mult=1.5 \
  --config-override volume_surge_mult=1.5 \
  --config-override wick_body_ratio=0.30 \
  --run-id sld_B

# B + 放宽无进展止损（出场端单独一变量）
  ...B 的三条... --config-override no_progress_bars=8 --run-id sld_B_np8
```

预期候选量（40 品种折算）：A ≈ 99，B ≈ 291，B 每月约 49 个。
到这个量级才谈得上统计意义。

**不要做的事**：把成交量基线从 20 改成 60。已经实测无效，改了只会白跑一轮，
还会让下一次对比多一个混淆变量。

## 7. 还没试但值得试的方向

1. **"腿"口径**（scan 里的 D/E 预设）：不要求两根各自 ≥N×ATR，改成
   **两根合起来的净跌幅 ≥ N×ATR、单根 ≥ N/2**。这更贴近 Brooks 的原意——
   重要的是这一"腿"够强，不是两根长得一样。N=3.0 的腿口径给出 149 命中
   （≈40 品种 283 个），与 per-bar N=1.5 相当，但形态含义更干净，
   而且天然接纳"一根大阴线 + 一根跟随阴线"这种最常见的形状。
   需要在 `rules.py` 里加一个 `body_mode: per_bar | leg` 开关。
2. **放开三根形态的中间根**：现在要求 `high(M) <= high(F)`。改成允许小幅
   上插（`high(M) <= high(F) + 0.25*ATR`）能多接一批标准的"两腿推进"。
3. **扩品种**：现在 `--top-n 40`。这个形态本质是横截面事件，品种数直接线性
   放大样本。`--top-n 60` 加上成交额补池是最没有副作用的加样本方式——
   它不改变任何形态定义，不会污染参数评估。

第 3 条应该**第一个做**：它是唯一一个"加样本但不动策略定义"的杠杆。

# 附：5 分钟信号周期实测（2026-09-05 补）

问题："把 1min 换成 5min 试试效果"。

## A.1 实现

`signal_timeframe_minutes`（默认 1）。>1 时用 `aggregate_completed_bars`
把 1 分钟合成 N 分钟找形态，**执行与出场仍然走 1 分钟**：

- 订单活在执行时间轴上。10:05 收盘的 5 分钟 K 线，产生的订单属于 **10:06**
  那根 1 分钟 K 线，不是 10:10。见 `strategy._order_window`。
- 以"根"计的窗口（`no_progress_bars` / `follow_through_bars`）说的是**信号周期
  的根数**。落到 1 分钟引擎前由 `SecondLegDownConfig.for_replay()` 乘回去
  （5 根 → 25 根）。不折算的话每笔 5 分钟交易都会在自己的第一根信号 K 线里
  被砍掉，这个对比就没意义了。
- 折算在 `--config-override` **之后**执行（共享 runner 新增 `config_finalizer`
  钩子），否则命令行改了周期却拿不到折算。

## A.2 结论：5 分钟不是加样本的方向

21 品种 / 2026H1，同一套参数：

| 周期 | 总 K 线 | leg N=4.0 命中 | ≈40 品种 | ≈每月 |
| --- | ---: | ---: | ---: | ---: |
| **1 分钟** | 876,779 | **45** | 85 | 14 |
| 5 分钟（ATR 60 根 = 5 小时） | 177,287 | 9 | 17 | 3 |
| 5 分钟（ATR 12 根 = 1 小时，与 1 分钟同墙钟） | 177,287 | 2 | 3 | 1 |

**命中数基本按 K 线根数等比缩小**——每根 K 线的命中率两边差不多，但 5 分钟只有
五分之一的根数。这个形态的出现频率跟的是**根数**，不是周期。要样本就别往上走周期。

## A.3 但 5 分钟的样本质量有一处明显不同

入场后的正向行程（leg N=4.0）：

| 周期 | n | 5 根内 MFE≥0.5R | 20 根内 MFE≥1R | 中位 MFE20 | 20 根内 MAE≥1R |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 分钟 | 45 | 22.2% | 17.8% | 0.47R | 4.4% |
| 5 分钟 | 9 | **44.4%** | **0.0%** | 0.30R | 11.1% |

两件事：

1. **5 分钟在"自己的头 5 根"里摸到 0.5R 的比例翻倍**（44% vs 22%）。但那 5 根
   是 25 分钟，1 分钟那 5 根只有 5 分钟——这不是 5 分钟更好，而是**再次印证
   `no_progress_bars=5` 在 1 分钟上太紧**：这个动作本来就需要二十来分钟才走得出来。
2. **5 分钟的 R 更大**（止损是 5 分钟形态区间的高点，宽得多），所以 20 根内
   够到 1R 的比例是 **0%**，中位 MFE20 只有 0.30R。同样的价格波动，用更宽的
   R 去量就显得更小。

综合：**5 分钟既没有更多样本，R 口径的收益也更差**。真正值得单独试的是把
1 分钟的 `no_progress_bars` 放宽到 20~25，那才是这两张表共同指向的东西。

## A.4 顺带修掉的两个 bug

扫描脚本的 `--bar-minutes` 路径原本全灭（5 分钟下命中恒为 0），两处原因：

1. 时段切分的间隔阈值写死 1 分钟。5 分钟 K 线上相邻两根本来就差 5 分钟，
   于是**每一根都被判成新时段**，成交量基线和交易时间窗直接全空。
2. `min_samples` 写死 15，而 `--baseline-bars 12` 时 `rolling(12).count()`
   最大只有 12，成交量那道门永远不满足。

`--config-override` 也修了一个：它按 `MultiTimeframeTrendConfig` 的字段解析，
所以并行策略自己的字段（`body_mode`、`leg_body_atr_mult`、
`signal_timeframe_minutes` …）一律报 `unknown config field`。改成按**本次运行
实际使用的配置类**解析，并支持 str 字段（取值合法性仍由 `__post_init__` 把关）。
在此之前，本文档 §6 里所有 `--config-override` 命令其实都是跑不起来的。

## A.5 仓位：一手放宽档

`max_capital_share=0.10` 装不下一手时，改为：一手若能装进
`single_lot_capital_share=0.15` 就按一手开，超过则 `CAPITAL_LIMIT` 不开。

一处刻意的取舍：放宽档下**跳过 `RISK_BELOW_MINIMUM` 检查**。放宽档只有"一手"
这一个选项，加不了手数；此时再用"风险太小"否掉它，等于同时嫌它资金占用太大、
风险敞口太小。资金约束优先。

候选表新增 `single_lot_relief` 列，事后可以数有多少笔是靠放宽档进的场。
