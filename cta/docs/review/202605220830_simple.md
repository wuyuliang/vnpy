## §2 拆 God Config（A4 / P1 推荐）

### 现状

`cta/config/model_oot_eval_config.py:36 @dataclass class OotEvaluationConfig` 共 **74 字段** + 9 个 dict 默认值 + 360 行 `__post_init__` 校验。

这是教科书级 **God Object** —— 任何小改动都要看 380 行配置文件，新人接手前 2 周都在搞清字段。

字段大致归 7 类（基于命名前缀）：

| 类 | 字段数 | 示例字段 |
|---|---|---|
| **gates** | 12 | `use_trade_filter_gate` / `use_regime_gate` / `use_mfe_mae_gate` / `use_stacking_gate` / `use_ma_cross_gate` / `use_regime_short_filter` / 6 个 threshold |
| **gate_thresholds_by_dim** | 6 | `trade_filter_raw_threshold_by_cluster_interval` / `..._side_bull_mode` / `intrabar_stop_loss_pct_by_cluster_interval` / `ma_cross_enabled_by_cluster_interval` / `regime_short_filter_enabled_by_cluster_interval` |
| **bull_mode** | 5 | `bull_strength_score_column` / `bull_attack_percentile_threshold` / `bull_late_risk_percentile_threshold` / 2 个 delta |
| **sizing & limits** | 12 | `initial_capital` / `risk_per_trade_pct` / `max_single_loss_pct` / `max_position_scale` / `max_symbol_notional_pct` / `max_concurrent_positions_*` / `commission_pct_per_trade` / `slippage_pct_per_trade` / 等 |
| **intrabar** | 5 | `use_intrabar_stop_tracking` / `intrabar_tracking_interval` / `intrabar_tracking_fallback_intervals` / `intrabar_stop_loss_pct` / `intrabar_stop_loss_pct_by_cluster_interval` |
| **portfolio_constraints** | 14 | `use_portfolio_constraints` / `margin_rate` / `max_total_leverage` / `max_daily_new_notional_pct` / `weekly_max_drawdown_pct` / `monthly_max_drawdown_pct` / `block_new_entries_on_*` 等 |
| **misc** | 20+ | `use_roll_cost` / `default_roll_cost_pct_per_year` / `roll_cost_day_of_month` / `roll_cost_day_count` / `stop_loss_consistency_tolerance` / `enforce_stop_loss_consistency` / `symbol_contract_specs` / etc. |

**问题**：

- 看 `cfg.use_ma_cross_gate` 时，IDE 自动补全弹 74 个字段
- `__post_init__` 360 行逻辑都跑（哪怕只是想配 commission_pct_per_trade）
- 一个 bug 涉及 trade_filter，看 model_oot_eval_config.py 整 380 行才能确认所有相关字段

### 推荐拆分

```python
# cta/config/oot_eval/__init__.py
@dataclass(frozen=True)
class OotEvaluationConfig:
    gates:         GatesConfig            # 12 字段
    sizing:        SizingConfig           # 12 字段
    intrabar:      IntrabarConfig         # 5 字段
    portfolio:     PortfolioConstraintsConfig  # 14 字段
    portfolio_logic: PortfolioLogicConfig  # 已有，不动
    misc:          MiscConfig             # 20 字段（roll_cost / stop_loss_consistency / etc.）
```

每个子 config：

- frozen dataclass
- 字段 5-15 个
- 自己的 `__post_init__`（校验 50-80 行）
- 单独的测试文件

### 实施

1. **新增** 5 个子 config 文件：
   - `cta/config/oot_eval/gates.py`
   - `cta/config/oot_eval/sizing.py`
   - `cta/config/oot_eval/intrabar.py`
   - `cta/config/oot_eval/portfolio_constraints.py`
   - `cta/config/oot_eval/misc.py`
2. `OotEvaluationConfig` 改为 5+1 字段的聚合（`PortfolioLogicConfig` 已有，保留）
3. 提供 **向后兼容代理**：临时保留 `__getattr__` 让 `cfg.intrabar_stop_loss_pct` 仍能访问（代理到 `cfg.intrabar.stop_loss_pct`）
4. 调用点逐步迁移到新路径，待全部迁移完后删代理

**风险**：中。迁移期间需双路径并存，测试要补全（每个新子 config 一套 test）。**1 天内完成**。

**效果**：

- LOC 净持平（拆 ≈ 合）
- 但**调用方代码可读性**和**新人 onboarding 速度** 显著提升
- 配置变更影响范围被边界化（动 `gates` 不会影响 `sizing` 测试）

## §6 异常处理收紧（A9 / P3）

### 现状

```bash
grep -rn "except Exception" --include="*.py" cta/ | grep -v __pycache__ | wc -l   # 147
```

147 个 `except Exception:` 中，**估计 80%+ 是 silent swallow**（catch + log + continue），其中很多是 data loading / feature joining 路径上的"容错"。

### 风险

- silent swallow 会掩盖真正的 bug
- 测试覆盖率假象（一个测试因为 except Exception 默默走 fallback 路径，开发以为"测过了"）

### 行动

1. `grep -nB1 -A3 "except Exception" cta/ -r --include="*.py"` 全量列出
2. 按目录分批处理：
   - 把 `except Exception:` 改成具体异常类型（如 `except (FileNotFoundError, ValueError):`)
   - 真不知道捕什么的，至少把 fallback 内容打 `logger.warning` + 包括 stack trace
3. 优先处理 `cta/model/` 和 `cta/portfolio_logic/` 下的（业务核心）；`cta/data_code/` 和 `cta/skills/data_backtest/` 次之

**效果**：

- 行数减少有限（-50 ~ -100），但**bug 暴露速度**和**系统可观测性**显著提升

## §7 杂项 (A10 + A11 / P3)

### 7.1 A10：`block_reasons.py` 4 倍重复

```python
# cta/model/oot/block_reasons.py
BR_BLOCKED_MA_CROSS_TREND = "blocked_ma_cross_trend"   # 1. 常量定义

BlockReason = Literal[
    ...,
    "blocked_ma_cross_trend",                          # 2. Literal 字面量
    ...,
]

CANONICAL_BLOCK_REASONS: tuple[BlockReason, ...] = (
    ...,
    BR_BLOCKED_MA_CROSS_TREND,                         # 3. tuple
    ...,
)

__all__ = [
    ...,
    "BR_BLOCKED_MA_CROSS_TREND",                       # 4. __all__
    ...,
]
```

加一个 reason 要 **4 处同步**，加错一处就 `test_all_emitted_block_reasons_are_canonical` 飘红。

### 推荐

改用 `enum.StrEnum`（Python 3.11+，本项目用 3.10+ 可用 `enum.Enum` + `str` 多继承）：

```python
from enum import StrEnum

class BlockReason(StrEnum):
    INVALID_TIME = "invalid_time"
    BLOCKED_THROTTLE_HALT = "blocked_throttle_halt"
    BLOCKED_MA_CROSS_TREND = "blocked_ma_cross_trend"
    BLOCKED_REGIME_SHORT_FILTER = "blocked_regime_short_filter"
    # ...

# 用法
BlockReason.INVALID_TIME            # 等于字符串 "invalid_time"
str(BlockReason.INVALID_TIME)       # "BlockReason.INVALID_TIME"
list(BlockReason)                    # 32 个枚举（自动）
```

向下兼容：保留 `BR_INVALID_TIME = BlockReason.INVALID_TIME.value` 之类的常量 alias。

**效果**：-90 LOC，单点定义，加 reason 改 1 处。
