## 1. Critical（必须实盘前修复）

### C1. 空头 trailing stop 方向反了
**文件**：`cta/portfolio_logic/trailing_exit.py:280-284`

**问题**：`update_only_in_favor` 为 True 时，short 方向用 `trail_stop = min(trail_stop, new_stop)`。空头的止损价应该在入场价**之上**，价格下跌（对空头有利）时止损应当**下移**收紧。`min()` 会选**更低**的（更松的）那个，等于这个分支永远不收紧，等同关掉 trailing。

**影响**：所有空头仓位的 trailing exit 是死的。如果 trailing 是 alpha 的主要止盈手段，空头收益全部漏出。

**修法**：long 用 `max(trail_stop, new_stop)`，short 用 `min(...)` —— 现在代码看上去把方向搞反了。建议显式：
```python
if direction == "long":
    trail_stop = max(trail_stop, float(new_stop))  # 价格上涨止损上移
else:  # short
    trail_stop = min(trail_stop, float(new_stop))  # 价格下跌止损下移
```
（具体哪边对取决于 `new_stop` 的计算方向，但当前实现两侧的非对称性看着可疑，必须实跑 long+short 各一个例子手工核验。）

---

### C2. Exit cleanup 双扣 margin / open_notional
**文件**：`cta/model/pipeline_oot_evaluation.py:820-821 + 1264-1310`

**问题**：主时间线循环 (line 816-863) 在仓位 exit 时减 `margin_used` 和 `open_notional`。但最终清算循环 (line 1264-1310) 又会对**同一批已退出的仓位**再减一次。`max(0.0, ...)` 把负值兜底成 0 把症状掩盖了，但 `margin_used` / `open_notional` 序列本身已经被腐蚀。

**影响**：组合保证金占用 / leverage 计算在残留仓位场景下偏低 → 后续 entry 误判为"额度充足"，实盘会触发超限。

**修法**：清算循环只记录最终 PnL，不再减仓位。或者主循环 exit 时给位置加一个 `_cleaned_up: bool` flag，清算时跳过。

---

### C3. Margin 在 block 检查前就被自增
**文件**：`cta/model/pipeline_oot_evaluation.py:1135 / 1150-1165 / 1180-1189`

**问题**：交易刚算完 `notional` 就把 `margin_used += notional * margin_rate` 和 `open_notional += notional` 自增（line 1181-1189），**之后**才跑 margin / leverage / daily_position / weekly_dd 等 block 检查（line 1150-1165）。若 block 触发，notional 不会回滚 → 同 bar 的下一笔交易看到的是已虚占了的 margin/notional。

**影响**：实盘场景，多个候选信号在同一 bar 触发时，先被 block 的占了名额，后面的真信号反而被卡。或者过夜后某些 reset 没执行干净，累计错位。

**修法**：把 line 1181-1189 的自增挪到 block 检查全部通过之后；或者用 tentative reserve 模式：先 `tentative_apply()`，全部检查过再 `commit()`，否则 `rollback()`。`PortfolioState` 已有相关接口（但 §C4 显示 rollback 是空实现）。

### C4. `test_pool_training.py` 重蹈 W4 mock namespace 回归覆辙
**文件**：`cta/model/tests/test_pool_training.py:68-99, 122, 151`

## 2. High

### H1. Weekly/monthly drawdown peak stale（只在 exit 时更新）
**文件**：`cta/model/pipeline_oot_evaluation.py:868-878 + 1142-1148`

**问题**：`week_peak_equity` / `month_peak_equity` 只在仓位 exit 时刷新。但 entry 阶段用 `used_dd_amt = max(0.0, week_peak_equity - entry_equity)` 算可用周回撤预算（line 1143）—— 如果 peak 还是上次 exit 时的旧值，且本 bar 内部权益已经爬高，预算就**偏小**，会错误地拒绝新仓。反向，如果权益跌了 peak 没更新，预算就**偏大**，本不该开仓的开了。

**影响**：周/月回撤阈值在 bar 内的精度差一截。靠 weekly_dd_budget 控仓的策略行为偏离设计。

**修法**：在每个 bar 处理完所有 exit 和 entry 之后，统一刷新 peak。或者直接每个 bar 都刷。

---

### H2. Intrabar entry fill 与 stop-loss 计算的 1-bar 错位
**文件**：`cta/model/oot_intrabar.py:133-156`

**问题**：`entry_fill_price` 优先用 `entry_price_hint`，回退 `bar.open` / `bar.close`。stop-loss 用 entry_fill_price 算，但**入场的成交动作**在第一根 bar 上是否真的发生在 bar.open 没有明确建模 —— 如果是真要等下一根 bar 的 open 才能成交，那 stop-loss 应该用下一根 bar 的入场价。

**影响**：在 hint 与真实 fill 价偏差大的场景（gap、滑点），stop 计算与实盘脱节。

**修法**：明确文档约定：`entry_price_hint` 必须是真实 fill 价；并且写一个 invariant test：`entry_fill_datetime == entry_ts` 或 `entry_fill_datetime > entry_ts`（不可能 < entry_ts）。

### M5. `risk_throttle.py` drawdown 区间边界开闭歧义
**文件**：`cta/portfolio_logic/risk_throttle.py:159`

`if float(level.drawdown_lo) <= dd < float(level.drawdown_hi)` — 半开区间。如果某个 level 配置 `(0.05, 0.10)`，dd 恰好 = 0.10 时**跳过**这一级。等于刚踩到 conservative 阈值就跳进 halt。

**修法**：把开闭区间在 dataclass 上显式写明，或在最后一级用 `<=` 上界包含。

### M6. `pyramid_manager.py` trailing stop 未防 NaN 污染 `effective_stop`
**文件**：`cta/portfolio_logic/pyramid_manager.py:32-36`

`effective_stop = max(hard_stop, trail_stop)`，如果 `trail_stop` 被外部 mutate 成 NaN，整条 exit 检查链路返回 NaN，所有比较短路成 False → 仓位永不出。

**修法**：初始值用 `float("-inf")`（long）/ `float("inf")`（short），赋值前 `if np.isfinite(value)` 守一道。

---

### M7. `trade_filter_model.py` 早停保护缺独立单测
**文件**：`cta/model/trade_filter_model.py:155-173`

刚加的 `min(pos, neg) < 2` → 关 early_stopping 的保护在 walk-forward 里被间接触发过，但没有显式 unit test 锁住"pos=1, neg=99 时 fit 不抛"这个 invariant。

**修法**：加 `test_fit_does_not_raise_when_one_class_has_single_sample`，构造 y=[1]+[0]*99 然后调 `model.fit(...)`，断言 `model_kind != "uninitialized"`。

---

### M8. `regime_classifier_model.py` 多分类极端不平衡时 RF 无 early_stopping 但仍可能 silently 退化
**文件**：`cta/model/regime_classifier_model.py:82-102`

虽然 `class_weight="balanced_subsample"` 处理了不平衡，但当某一类样本数 < `min_samples_leaf` 时该类无法形成叶节点，预测概率永远为 0。OOT regime gate 拒绝 `trend_down` 时，所有空头机会被丢。

**修法**：加 sample-count 警告日志；考虑当某类 <50 样本时把 `min_samples_leaf` 调到 max(2, min_count // 2)。
