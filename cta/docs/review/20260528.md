## §1 总体观感

### §1.1 优点（值得保留的设计）
- **sim ↔ live 共用入口**：`cta/live/live_runner.py:108` 把 `LiveRunConfig = SimRunConfig`，启动链复用
  `run_sim` → 翻译 vnpy 中文 key → connect → add_strategy → init/start，避免双份配置漂移。
- **gate 单一实现**：[`entry_gate_chain.py:27`](../../sim/adapters/entry_gate_chain.py) 直接调 OOT 的
  `apply_ma_cross_gate` / `apply_regime_short_filter` / `apply_trade_filter_gate`，sim 不再实现 gate
  逻辑，三层口径强一致（v2 §3.2 invariant）。
- **HTF gate 自动透传**：[`entry_gate_chain.py:107`](../../sim/adapters/entry_gate_chain.py) 通过
  `cfg.portfolio_logic.interval_gate` 构造 `HtfGate`，Action 3 的 `fallback_when_htf_missing_by_cluster_interval`
  自动生效（不需要 sim 侧改任何代码）。
- **状态机闭包**：[`order_lifecycle.py:40`](../../live/order_lifecycle.py) 显式列出 6 种 CTP 状态的合法转移表
  + traded_volume 单调校验，比 vnpy 默认 OrderData 更严格。
- **kill_switch 双路径激活**：[`kill_switch.py:33`](../../live/kill_switch.py) 内存 flag + 信号文件，运维
  `kill -HUP` / `touch /tmp/kill` 都能一键禁单。

### §3.3 P0-3 时区不一致：`TradeRecorder` 用 `datetime.utcnow()` 兜底

**问题**：[`cta/live/trade_recorder.py:40`](../../live/trade_recorder.py)
```python
"datetime": getattr(trade, "datetime", None) or datetime.utcnow(),
```

项目 invariant（[`timezone_helpers.py:12`](../../sim/timezone_helpers.py)）：sim/live 内部统一用
**naive Asia/Shanghai**。但当 vnpy `TradeData` 缺 datetime 字段时（异常路径 / 部分 gateway fake），

- `daily_parity_report` 拿 trade timestamp 与 backtest dates 做 ±1min 对账 → 8 小时偏移直接全部

**修复**：
```python
from cta.sim.timezone_helpers import ensure_naive_shanghai
...
"datetime": ensure_naive_shanghai(getattr(trade, "datetime", None) or pd.Timestamp.now()),
```
新增测试：缺 datetime 的 fake trade 落盘后，时间字段必须是 naive Asia/Shanghai。**工作量**：0.5 小时。

## §4 P1 — sim soak 启动门槛前修

### §4.1 P1-1 broker 对账只比"行数"不比"volume"

**问题**：[`live_runner.py:53`](../../live/live_runner.py)
```python
broker_counts[key] = broker_counts.get(key, 0) + 1
```
key = (symbol, exchange, direction)。**每条 row 计数 +1**，没看 `volume` 字段。

后果：broker 端持 5 手 RB long、本地 PortfolioState 持 1 手 RB long，但都只产生 `("RB", "SHFE", "long")`
一条 entry → counts 完全相等 → 对账通过 → 实盘启动后立刻爆仓。

**修复**：
```python
broker_lots[key] = broker_lots.get(key, 0) + float(row.get("volume", 0))
```
本地同理对 `pos.get("volume")` / `pos.get("lots")` 累加；比较 `abs(diff) < tolerance_lots`。
**测试**：补 1 条 lots 不等但 count 相等的对账 fail 用例。**工作量**：1 小时。

### §4.2 P1-2 风控规则非线程安全

**问题**：
- [`risk.py:140`](../../live/risk.py) `PortfolioThrottleRule._current_level` 状态字段，在 `check()`
  里读 + 改 + 写，**无 lock**；
- [`risk.py:115`](../../live/risk.py) `OrderRateLimit._stamps` deque pop + append，无 lock。

vnpy event-loop 单线程通常 OK，但 sim/live 里若有：
- 旁路 cron 定时触发 reload / drain（HotReloadableRegistry SIGHUP 在主线程，但 reload 时其他线程的
  request 仍走 RiskGuard），
- 多策略实例共享同一个 RiskGuard，

会出现 race condition → throttle level 跳变 / 速率限制漏拦。

**修复**：给 `PortfolioThrottleRule`、`OrderRateLimit` 各加 `threading.Lock`，evaluate 临界区加锁。
**测试**：用 100 线程并发 `check()`，断言 throttle level 单调（不能反向跳）。**工作量**：1 小时。

### §4.3 P1-3 `make_risk_filter` flat 无持仓时仍生成 close 订单

**问题**：[`risk.py:203`](../../live/risk.py)
```python
elif side == "flat":
    cur = float(getattr(adapter, "pos", 0.0) or 0.0)
    direction = "short" if cur > 0 else "long"   # cur=0 走到 else，生成 long.close
    offset = "close"
```

`cur == 0` 时还构造一个 risk_order 跑 RiskGuard → 多数规则 offset=close 直接通过，无影响；但
`PortfolioThrottleRule._current_level` 仍被 mutate（无 lock，见 P1-2），引入幽灵状态。

**修复**：`if abs(cur) < 1e-9: return True`（无持仓 flat 是 no-op，不走 guard）。**工作量**：5 min。

### §4.4 P1-4 `kill_switch.is_active` 每订单一次磁盘 IO

**问题**：[`kill_switch.py:38`](../../live/kill_switch.py)
```python
if self.signal_file and Path(self.signal_file).exists():
    content = Path(self.signal_file).read_text(...)
```

`KillSwitchRule.check` 在 `RiskGuard.evaluate` 短路链最前；若开仓密集（分钟级 batch），每订单都
触发两次 `Path.exists()` + 一次 `read_text()`。NFS / 容器只读卷上 stat 延迟 ~10 ms → 单订单加 20 ms。

**修复**：缓存 mtime + 内容；mtime 没变就用缓存。`is_active()` 实现：
```python
st = self.signal_file.stat()
if (st.st_mtime, st.st_size) == self._cached_key:
    return True, self._cached_reason
...
```
**工作量**：30 min。

### §4.5 P1-5 WebhookAlerter 同步 urlopen 阻塞主线程

**问题**：[`monitoring.py:165`](../../live/monitoring.py)
```python
urllib.request.urlopen(req, timeout=float(self.timeout_seconds)).close()
```
`timeout=3s`，最坏情况主线程卡 3s × 重试次数。告警风暴下连锁阻塞 vnpy event-loop。

**修复**：内部用 `queue.Queue` + 单 daemon 线程串行发送；调用方 `put_nowait`。
**测试**：注入慢 fake http_get，主线程 send() 返回 <10 ms。**工作量**：1 小时。

### §4.7 P1-7 silent drop：rotation_order_wire 无日志

**问题**：[`rotation_order_wire.py:117–120`](../../sim/adapters/rotation_order_wire.py)
- `cfg.only_trade_matching_vt_symbol and strategy_symbol != symbol → continue` （silent）
- `not (math.isfinite(price) and price > 0) → continue` （silent）

### §4.8 P1-8 PositionEvaluator state_provider=None 时静默用中性值

**问题**：[`position_evaluator.py:100`](../../sim/adapters/position_evaluator.py)

## §8 不变量（新增 3 条）

承接 v2 §7 已有 10 条，本次 review 加 3 条 sim/live 专属：

11. **sim/live trade record 时间字段必须是 naive Asia/Shanghai**（不允许 UTC、不允许 aware tz）。
    防回归：`ensure_naive_shanghai` 包裹所有 `getattr(trade, "datetime", ...)`。

    sim 主流程缺这个 dump 调用就 fail。
13. **broker reconciliation 按 lots/volume 比较，不允许只比 count**。`live_runner._reconcile_or_raise`
    及其单测必须显式覆盖"counts 相等但 volume 不等"反例。
