## Findings（按严重级别）

### [P0] whitelist 模式 generic 列回归超限（18 -> 20）
- 现象：`test_pipeline_whitelist_mode_caps_generic_at_18_columns` 失败，断言 `<=18`，实际 `20`。
- 证据：
  - [cta/model/tests/test_model_pipeline_part06.py](/Users/wuyuliang/code/vnpy/cta/model/tests/test_model_pipeline_part06.py:88)
  - [cta/model/dataset/pipeline_feature_enrichment.py](/Users/wuyuliang/code/vnpy/cta/model/dataset/pipeline_feature_enrichment.py:103)
  - [cta/model/dataset/pipeline_feature_enrichment.py](/Users/wuyuliang/code/vnpy/cta/model/dataset/pipeline_feature_enrichment.py:104)
- 根因：`generic_model_cluster_breadth_up`、`generic_model_cluster_momentum_rank` 无条件追加，绕过了 whitelist 18 列约束。
- 建议修复：
  1. 仅在 `generic_mode=auto` 或 `force_generic_fallback=True` 时追加这两个列；
  2. 或改名前缀（非 `generic_`）并在下游显式白名单使用。

### [P0] final long/short 模型缺失 `*_features.csv` manifest
- 现象：`test_pipeline_writes_feature_manifest_per_saved_model` 失败；`final_decision_stack_long.joblib` / `short.joblib` 旁没有同名特征清单。
- 证据：
  - [cta/model/tests/test_model_pipeline_part06.py](/Users/wuyuliang/code/vnpy/cta/model/tests/test_model_pipeline_part06.py:160)
  - 保存 long/short 模型： [cta/model/orchestration/pipeline_run.py](/Users/wuyuliang/code/vnpy/cta/model/orchestration/pipeline_run.py:268)
  - 仅写了 base final manifest： [cta/model/orchestration/pipeline_run.py](/Users/wuyuliang/code/vnpy/cta/model/orchestration/pipeline_run.py:296)
- 根因：`final_model_long` / `final_model_short` 已保存，但未调用 `_dump_feature_manifest`。
- 建议修复：
  1. 为 `final_long_joblib`、`final_short_joblib` 分别补齐 manifest；
  2. `model_kind` 建议区分 `final_decision_stack_long` / `final_decision_stack_short`，避免部署侧混淆。

### [P1] vn.py adapter 下单失败后仍更新本地持仓，可能与真实仓位漂移
- 证据：
  - 下单异常被吞并仅记录日志： [cta/strategy/vnpy_adapters/baseline_strategy.py](/Users/wuyuliang/code/vnpy/cta/strategy/vnpy_adapters/baseline_strategy.py:294)
  - 之后仍直接改 `self.pos`： [cta/strategy/vnpy_adapters/baseline_strategy.py](/Users/wuyuliang/code/vnpy/cta/strategy/vnpy_adapters/baseline_strategy.py:308)
- 风险：网关拒单/异常时，策略内部 `pos` 与账户真实持仓不一致，后续止损/平仓决策会偏离。
- 建议修复：
  1. `_record_and_send` 返回成功/失败；
  2. 只有成功后才调整 `self.pos`；
  3. 中期建议以 `on_trade` 回报作为仓位真值。

### [P1] CLI 批量模式吞异常后继续运行，可能“全失败但进程成功退出”
- 证据：
  - group-pool 异常后 `continue`： [cta/model/orchestration/pipeline_cli.py](/Users/wuyuliang/code/vnpy/cta/model/orchestration/pipeline_cli.py:261)
  - pool 异常后 `continue`： [cta/model/orchestration/pipeline_cli.py](/Users/wuyuliang/code/vnpy/cta/model/orchestration/pipeline_cli.py:310)
- 风险：CI/批跑脚本看到退出码 0，误以为本次训练成功。
- 建议修复：
  1. 增加 `--strict-fail-fast`（默认 true 更稳）；
  2. 至少在“0 个 interval/group 成功”时抛 `RuntimeError`。

### [P2] 测试 warnings 量较大，建议做“告警预算”治理
- 现象：本次全量测试 warnings `1934`（主要是 sklearn deprecation/convergence/runtime）。
- 风险：真实回归信号被噪音淹没，后续定位成本高。
- 建议修复：
  1. 先清 `FutureWarning: LogisticRegression penalty`；
  2. 对可预期 warnings 用精准过滤；
  3. 为 pipeline 加 `warnings budget`，超过阈值直接失败。
