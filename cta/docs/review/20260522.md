## §3 Findings

### §3.1 Critical（C）

#### C1 — training pipeline 强制 enable rotation，违反默认 off

**位置**：[pipeline_dataset_prep.py:367-371](../../model/dataset/pipeline_dataset_prep.py)

```python
rotation_cfg = CrossSectionalRotationConfig(
    use_cross_sectional_momentum_rotation=True,        # 硬编码 True
    long_only_mode=(mode == "long"),
    enabled_by_cluster_interval={"*|day": True},        # 硬编码全 cluster opt-in
)
```

**问题**：用户 `OotEvaluationConfig` / `PortfolioLogicConfig` 即便不开 rotation，
day-level pool 训练也会调用 `_build_pool_cross_sectional_candidate_table` 并
强制产生 rotation 候选合并进训练样本。

**证据**：[test_pool_training.py](../../model/tests/test_pool_training.py) 把两处
既有测试的 `interval="day"` 改成了 `"60min"` 来**规避**新副作用，而非修正预期；
这是典型"测试为产品 bug 让路"的反模式。

**影响**：
- 训练集分布偏移：day-level 所有 pool 任务都额外多出 cross_sectional_momentum 样本
- 与设计文档 §13 不变量"默认 off 时行为完全不变"直接冲突
- 跟[20260521.md](./20260521.md) H3 / C1-r 同类型 bug（"功能默认 True 即便用户没显式开"）

**修复方向**：
1. 把 `rotation_cfg` 改为接受外部 cfg：从调用方（`_build_pooled_feature_df`）传入
   `PortfolioLogicConfig.cross_sectional_rotation`
2. 在 `_build_pool_cross_sectional_candidate_table` 内首先检查 `cfg.use_cross_sectional_momentum_rotation`，未启用直接 return empty
3. 恢复 `test_pool_training.py` 两处 `"60min"` → `"day"`，不应通过修改测试规避产品 bug

**优先级**：P0（必须修，影响所有 day-level 训练 run）

#### H3 — 执行器 NaN target_weight 未过滤

**位置**：[cross_sectional_rotation_executor.py:92-94](../../portfolio_logic/cross_sectional_rotation_executor.py)

```python
target_weight = float(row.get("target_weight", 0.0) or 0.0)  # NaN 是真值 → 不会 fallback 到 0
target_notional = abs(target_weight) * float(portfolio_state.equity)  # NaN * X = NaN
if not symbol or target_notional <= 0.0:                              # NaN <= 0 → False
    continue                                                           # 不会跳过
```

**问题**：`or 0.0` 短路只在 `target_weight` 为 falsy（0 / None / ""）时才生效；
`float('nan')` 在 Python 中是 **truthy**，不会被 `or` 替换。NaN 会一路传到
`RotationOrderIntent.target_notional`，下游 sim/live 拿到 NaN 名义会爆。

**验证**：

```python
>>> import math
>>> math.nan or 0.0
nan
>>> math.nan <= 0.0
False
```

**修复方向**：

```python
import math
target_weight = float(row.get("target_weight", 0.0) or 0.0)
if not math.isfinite(target_weight):
    continue
target_notional = abs(target_weight) * float(portfolio_state.equity)
if not symbol or target_notional <= 0.0:
    continue
```

**优先级**：P0（生产风险：NaN intent 进下游会引发不可预期的下单行为）

#### H4 — `trade_filter_bypass_signal_types` 默认含 rotation 信号，但 rotation 默认 off

**位置**：[model_oot_eval_config.py:80](../../config/model_oot_eval_config.py)

```python
trade_filter_bypass_signal_types: tuple[str, ...] = ("cross_sectional_momentum",)
```

**问题**：即使 rotation 默认 off（用户未启用），OOT trade-filter gate 内部仍把
`signal_type=="cross_sectional_momentum"` 的行视为"无条件通过"。

**当前实际风险**：
- 当 rotation off 时，不会产生 `signal_type=="cross_sectional_momentum"` 的行 → 无副作用
- **但是** 任何测试 / 调试代码若手动构造该 signal_type 的样本，会触发默认 bypass，
  而用户从未明确同意

**与 C1 的关系**：C1 让 day-level pool 在默认配置下产生 rotation 样本；H4 让
OOT 对这些样本的 trade-filter 默认放行。两个 default-on 行为叠加 → rotation
功能其实是"默认开启"的，违反整体设计意图。

**修复方向**：
- 选项 A（推荐）：默认 `trade_filter_bypass_signal_types = ()`，由用户显式 opt-in
- 选项 B：bypass 触发同时要求 `cfg.use_cross_sectional_momentum_rotation`（与 C1 fix 配套）

**优先级**：P0（与 C1 配套修复）

### §3.3 Medium（M）

#### M1 — 执行器每个 step 都调用 `universe_provider`

**位置**：[cross_sectional_rotation_executor.py:70](../../portfolio_logic/cross_sectional_rotation_executor.py)

```python
def step(self, t, portfolio_state):
    as_of = pd.Timestamp(t)
    universe_bars = self.universe_provider(as_of)  # 每个 step 都跑
    ...
    candidates = self.rotation.generate_rebalance_candidates(...)
    if candidates.empty: return []
```

**问题**：`universe_provider` 在每个 bar 都被调用一次（不仅 rebalance 日）。
对 50 品种 day 数据 × 252 交易日 = 12 600 次 load，其中 ~85% 是非 rebalance 日，
完全是无效 IO。

**修复方向**：把 rebalance-day 判定提前：

```python
def step(self, t, portfolio_state):
    as_of = pd.Timestamp(t)
    if not _is_rebalance_day(as_of, ...):
        return []
    universe_bars = self.universe_provider(as_of)
    ...
```

但这会要求 `_is_rebalance_day` 成为公共 API（与 H2 一致）。

**优先级**：P2（性能，非正确性）

#### M4 — 执行器 `last_rebalance_dt` 在空 intent 时不更新（语义模糊）

**位置**：[cross_sectional_rotation_executor.py:85-88](../../portfolio_logic/cross_sectional_rotation_executor.py)

```python
candidates = self.rotation.generate_rebalance_candidates(...)
if candidates.empty:
    return []                              # 早返回，last_rebalance_dt 不更新

self.last_rebalance_dt = as_of             # 只在有候选时更新
```

**问题**：rebalance 日 universe 为空（例如所有品种被 disable）→ candidates.empty → last_rebalance_dt 不更新 → 第二天再次触发 rebalance 判定（因为上次没 update）。这与设计意图（"已经到 rebalance 日，无论是否真的下单都消耗一次 cadence"）不一致。

**修复方向**：把 `last_rebalance_dt = as_of` 提到 `if not _is_rebalance_day(): return []` 之后、`if candidates.empty:` 之前。

**优先级**：P2

## §8 总结

### §8.1 整体质量

**P0/P1（claude）**：高质量。dataclass 校验 / 默认 off / TDD 全套测试 / 类型注解齐全 /
500 行规范。可作为后续策略落地的样板。

**P2 最小接入（codex）**：**有 3 个 critical / high 等级 bug**：
- C1: training pipeline 强制 enable rotation
- H3: NaN target_weight 透传
- H4: bypass 默认含 rotation 信号

修复成本不高（每个 < 30 行 diff），但**必须在合并 / 上线前修完**，否则
"默认 off"承诺无法兑现，且 NaN 会引起下游 sim/live 异常。

### §8.2 不要回退方向

[mean_reversion_voi_regime_adaptive_design.md](../mean_reversion_voi_regime_adaptive_design.md) 2026-05-22 已被 codex 回退，
本设计有同样风险：**如果 C1/H3/H4 不修，下一轮 OOT 出现异常时，rotation 会成为
首个被回退的功能**。建议这 3 个 P0 在合入主分支前必修。

### §8.3 下一步建议

1. 立即修复 §6.1 的 3 个 P0
2. 然后继续 P2 完整接入：把 `RotationOrderIntent` 串到 portfolio cap / sim / live
3. 等 P2 完整接入后再考虑生产灰度（设计 §10 滚动启用日历）
