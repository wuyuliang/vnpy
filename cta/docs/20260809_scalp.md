## 1. 目标、强制指标与非目标

### 1.1 目标

构建一个可由 vn.py 驱动、离线和在线共用同一状态机的 Brooks 日内剥头皮策略：

1. 只在明确市场环境中交易，紧区间和结构不清晰时保持空仓。
2. 使用 30 分钟背景、5 分钟 setup 和 1 分钟 stop-entry，避免在 setup bar 内偷看成交。
3. 使用固定的小风险、快速失败退出和 session 强平控制尾部风险。
4. RB、CU 先独立验证，组合结果不能掩盖单品种失败。
5. 扩展新品种时只增加合约元数据和数据映射，不允许为单品种重新拟合价格行为阈值。

### 1.2 指标的唯一口径

以下指标一律在扣除手续费、平今费、滑点和资金约束后的完整 round-trip 上计算：

```text
is_win = net_pnl > 0
win_rate = count(is_win) / count(all_closed_round_trips)

avg_win = mean(net_pnl where net_pnl > 0)
avg_loss = abs(mean(net_pnl where net_pnl < 0))
payoff_ratio = avg_win / avg_loss

daily_return_t = equity_close_t / equity_close_t-1 - 1
average_daily_return = mean(daily_return_t over every trade date,
                            including zero-trade dates)

monthly_return_m = month_end_equity_m / prior_month_end_equity - 1
average_monthly_return = mean(monthly_return_m)
```

`net_pnl == 0` 的 scratch 交易计入胜率分母但不计为盈利；它不进入 `avg_win` 或
`avg_loss`。若没有盈利交易或没有亏损交易，`payoff_ratio` 不得伪造为无穷大或零，状态为
`UNDEFINED`，整个分组记为 `INCONCLUSIVE`。

强制指标：

| 指标 | 要求 | 失败状态 |
| --- | ---: | --- |
| 每个 `symbol × 三种 setup × 多空方向` 锁定评估样本 | 至少 100 笔 | `INCONCLUSIVE` |
| 上述全部六个分组的净胜率 | `>=80%` | `REJECTED` |
| 每个品种总体净胜率 | `>=80%` | `REJECTED` |
| 组合总体净胜率 | `>=80%` | `REJECTED` |
| 上述全部六个分组的净平均盈亏比 | `1.02~1.20`，含边界 | `REJECTED` |
| 每个品种及组合 `RiskScore` | `>=90/100` | `REJECTED` |
| 任一风险一票否决项 | 不得触发 | `REJECTED` |

收益目标：

| 指标 | 目标 | 失败状态 |
| --- | ---: | --- |
| 每个品种独立账户日均净收益 | `>=1%` | `TARGET_MISSED` |
| RB+CU 共享账户日均净收益 | `>=1%` | `TARGET_MISSED` |
| 每个品种独立账户平均月收益 | `>=20%` | `TARGET_MISSED` |
| RB+CU 共享账户平均月收益 | `>=20%` | `TARGET_MISSED` |

最终只有全部强制指标和收益目标都通过，才可标记 `RESEARCH_ACCEPTED`。这仍然只代表历史
研究通过，不代表实盘收益保证。

### 1.3 数学可行性审计

在胜率 80%时，净平均盈亏比为 1.02 和 1.20 对应的每笔期望分别为：

```text
expectancy_low_R  = 0.80 * 1.02 - 0.20 = 0.616R
expectancy_high_R = 0.80 * 1.20 - 0.20 = 0.760R
```

每笔计划风险为账户权益 0.25%时，理论每笔期望约为 `0.154%~0.190%`。在交易近似独立、
每笔都使用完整风险预算且上述净指标真实成立的理想条件下，日均 1%仍需要约 5.3 至 6.5
笔交易。实际还会遇到取整、无信号、风险缩放和停机，因此报告必须同时列出每天候选数、
有效交易数和风险利用率。不得通过提高单笔风险来掩盖信号频率不足。

若日均 1%持续 252 个交易日，理论复利年收益约为 `+1127%`。这是极高研究目标，不是合理
默认预期，也不能作为参数搜索的损失函数。

### 1.4 非目标

- 不做隔夜或跨 session 趋势持仓。
- 不做加仓摊薄亏损、马丁格尔、网格或亏损后加倍。
- 不做基于盘口队列的高频交易；只有分钟 OHLCV 时不模拟毫秒级排队优势。
- 不使用固定 20 万元名义敞口；20 万元是账户权益，仓位必须按风险计算。
- 不为达到 80%胜率而删除 scratch、滑点较差或换月附近的真实交易。
- 不把 RB、CU 的阈值优化后直接宣称适用于所有期货。
- 不在本文件中承诺上线实盘；上线前还需 paper trading 和经纪商成交核验。

## 2. 设计依据

Al Brooks 的价格行为框架强调市场在趋势与交易区间之间循环，高概率与高盈亏比通常需要
交换。在大部分时段，交易概率并不接近 80%；强突破等少数背景才可能提高概率。因此本
策略通过“少交易、硬过滤、允许零交易”追求高质量，而不是把所有形态都转成订单。

首版只实现以下原则：

1. 强趋势中优先顺势二次入场和强突破跟进。
2. 宽幅交易区间中只在上下三分之一区域做失败突破反转。
3. 紧区间和 Barb Wire 不交易，等待方向和 follow-through。
4. 使用 stop-entry，不在信号 bar 内假设提前成交。
5. 剥头皮失败应很快显现，缺少 follow-through 时快速退出。
6. 不 scale in，不把宽止损和补仓产生的表面高胜率带入自动策略。

## 4. 数据契约

### 4.1 统一分钟 bar

所有输入最终归一为：

```text
source_calendar_date, exchange_trade_date, session_id, bar_start, bar_end,
root_symbol, vt_symbol, contract_code, exchange,
open, high, low, close, volume, turnover, open_interest,
pre_settlement, limit_up, limit_down, limit_source, limit_known_at,
source_path, source_row
```

要求：

- `bar_start`、`bar_end` 是 Asia/Shanghai 时区感知时间。
- `bar_end` 表示该 bar 完整可用时间；所有特征的 `feature_asof` 必须等于或早于它。
- `source_calendar_date` 是源文件的自然日，`exchange_trade_date` 是交易所日历映射后的交易日。
- `contract_code` 必须是真实可交易合约，不得只保留 `RB0`、`CU0`。
- OHLC 必须有限且为正，满足 `low <= min(open, close) <= max(open, close) <= high`。
- `volume/turnover/open_interest >= 0`；缺失值不得向后填充。
- `(contract_code, bar_end)` 唯一且严格升序。

### 4.2 本地 RB 与 CU 的已知差异

RB 当前原始 schema：

```text
datetime, open, high, low, close, volume, open_interest,
turnover, ts_code, symbol, exchange
```

CU 当前原始 schema：

```text
trade_time, open, high, low, close, vol, amount, oi,
trade_date, ts_code, raw_symbol, mapping_symbol, contract_code, freq
```

适配器固定映射：

```text
CU.trade_time -> bar timestamp candidate
CU.trade_date -> source_calendar_date，不能直接当 exchange_trade_date
CU.vol        -> volume
CU.amount     -> turnover
CU.oi         -> open_interest
CU.contract_code, fallback CU.ts_code -> contract_code

RB.datetime   -> bar timestamp candidate
RB.ts_code    -> contract_code
```

CU 数据存在 `00:00` 等夜盘时间，源 `trade_date` 实际只作自然日校验字段。
`exchange_trade_date` 必须由版本化 SHFE 交易日历重建：夜盘映射到该夜盘之后的第一个
SHFE 交易日，因此周五夜盘可映射到周一；日盘自然日必须本身是交易日。
日历版本和每条映射的 `calendar_sha256` 进入审计文件。无法唯一解释时立即失败，
不得静默平移时间。

本地少数早期文件额外包含恰好位于 `09:00/10:30/13:30/21:00` 的 segment 开盘快照；这些
时间点不能按 `bar_end` 解释为完整 1m bar。研究流水线只删除“恰好等于已声明 segment
start”的快照，并把逐 symbol 删除数写入 `source_audit.json`；其他 session 外时间仍立即失败，
不得泛化为静默清洗。

### 4.3 InstrumentSpec

每个品种必须按生效日期提供版本化元数据：

```python
@dataclass(frozen=True)
class InstrumentSpec:
    root_symbol: str
    exchange: str
    contract_size: float
    price_tick: float
    lot_step: int
    slippage_ticks_base: float
    sessions: tuple[SessionSpec, ...]
    effective_from: date
    effective_to: date | None
```

费用和保证金独立按生效时间版本化：

```python
@dataclass(frozen=True)
class FeeMarginSpec:
    schedule_id: str
    root_symbol: str
    contract_code: str | None
    margin_rate_long: float
    margin_rate_short: float
    open_fee_rate: float
    close_fee_rate: float
    close_today_fee_rate: float
    fee_per_lot_open: float
    fee_per_lot_close: float
    fee_per_lot_close_today: float
    effective_from: datetime
    effective_to: datetime | None
    source: str
    known_at: datetime
```

按成交额和按手收费允许同时存在，实际费用取交所/经纪商规则计算结果之和。

每个合约交易日还必须关联：

```python
@dataclass(frozen=True)
class DailyTradingSpec:
    contract_code: str
    exchange_trade_date: date
    pre_settlement: float
    limit_up: float
    limit_down: float
    fee_margin_schedule_id: str
    source: str
    known_at: datetime
```

`known_at` 必须不晚于该交易日第一个 session 开始。只有涨跌停比例而没有昨结算价
和当日实际上下限时，当日禁止新仓；不得用昨收盘代替昨结算。

字段契约：

```text

```

权威性和回补顺序固定为：

1. SHFE 官方交易日历、每日结算数据、限价/保证金通知和合约规则是 RB/CU 研究的
   主来源；实盘费率和保证金加收以经纪商结算单/版本化费率表为准。
2. 仓库现有 `cta/data_code/futures_downloader.py` 的 Tushare `fut_daily/fut_mapping` 只作 staging
   和交叉校验。导入器必须从 raw `fut_daily` 保留 `pre_settle/settle`，不能使用当前会
   丢弃该字段的归一化表代替权威数据。
3. 若官方文件只提供昨结算和生效限价比例，可按当日 SHFE 合约取整规则派生
   `limit_up/limit_down`，但必须保存 `limit_rounding_rule` 和派生输入。
4. 禁止用当前费率/保证金覆盖全历史，禁止跨生效时间缺口向前或向后填充。

RB/CU 当前元数据由以下命令可复现生成：

```bash
python3 -m cta.strategy.brooks.scalp.shfe_metadata_builder \
  --start 2018-01-03 \
  --end 2026-04-16 \
  --data-root cta/data/origin/minute \
  --output-root cta/strategy/brooks/scalp/meta \
  --cache-root /private/tmp/vnpy_shfe_scalp_metadata \
  --workers 8
```

构建器按上一开市日 SHFE `js` 参数生成下一交易日费率/保证金，按 SHFE 规则从投机保证金率
派生限价比例，并用官方 `kx` 当日最高/最低价反向校验派生上下限。`manifest.json` 之外还生成
`shfe_source_audit.jsonl.gz` 和 `build_summary.json`，保存 4,070 个官方源文件的 URL、日期和
SHA-256。

夜盘可用性不是用“存在一行数据”判断。RB 必须完整覆盖 `21:00-23:00`；CU 必须同时覆盖
`21:00-23:59` 和 `00:00-01:00`。每段需覆盖首尾、至少有正成交量，且任意相邻记录最多
缺 2 根 1m bar。源数据不满足时 `night_session_start` 留空，表示“本地数据不足以回测完整
夜盘”，不是断言交易所当日没有夜盘。连续主力源若在同一 session 内切换实际合约，该
session 在 RB+CU 组合及两个独立对照中同步排除，并写入 `source_audit.json`。

当前 `fee_margin_schedule.csv` 保存 SHFE 交易所标准费率和保证金，不含期货公司加收。接入
paper/live 前必须导入版本化经纪商结算单或费率表重新验证；禁止把本次研究成本误称为真实
账户最终成本。

扩展到 DCE、CZCE、CFFEX、INE 或 GFEX 时，必须换成对应交易所官方来源，但仍产出同一
canonical schema；不允许用 SHFE 日历、限价或费率规则推断其他交易所。

`metadata_importer.py` 只接受保存了来源 URL/文件名、下载时间、数据覆盖区间和 SHA-256
的输入。`manifest.json` 对四个 CSV 逐个记录行数、最小/最大日期和哈希。任一回测日
缺少对应真实合约的 `InstrumentSpec + DailyTradingSpec + FeeMarginSpec`，本次运行整体输出
`BLOCKED_METADATA`，不生成全零交易的绩效报告。

### 4.5 session 与 trade date

`SessionCalendar` 必须显式保存每个品种的夜盘和日盘区间，禁止用固定小时推断所有品种。
每个 session 由一个或多个连续 `SessionSegment(start, end, bucket_anchor)` 组成，例如日盘
`09:00-10:15`、`10:30-11:30`、`13:30-15:00`是三个 segment。
一个 session 内独立维护候选、订单、持仓、盈亏和停机状态：

```text
session_open
no_new_entry_after = session_close - 15 minutes
force_flat_at      = session_close - 5 minutes
session_close
```

夜盘属于交易所定义的下一 trade date，但仍是独立 session。午间休市不得把 5m 或 30m bar
跨休市拼接。缺失 session 尾部 bar 时，在最后可用 bar 立即发出保守强平；若无法成交，记录
`forced_flat_failed` 并触发风险一票否决。

### 4.6 5m/30m 因果聚合

每个 session 从 session 起点单独分桶：

```text
open   = first(open)
high   = max(high)
low    = min(low)
close  = last(close)
volume = sum(volume)
turnover = sum(turnover)
open_interest = last(open_interest)
source_max_bar_end = max(1m.bar_end)
```

只发布完整分桶。30m/5m 特征仅在聚合 bar 的 `bar_end` 后可用，不能把未完成周期实时值写成
历史完整值。所有信号行必须保存 `source_max_bar_end <= feature_asof < first_eligible_entry_bar`。

分桶每个 segment 独立从 `bucket_anchor` 重新计数，不跨休市：

- 5m 只发布包含 5 根连续合法 1m bar 的分桶。
- 30m 只发布包含 30 根连续合法 1m bar 的分桶。
- segment 尾部不足 30 分钟的数据仍参与 5m setup，但不发布缩短 30m bar，不更新 regime。
- 下一 segment 从新 anchor 开始；不得将 `10:00-10:15` 与 `10:30-10:45` 拼成一根 30m bar。

测试必须固定校验 `10:15`、`10:30`、`11:30`、`13:30` 和夜盘跨日边界的期望 bar end。

### 4.7 换月和真实合约

- 信号、订单、成交和盈亏都绑定 `contract_code`。
- 不允许通过未完成 session 的成交量/OI “预知”下一主力合约。
- 预计算主力映射必须保存 `mapping_contract`、`effective_session`、`decision_asof`、`source`，且
  `decision_asof <= effective_session.session_open`。
- 对当前本地连续合约文件，允许用 session 第一根 1m bar 的真实 `contract_code`
  确定当前合约；此时 `decision_asof` 明确等于第一根 `bar_end=session_open+1m`，该时刻之前
  禁止产生候选或订单。该 session 若相比上一 session 发生切换，整个 session 保持换月冻结并重新预热。
- session 内 `contract_code` 再次变化属于数据错误，立即 fail-closed。
- 合约切换后清空 1m/5m/30m滚动状态，使用新合约独立预热，不跨跳点计算 ATR 或形态。
- 连续合约可用于长期展示，不能用于成交价、手续费、保证金或止损判断。
- 发现合约切换的当前 session 及后续未完成预热的 session 输出 `roll_freeze=true`
  及拒绝原因；不得为了标记“换月前”而查看未来映射。

### 4.8 数据失败关闭

以下任一情况立即失败：

- 重复或乱序 bar。
- 非法 OHLC、负量、未知合约或元数据缺口。
- 时区、bar 起止语义或夜盘 trade date 无法确定。
- 交易日日历缺失，或 `DailyTradingSpec/FeeMarginSpec.known_at` 晚于对应规则生效时刻。
- session 内缺口超过 2 根连续 1m bar。
- 5m/30m source 时间晚于 feature 时间。
- 主力合约变化但没有换月冻结记录。
- 预计算合约映射缺少 `decision_asof` 或其晚于生效 session 开始。
- 历史文件在同一 run 内发生 SHA-256 变化。

`pa_scalp_score`、`setup_quality_score`、`context_score` 等加权综合分只记录诊断，不参与入场。
突破字段在启用前必须通过多空镜像和前缀不变性测试；若现有定义不满足
本文件语义，在 `scalp/setups.py` 中实现局部确定性 detector，不修改旧 v3 行为。

以下现有字段禁止直接参与本策略信号：

- `pa_trading_range_20` 内部对整列 `range_pct` 做百分位排名，追加未来数据可能改变历史值。
- `pa_range_over_atr_20` 的 ATR 初始化方式与第 6.2 节冻结定义不同。
- `pa_pullback_depth_20` 是从滚动高点向下计算，不能直接镜像为空头回撤。
- `pa_bo_vol_ratio_20` 只在 20 根突破时输出实际量比，不能替代 10 根突破的独立量能条件。
- `pa_h123`、`pa_l123`、`pa_second_entry` 和 `pa_two_leg_pullback` 没有跟踪第一次尝试是否触发并失败，
  只允许作为诊断列，不得代替第 8.1 节的状态机。

在 `scalp/features.py` 中仅用截至当前完整 bar 的数据计算以下局部字段：

```text
range_high_20 = max(high_i, i = t-19 ... t)
range_low_20 = min(low_i, i = t-19 ... t)
causal_range_over_atr_20 = (range_high_20 - range_low_20) / frozen_atr_14

bar_direction_t = sign(close_t - open_t)
direction_change_ratio_20 =
    count(bar_direction_i * bar_direction_i-1 < 0, i=t-18..t) / 19

pullback_depth_long_20 =
    (range_high_20 - close_t) / (range_high_20 - range_low_20)
pullback_depth_short_20 =
    (close_t - range_low_20) / (range_high_20 - range_low_20)

volume_ratio_prev20_t = volume_t / mean(volume_i, i = t-20 ... t-1)
```

区间符号在上式中包含左右端标出的历史 bar，不含任何未来 bar；分母为 0、样本不足或非有限时
返回 `UNAVAILABLE`，不得填默认值放行交易。

### 6.2 Wilder ATR14

TR 定义为：

```text
TR_t = max(high_t - low_t,
           abs(high_t - close_t-1),
           abs(low_t - close_t-1))
```

第 14 个 ATR 使用最初 14 个 TR 的算术平均作为种子，之后递推：

```text
ATR_t = (13 * ATR_t-1 + TR_t) / 14
```

ATR 未形成、非有限或不大于 0 时不生成状态和 setup。本策略中名为 `atr_14`
的字段一律指这个局部冻结实现，不得从旧特征表同名列透传。

### 6.3 EMA20/EMA60

EMA 固定使用 `adjust=False` 递推，首根完整 bar 的 close 为种子：

```text
alpha_N = 2 / (N + 1)
EMA_N,t = alpha_N * close_t + (1 - alpha_N) * EMA_N,t-1
```

即使数值已经形成，也必须完成第 5 节规定的周期预热后才可用于信号。

## 7. 30分钟市场状态

`RegimeState` 取值：

```text
STRONG_TREND_UP
STRONG_TREND_DOWN
WIDE_TRADING_RANGE
TIGHT_RANGE_BREAKOUT_MODE
CLIMAX_TRANSITION
UNAVAILABLE
```

每次分类产生不可变快照：

```python
@dataclass(frozen=True)
class RegimeSnapshot:
    state: RegimeState
    direction: Literal[1, -1, 0]
    feature_asof: datetime
    range_high: float
    range_low: float
    range_mid: float
    source_contract: str
```

`range_high/range_low` 始终取分类 bar 之前 20 根完整 30m bar 的最高/最低，`range_mid` 是二者
中点。即使后续 5m bar 创出新高低，在下一次完整 30m 分类前，当前 setup 仍引用该快照，不得
在 5m 层重算另一套区间。

状态优先级固定为 `UNAVAILABLE -> CLIMAX -> TIGHT_RANGE -> STRONG_TREND -> WIDE_RANGE`。

### 7.1 强趋势

多头强趋势同时满足：

```text
pa_always_in_dir >= 0.10
pa_trend_strength_20 >= 3.0
pa_ema_slope_20 > 0
ema_20 > ema_60
close > ema_20
pa_trend_bar_net >= 0.15
pa_overlap_ratio_20 <= 0.65
pa_buy_climax == 0
```

空头强趋势必须明确同时满足：

```text
pa_always_in_dir <= -0.10
pa_trend_strength_20 <= -3.0
pa_ema_slope_20 < 0
ema_20 < ema_60
close < ema_20
pa_trend_bar_net <= -0.15
pa_overlap_ratio_20 <= 0.65
pa_sell_climax == 0
```

### 7.2 宽幅交易区间

同时满足：

```text
direction_change_ratio_20 >= 0.50
pa_overlap_ratio_20 >= 0.55
causal_range_over_atr_20 >= 4.0
abs(pa_always_in_dir) < 0.10
abs(pa_trend_strength_20) <= 15.0
pa_barb_wire == 0
```

区间上下边界使用 `RegimeSnapshot` 的最高和最低，当前分类 bar 不参与边界计算。区间高度
不足以容纳 `1.20R + 双边压力成本` 时不得交易。

### 7.3 紧区间和 breakout mode

任一满足：

```text
pa_barb_wire == 1
or (pa_overlap_ratio_10 >= 0.75 and causal_range_over_atr_20 < 4.0)
or 最近10根30m bar区间高度 < 2.2 * atr_14
```

该状态不允许 range fade，也不立即追第一根突破；只允许第 8.2 节的强突破 follow-through。

### 7.4 高潮和转换

任一满足：

```text
pa_buy_climax == 1
or pa_sell_climax == 1
or pa_momentum_decay >= 1.0
or 30m主力合约刚切换且预热未完成
```

状态为 `CLIMAX_TRANSITION`，禁止新仓。连续 2 根完整 30m bar 不再满足后，才重新分类。
`pa_momentum_decay` 正值表示实体递减；负值是实体增强，不能用 `abs()` 当作动能衰减。

### 8.1 `second_entry_continuation`

该规则不得直接读取旧 `pa_h123/pa_l123/pa_second_entry/pa_two_leg_pullback`。每个 symbol 在
5m 层维护以下状态：

```text
IDLE
PULLBACK_LEG_1
FIRST_SIGNAL_ARMED
FIRST_ATTEMPT_FAILED
PULLBACK_LEG_2
SECOND_ENTRY_READY
```

做多状态转换固定为：

1. `STRONG_TREND_UP` 中，最近 3 根5m bar 至少 2 根阳线且净上涨 `>=0.50*atr_14`，记为
   impulse；其后第一根阴线或低点下移 bar 进入 `PULLBACK_LEG_1`。
2. 第一根满足本节 signal-bar 质量条件的多头反转 bar 形成影子 H1，保存
   `first_trigger=high+1tick`、`first_stop=low-1tick`，进入 `FIRST_SIGNAL_ARMED`；影子 H1
   只用于观察，绝不下真实订单。
3. 后续价格若先达到 `first_trigger`，记录 `first_attempt_triggered=true` 和影子 MFE；无论是否
   已触发，只要在影子 MFE 达到 `0.50R` 前出现完整5m bar 的 low 低于 `first_stop`，第一次
   尝试判定失败并进入 `FIRST_ATTEMPT_FAILED`。
4. `FIRST_ATTEMPT_FAILED` 后，至少再出现一根完整5m bar 满足 `low<=failure_bar.low` 或
   `close<open`，才进入 `PULLBACK_LEG_2`；随后第一根满足 signal-bar 质量条件的多头反转 bar
   进入 `SECOND_ENTRY_READY`。每根 bar 最多推进一个状态，这根反转 bar 是实际候选 signal bar。
5. 从回调开始超过 10 根5m bar、影子 H1 先达到 `0.50R`、regime 不再为同向强趋势、session
   结束、换月或数据中断时立即重置 `IDLE`。

做空使用完全镜像的价格不等式、影子 L1 trigger/stop 和 MFE。状态、影子尝试及重置原因全部
写入 `candidates.csv` 的 context，确保前缀不变性可审计。

做多规则：

```text
regime == STRONG_TREND_UP
second_entry_state == SECOND_ENTRY_READY
0.10 <= pullback_depth_long_20 <= 0.60
low <= ema_20 + 0.25 * atr_14
close >= ema_20 - 0.25 * atr_14
pa_bull_reversal == 1
bar_body / bar_range >= 0.35
(close - low) / bar_range >= 0.65
bar_range <= 1.20 * atr_14
pa_buy_climax == 0
```

做空规则必须使用空头 `SECOND_ENTRY_READY`、`pa_bear_reversal == 1`、对称的 EMA 下方条件、
`pa_sell_climax == 0` 和 `0.10 <= pullback_depth_short_20 <= 0.60`。

触发和止损：

```text
LONG trigger = signal_high + 1 tick
LONG stop    = min(本次5m回调所有low) - 1 tick

SHORT trigger = signal_low - 1 tick
SHORT stop    = max(本次5m反弹所有high) + 1 tick
```

回调起点由最近一次与趋势同向的 5m impulse 结束后第一根反向 bar 确定，最多回看 10 根5m
bar。超过 10 根视为旧趋势影响消失，不生成 continuation。

### 8.2 `strong_breakout_follow_through`

允许背景为同向强趋势或 `TIGHT_RANGE_BREAKOUT_MODE`。做多规则：

```text
前一根5m bar: pa_breakout_up_10 == 1
前一根5m bar: pa_breakout_strength_10 >= 0.35
前一根5m bar: pa_bo_body_ratio_10 >= 0.60
前一根5m bar: pa_bo_close_pos_10 >= 0.80
前一根5m bar: volume_ratio_prev20 >= 1.20
当前5m bar: close > open and close > prior_close
当前5m bar: low >= prior_bar_mid - 0.10 * atr_14
当前5m bar: pa_follow_through_10 > 0
当前5m bar: bar_range <= 1.50 * atr_14
pa_buy_climax == 0
```

做空必须显式使用 `pa_breakout_down_10 == 1`、`pa_breakout_strength_10 <= -0.35`、
`pa_bo_close_pos_10 <= 0.20`、当前阴线且低于前收，以及 `pa_follow_through_10 < 0`。
触发位为 follow-through bar 高/低外 1 tick；结构止损放在 breakout bar 与
follow-through bar 的共同低点/高点外 1 tick。

只交易确认后的 follow-through，不交易第一根突破。这会减少机会，但符合 80%强制胜率的
高选择性方向。

### 8.3 `failed_breakout_range_fade`

做多规则：

```text
regime == WIDE_TRADING_RANGE
previous_5m.low < regime.range_low - 1 tick
previous_5m.close > regime.range_low
current_5m.close > current_5m.open
current_5m.close > previous_5m.close
current_5m.low >= previous_5m.low
current_5m.pa_bull_reversal == 1
trigger <= regime.range_low + (regime.range_high - regime.range_low) / 3
regime.range_mid - trigger >= 1.20 * price_risk + pressure_cost_price
```

做空规则使用同一 `RegimeSnapshot` 在区间上三分之一完全镜像。
旧 `pa_breakout_fail_10` 的 `+1 = 向上突破失败`、`-1 = 向下突破失败` 只输出诊断，不参与门控，
避免把 5m 的10根边界与冻结的30m区间混用。
触发位为 reversal bar 高/低外 1 tick，结构止损为假突破极值外 1 tick。目标不能越过区间中点；
若 1.10R目标在中点之外则拒绝候选。

## 9. 交易计划与净盈亏比

### 9.1 障碍位、可用空间和压力成本

局部 swing 只在右侧 2 根 bar 已完成后确认：若 `high_j` 高于 `j-2,j-1,j+1,j+2`，
该 swing high 的 `known_at` 是 `bar_end[j+2]`；swing low 完全镜像。任一 setup 只能使用
`known_at<=setup_bar_end` 的 swing，不得将 pivot 回填到 `j` 后当作当时已知。

障碍位固定为：

```text
second_entry_continuation / strong_breakout_follow_through LONG:
    obstacle = min(
        过去60根5m已确认 swing highs 中 > trigger 的价格,
        过去20根30m已确认 swing highs 中 > trigger 的价格,
        DailyTradingSpec.limit_up
    )

second_entry_continuation / strong_breakout_follow_through SHORT:
    obstacle = max(
        过去60根5m已确认 swing lows 中 < trigger 的价格,
        过去20根30m已确认 swing lows 中 < trigger 的价格,
        DailyTradingSpec.limit_down
    )

failed_breakout_range_fade LONG/SHORT:
    obstacle = RegimeSnapshot.range_mid
```

趋势类某个 swing 集合为空时忽略该集合，但当日 limit 必须存在，因此 `obstacle`
始终唯一。已被突破且在 trigger 后方的水平不是前方障碍。一旦候选生成，其 obstacle
和来源 `known_at` 冻结到 context，订单存续期内不重算得更宽。

压力成本按 1 手统一转为价格距离：

```text
pressure_fee_1 = 2.0 * (
    fee(OPEN, trigger, 1)
    + max(fee(CLOSETODAY, structural_stop, 1),
          fee(CLOSETODAY, obstacle, 1))
)
pressure_slippage_1 = (
    2 sides * 3.0 * base_slippage_ticks * price_tick * contract_size
)
pressure_cost_price = (pressure_fee_1 + pressure_slippage_1) / contract_size

available_space_price = abs(obstacle - trigger)
required_space_price = 1.20 * price_risk + pressure_cost_price
available_space_r = (
    available_space_price - pressure_cost_price
) / price_risk
```

只有 `available_space_price>=required_space_price` 才能建立计划。`price_risk<=0`、障碍位在错误方向、
费率或 limit 缺失时均拒绝，不允许用无穷大空间。

### 9.2 风险和目标

定义未计成本的价格风险：

```text
price_risk = abs(trigger_price - structural_stop)
```

先按 1 手（per contract）计算规划成本，不得在尚未得到 `qty` 时使用总手数：

```text
open_fee_1 = fee(OPEN, trigger_price, quantity=1)
stop_close_fee_1 = fee(CLOSETODAY, structural_stop, quantity=1)
slippage_1 = 2 * base_slippage_ticks * price_tick * contract_size

stop_cost_1 = open_fee_1 + stop_close_fee_1 + slippage_1
net_stop_loss_per_contract = price_risk * contract_size + stop_cost_1

target_close_fee_1(p) = fee(CLOSETODAY, p, quantity=1)
net_profit_per_contract(p) =
    abs(p - trigger_price) * contract_size
    - open_fee_1 - target_close_fee_1(p) - slippage_1
net_payoff(p) = net_profit_per_contract(p) / net_stop_loss_per_contract
```

从 trigger 向盈利方向逐 tick 枚举目标价，选择第一个 `net_payoff>=1.10` 的合法 tick。
费率依赖成交额时每个候选目标都重算费用，因而没有目标价与费用的循环歧义。
只有最终 `net_payoff` 在 `[1.02, 1.20]` 且可用空间至少为 `1.20R` 时，候选才进入仓位计算。

### 9.3 仓位

```text
risk_budget = current_equity * current_risk_pct
risk_qty = floor(risk_budget / net_stop_loss_per_contract)

margin_per_contract = entry_price * contract_size * margin_rate
margin_qty = floor(
    (current_equity * 0.30 - current_margin_used_and_reserved)
    / margin_per_contract
)

portfolio_risk_qty = floor(
    remaining_portfolio_open_risk
    / net_stop_loss_per_contract
)

qty = floor_to_lot(min(risk_qty, margin_qty, portfolio_risk_qty))
```

`qty < 1` 时记录 `qty_zero` 并跳过。不得缩窄结构止损换取 1 手。
得到手数后，计划总止损损失为 `qty * net_stop_loss_per_contract`，计划总费用为每手
费用乘实际成交手数，两者必须分列输出。

### 9.4 订单生命周期

- setup bar 收盘后创建 stop-entry。
- 最早在下一根 1m bar 触发。
- 订单最多有效 3 根完整 1m bar。
- regime、合约、session、结构位或风控任一失效立即撤单。
- 一个 symbol 同时最多一个 entry order 和一个持仓。
- RB 与 CU 同分钟候选若组合风险不足，先处理退出，再按 `trigger_timestamp`、`vt_symbol`
  升序确定性处理入场。
- stop-entry 是 engine 内部合成触发，不提前向经纪商挂无法重定量的全量市价止损单。
- 触发时先用当前可成交参考价和不利滑点重算每手风险、保证金和 `qty`；缺口导致
  `qty` 减少时只发缩减后手数，`qty<1` 则取消。
- 实际部分成交后若因二次滑点使已成交开放风险超过预算，立即撤销余单并减仓/平仓至
  预算内；无法成交时记录 `entry_risk_breach` 并触发风险一票否决。

## 10. 1分钟撮合和退出

### 10.1 bar 事件顺序

每根 1m bar 固定顺序：

1. 以 open 执行上一 bar 收盘后产生的市价退出。
2. 处理账户、session、换月和涨跌停强制动作。
3. 检查既有持仓的 gap-through-stop。
4. 检查 bar 内既有 stop/target。
5. 检查此前已存在的 entry stop。
6. 对新成交持仓检查该 bar 剩余路径可能触及的 stop/target。
7. 以 close 估值并更新 5m/30m聚合。
8. 完整周期收盘后生成下一 bar 才可用的状态、setup 和退出意图。

OHLC 无法确定盘中路径时采用最不利假设：

- 同时触及 stop 和 target，stop 优先。
- entry 与 stop 同 bar 均可能发生，视为先 entry 后 stop。
- gap 穿过 entry，成交价为 open 加不利滑点。
- gap 穿过 stop，成交价为 open 再加不利滑点。

涨跌停和无对手盘采用以下保守模型：

- 每个交易日必须先载入 `DailyTradingSpec`，不得用 `prev_close` 估算期货涨跌停价。
- 分钟 OHLCV 不能证明订单生效后的队列流动性。只要 1m bar 最终 `close==limit_up`，
  该 bar 内所有需要买入的新开/平仓订单都按不成交；`close==limit_down` 时，该 bar 内
  所有需要卖出的订单都按不成交。
- 即使该 bar 早段有成交量或 high/low 曾离开涨跌停，也不得假设本策略在封板前排队成交。
- 买入方向的新仓在涨停收板不成交，卖出方向的新仓在跌停收板不成交。
- 需在跌停卖出平仓或在涨停买入平仓时，保持 `forced_flat_pending`，每根 bar 继续尝试并以
  限价估值；不得伪造成交。
- session close 仍有 `forced_flat_pending` 时记录 `forced_flat_failed`，当次研究一票否决。

### 10.2 退出优先级

```text
1. exchange/account_kill_switch
2. hard_stop 或 gap_stop
3. forced_session_flat
4. profit_target
5. no_follow_through_scratch
6. max_holding_time
```

### 10.3 快速失败退出

入场后第 3 根完整 1m bar 收盘时，若：

```text
MFE < 0.25R
and (
    (direction == LONG and close <= entry_trigger)
    or (direction == SHORT and close >= entry_trigger)
)
```

则产生 `no_follow_through_scratch`，下一根 1m open 市价退出。最多持有 25 根1m bar；到期
后下一根 open 退出。session 强平优先于时间退出。

### 10.4 session 规则

- session 结束前 15 分钟不再创建 entry order，并撤销仍未触发的候选。
- session 结束前 5 分钟对全部持仓发市价强平。
- session close 后 `position_qty` 必须为 0，所有 entry order 必须已撤销。
- 日盘与夜盘盈亏汇总到交易所 trade date，但冷却状态按 session 和 trade date 两层保存。

## 11. 账户和风险控制

### 11.1 风险预算

- 基础单笔计划风险：当前权益 `0.25%`。
- 单品种最大开放风险：当前权益 `0.25%`。
- 组合最大开放风险：当前权益 `0.50%`。
- 新开仓后组合保证金占用上限：当前权益 `30%`。
- 逐分钟保证金硬上限：当前权益 `35%`。
- 单品种只允许一个方向，不允许锁仓。
- 平仓永远不受新开仓 guard 阻挡。

### 11.2 逐分钟保证金重估

每根 1m bar 和每个 order/trade callback 后，先按第 11.3 节更新 `marked_equity`，再重算：

```text
margin_mark_price = max(
    current_1m_close,
    position_entry_price,
    DailyTradingSpec.pre_settlement
)

position_margin = sum(
    abs(position_qty) * contract_size * margin_mark_price
    * active_FeeMarginSpec.margin_rate_for_direction
)

working_order_margin_reserve = sum(
    remaining_entry_qty * contract_size
    * max(order_trigger_price, current_1m_close, pre_settlement)
    * active_margin_rate_for_direction
)

margin_used_and_reserved = position_margin + working_order_margin_reserve
margin_usage = margin_used_and_reserved / marked_equity
available_funds = marked_equity - margin_used_and_reserved
```

`FeeMarginSpec` 按 bar/order 时刻的 `effective_from/effective_to` 选择，不能只在入场时锁定后不再
更新。当 `margin_usage>30%` 时拒绝新仓；已存在仓位因价格或保证金率变化使
`margin_usage>35%` 或 `available_funds<0` 时，先撤全部入场单，再按“每手保证金从高到低、
`vt_symbol` 升序”减仓，直到恢复到 30% 以下。无法成交时记录 `margin_breach_unresolved`。

`minute_equity.parquet` 每分钟保存每仓位保证金率、标记价、`position_margin`、
`working_order_margin_reserve`、`margin_usage` 和 `available_funds`。任一时刻硬上限穿越或
`margin_breach_unresolved` 都进入一票否决，即使后续已减仓也不删除事件。

### 11.3 标记权益唯一口径

所有仓位、熔断、回撤和日收益按每根 1m bar 收盘后的 `marked_equity` 计算：

```text
marked_equity = initial_cash
                + cumulative_closed_pnl_from_actual_fill_prices
                - paid_entry_and_exit_fees
                + open_position_unrealized_pnl_at_conservative_exit_price
                - estimated_exit_fee_for_open_positions
```

实际 fill price 已包含滑点，因此已平仓盈亏不得再扣一次 `realized_slippage_cost`。
`conservative_exit_price` 为 1m close 再加一次退出方向不利滑点。`total_slippage` 作为
参考价与实际成交价的执行归因字段，不在基于实际 fill 的 PnL 上重复扣减。

保证金只是冻结资金，不从权益重复扣除。`session_start_equity`、`trade_date_start_equity` 和
`trade_date_peak_equity` 都是同一口径的快照。交易日状态按 `exchange_trade_date` 而不是自然日重置。

```text
session_return = marked_equity / session_start_equity - 1
trade_date_return = marked_equity / trade_date_start_equity - 1
peak_profit = trade_date_peak_equity / trade_date_start_equity - 1
giveback_cny = trade_date_peak_equity - marked_equity
```

盈利保护在 `peak_profit>=1.00%` 后启用；`giveback_cny >= 0.40% * trade_date_start_equity`
时全平并锁定当日。不直接复用按自然日重置或按峰值比例回吐的旧 tracker。

### 11.4 session 和 trade date 熔断

| 条件 | 动作 |
| --- | --- |
| session 净亏损达到 `-0.60%` | 本 session 后续 `risk_pct=0.125%` |
| trade date 净亏损达到 `-1.00%` | 全平、撤单、当日禁止新仓 |
| 单品种连续亏损 2 笔 | 该品种冷却 30 分钟 |
| 单品种连续亏损 3 笔 | 该品种当日停机 |
| 组合连续亏损 4 笔 | 全组合当日停机 |
| 日内盈利曾达到 `+1.00%` 后回吐 `0.40%`权益 | 全平并锁定当日 |

止损跳空可能使实际单日亏损穿过 `-1%`。任何单日净亏损超过 `-2%` 都是一票否决，不因
“已经触发止损”而豁免。

### 11.5 账户回撤

| 从历史权益峰值回撤 | 动作 |
| --- | --- |
| `-3%` | 新交易风险减半 |
| `-5%` | 全平并停机 5 个完整 session |
| `-8%` | 策略硬停，必须人工复核后才能重新启用 |

### 11.6 以 fail-closed 方式复用 `cta/risk`

现有 `cta/risk/orchestrator.py` 对 guard/adjuster/scaler 异常采用 fail-open，因此本策略禁止直接
调用该 orchestrator。`risk_policy.py` 必须实现 `RuleOnlyRiskAdapter`，逐项直接调用可兼容
组件，捕获任何异常或缺少输入后返回 `REJECT_NEW_ENTRY`。固定顺序：

```text
LocalMarketDataStalePolicy
LocalDailyLimitPolicy
LiquidityFloorGuard
RolloverFreezeGuard
LocalConsecutiveLossPolicy
VolatilityRegimeScaler
DailyVaRBudgetSizer
ExecutionQualityScaler
LocalMarkedEquityLossPolicy
LocalFixedGiveBackPolicy
```

`PredictionStaleGuard` 检查模型预测文件，与纯规则策略无关，禁止接入。旧
`LimitMoveGuard` 使用 `prev_close` 且缺值可放行，由本文 `DailyTradingSpec` 策略替代。旧
`ProfitGiveBackGuard` 的重置/回吐口径不同，由第 11.3 节本地实现替代。
旧 `ConsecutiveLossGuard` 的 24 小时/分组口径与第 11.4 节不同，由本地
`LocalConsecutiveLossPolicy` 实现 2 笔冷却、3 笔当日停机和组合 4 笔停机。

`RuleOnlyRiskAdapter` 调用前还必须要求：Liquidity 的冻结字段；Rollover 的
`last_trade_date/main_switch_date`；Volatility 的完整 252 根30m窗口；Daily VaR 的显式账户/分组
`marked_equity PnL`；Execution Quality 的成交/拒单跟踪状态。组件返回“no data”、“no symbol”或
内部 tracker fallback 都不是通过决定，适配器必须转成 `REJECT_NEW_ENTRY`；只有明确冻结的
Execution Quality `INACTIVE_WARMUP` 例外。

Rollover 还必须显式传入 `trading_days_to_expiry` 和 `trading_days_since_switch`。两者只能从
对应交易所的版本化开市日历计算：前者统计 `(当前交易日, 最后交易日]`，后者统计
`(主力切换交易日, 当前交易日]`。日期字段保留用于审计，但风险适配器禁止自行按自然日相减。

若其他本地接口名称或签名变化，适配层可跟随当前实现，但上面的语义、顺序和 fail-closed
不得改变。每个组件的输入、决定、原因和异常写入审计日志。平仓不受新开仓 guard
阻挡；适配器异常时仍尽最大努力撤单/平仓并记录告警。

## 12. RiskScore

### 12.1 评分表

| 维度 | 条件 | 分值 |
| --- | --- | ---: |
| 生存 | 锁定评估最大回撤 `<=8%` | 10 |
| 生存 | 无保证金不足，保证金占用始终 `<=35%` | 8 |
| 生存 | 一年期 block-bootstrap 亏损20%概率 `<1%` | 7 |
| 尾部 | 最差单日亏损 `<=1.5%` | 8 |
| 尾部 | 日收益 Historical VaR99 `<=1.0%` | 6 |
| 尾部 | 日收益 Historical ES99 `<=1.5%` | 6 |
| 压力 | 2倍手续费后净收益为正且 Profit Factor `>1` | 8 |
| 压力 | 3倍滑点后净收益为正且 Profit Factor `>1` | 8 |
| 压力 | gap/涨跌停压力场景无保证金违约 | 4 |
| 控制 | 每笔和组合风险预算零违规 | 5 |
| 控制 | session/trade date熔断零违规 | 5 |
| 控制 | session close 零残仓 | 5 |
| 稳定 | 每个完整锁定评估年度净收益为正 | 4 |
| 稳定 | 滚动三个月收益为正的窗口占比 `>=70%` | 3 |
| 稳定 | RB、CU 单独均未触发强制失败 | 3 |
| 审计 | 因果和前缀不变性通过 | 4 |
| 审计 | 合约换月和 trade date 对账通过 | 3 |
| 审计 | fills/trades/equity 逐笔复算通过 | 3 |

总分必须 `>=90`。

### 12.2 一票否决

任一触发则 `REJECTED`：

- 最大回撤 `>8%`。
- 任一单日净亏损 `>2%`。
- 任一时刻保证金不足或保证金占用 `>35%`。
- 一年期 block-bootstrap 亏损20%概率 `>=1%`。
- 未来函数、未完成周期泄露或标签数据进入信号。
- session close 残仓或强平失败。
- 连续合约价格被当作真实成交价。
- 手续费、平今费或滑点没有进入 fills 和 equity。
- 风控拒绝开仓后仍产生开仓 fill。
- 产生无法立即恢复到预算内的 `entry_risk_breach`。
- 缺少当日昨结算/实际涨跌停数据却仍产生新开仓 fill。

block-bootstrap 使用 5 个 trade date 为一个 block，固定随机种子 `20260809`，10,000 条一年
路径，每条按 252 个交易日复利。“亏损20%”事件唯一定义为
`ending_equity / starting_equity - 1 <= -0.20`。不足 500 个日收益样本时该项记为
`INCONCLUSIVE`，不得给分。VaR99 和 ES99 以损失正数表示：`loss=-daily_return`，
VaR99 是 loss 的99%分位，ES99 是 `loss>=VaR99` 样本的平均。

### 15.3 vn.py 多品种在线架构

vn.py `CtaTemplate` 实例只绑定一个 `vt_symbol`，因此不得用一个策略实例伪装 RB+CU
共享账户。在线必须使用：

```text
BrooksScalpPortfolioCoordinator        # 账户级，唯一写者
  ├── BrooksScalpLiveStrategy(RB vt_symbol)
  └── BrooksScalpLiveStrategy(CU vt_symbol)
```

每个单品种 `BrooksScalpLiveStrategy(CtaTemplate)` 只负责 tick/1m bar、订单适配和经纪商回报。
`BrooksScalpPortfolioCoordinator` 拥有所有 symbol engine、共享 `AccountSnapshot`、保证金、开放风险、
熔断、风险决策日志和入场排序；单品种壳不得自行定仓或放行开仓。

协调器对每个 1m `bar_end` 先用各品种 `SessionCalendar` 计算
`expected_active_symbols(bar_end)`：只有当时处于连续交易 segment、并应产生该 bar end 的
symbol 才进入 watermark。休市或已收盘品种不等待、不判 stale；因此 RB 夜盘收盘后
不会阻塞仍在交易的 CU。

实时收到全部 active symbol 的 bar，或某 active symbol 超过冻结
`active_bar_stale_tolerance_seconds=90` 后，先按 `vt_symbol` 升序处理已存在退出，再按
`trigger_timestamp, vt_symbol, candidate_id` 处理入场。任一 symbol stale 时共享账户禁止新仓，
但所有退出仍继续。协调器不可用时，单品种壳只允许撤单和平仓。
历史回测不使用墙钟 90 秒：active symbol 在预期时间缺 bar 直接按数据缺口处理，不得
等待后来 bar 再回填旧 watermark。

单品种独立报告使用只注册一个 symbol、初始权益 200,000 的同一协调器；RB+CU 组合报告
使用同一个 200,000 共享账户，不是两个 200,000 账户相加。回测和 online runner 调用
同一 coordinator API。

### 15.4 在线订单状态机

每个经纪商订单固定状态：

```text
CREATED -> RISK_APPROVED -> SUBMITTED
SUBMITTED -> PARTIALLY_FILLED -> FILLED
SUBMITTED/PARTIALLY_FILLED -> CANCEL_PENDING -> CANCELLED
SUBMITTED -> REJECTED
CANCEL_PENDING -> PARTIALLY_FILLED/FILLED   # 撤单竞态中的迟到成交
```

- `OrderData` 和 `TradeData` 分开处理，以 `vt_orderid/vt_tradeid` 去重，重复回报不得重复计仓。
- 每次部分成交后，立即为已成交手数建立 reduce-only 止损和目标 OCO 意图；一边成交后
  撤销另一边。余下入场单按原到期和风险规则保留或撤销。
- 撤单途中的迟到 fill 必须入账并立即受保护，不得因本地已设 `CANCEL_PENDING` 丢弃。
- 开放风险同时计入已成交仓位和活动入场单的最坏全成交风险，撤单确认前不释放。
- SHFE 平仓根据经纪商持仓明细拆分 `CLOSETODAY/CLOSEYESTERDAY`。策略正常不跨 session，
  但恢复发现的历史仓仍必须正确拆单；vn.py 壳通过原生 `send_order` 保留这两个 offset，
  不得退化成通用 `CLOSE`。若成交回报只给出 `CLOSE`，按对应工作订单的冻结 offset 入账。
- 启动时先查询经纪商持仓和活动订单，再与 coordinator/symbol 快照三方对账。已有仓位
  缺少保护单时先重建保护；无法重建则市价平仓。对账一致前禁止新仓。

在线壳不得重新实现 setup、仓位或退出逻辑。coordinator、symbol engine、风险、订单和去重键
每分钟原子持久化。

## 17. 测试与验收

### 17.1 数据和因果

- RB/CU 两种 schema 归一结果一致。
- CU 源自然日与 `exchange_trade_date` 分离，周五夜盘、`00:00`和节假日映射正确。
- `10:15/10:30/11:30/13:30` 和夜盘边界不产生跨段 5m/30m bar，尾部缩短30m不发布。
- 未完成 5m/30m bar 不产生状态或 setup。
- 修改未来全部 OHLCV 不改变截止日前状态、setup、订单和成交。
- 主力映射 `decision_asof` 不晚于生效 session，切换时冻结和重新预热。
- 昨结算、当日实际涨跌停和 `known_at` 缺一时新仓 fail-closed。
- 四个元数据 CSV 覆盖不足时整个 run 为 `BLOCKED_METADATA`，manifest 行数/日期/哈希可复算。
- 早期 RB `open_interest<=0` 不前填，OI 诊断记为不可用；完整 volume/turnover activity 比率仍可独立审核。

### 17.2 规则

- 构造确定性 OHLC 序列分别触发三类多头 setup。
- 镜像价格序列触发完全对称的空头 setup。
- Second Entry 影子首次尝试未失败时不入场，破坏首次 stop 后的第二次才就绪。
- session/regime/换月/十根超时均重置 Second Entry 状态，追加未来 bar 不改变历史状态。
- range fade 的假突破、三分区和目标全部引用同一个冻结 30m `RegimeSnapshot`。
- swing 只在右侧2根完成后成为障碍位，趋势/区间三类 setup 的 obstacle 和空间公式可手算。
- Barb Wire、高潮、空间不足和过大 signal bar 均拒绝。
- 同 bar 多 setup 只保留固定优先级最高者。
- 规则不读取 `pa_scalp_score` 或任何模型输出。

### 17.3 撮合

- setup bar 不能成交，下一 1m bar 才能触发。
- 订单 3 根 1m bar 后过期。
- entry、stop、target 同 bar 时执行最不利路径。
- gap entry、gap stop、tick 取整和滑点正确。
- 触发时重定量，每手费用与实际手数总费用不循环。
- 平今费进入成交和权益。
- 涨/跌停封板的不可成交入场、延迟平仓和 `forced_flat_failed` 正确。
- bar 早段有量但最终收在不利涨跌停时，订单仍不能利用早于生效/排队的流动性。
- 部分成交立即建保护，撤单迟到 fill 不丢失，回报去重。
- SHFE `CLOSETODAY/CLOSEYESTERDAY` 拆单和费用正确。
- 25 根 1m bar 时间退出和 session 强平正确。

### 17.4 风险

- 20万元账户按500元基础风险向下取整。
- 1 手风险过大时跳过，不移动止损。
- 单品种和组合开放风险、35%保证金上限正确。
- 价格、保证金率和活动入场单变化后逐分钟重估，30%新开仓上限、35%硬上限和减仓顺序正确。
- session -0.6%减半、trade date -1%停机。
- 连亏冷却、单品种停机、组合停机和盈利回吐保护正确。
- 实现盈亏、未实现盈亏、已付/预估退出成本构成的 `marked_equity` 可逐分钟复算。
- `RuleOnlyRiskAdapter` 对每个异常/缺值拒绝新仓，测试确认未调用 fail-open orchestrator。
- 每个 risk component 的构造参数逐值等于 YAML，删掉任一 required input 都拒绝新仓。
- -3%/-5%/-8%回撤状态转换不可逆地按规则执行。
- 风控异常不能放行开仓，不能阻止必要平仓。

### 17.5 统计和报告

- scratch 计入胜率分母且不计为 win。
- 净胜率、盈亏比、日/月收益、VaR、ES和回撤可手工复算。
- 每个分组少于100笔为 `INCONCLUSIVE`。
- 六个冻结 setup×direction 中任一零交易/不足100笔不能通过禁用规避。
- 79.999%胜率失败，80%通过；1.0199和1.2001盈亏比失败。
- RiskScore 89失败，90通过；一票否决覆盖高分。
- 2倍手续费和3倍滑点独立重放，不直接乘最终 PnL。
- 原子发布失败时旧报告保持完整。

### 17.6 离线和在线一致

同一组历史 1m bar 分别通过 backtest adapter 和 live dry-run adapter 输入，共享 engine 的
每个状态、候选、订单意图和退出原因必须逐值一致。真实成交价可不同，但决策时间不得不同。
另用 RB/CU 同一 `bar_end` 构造候选，验证 coordinator 始终先退出、后按冻结顺序入场，
且共享开放风险/保证金与单品种壳回放一致。
再构造 RB 已收盘而 CU 仍 active 的夜盘时刻，确认 watermark 只等待 CU；active CU 超过
90 秒未到才判 stale，休市 RB 永不会阻塞 CU 合法入场。

## 18. 实施顺序

### Phase 1：数据和 session

1. 实现 RB/CU schema、自然日/交易日适配器和
   `InstrumentSpec/DailyTradingSpec/FeeMarginSpec`。
2. 实现 SHFE/经纪商元数据 importer、四个 canonical CSV 和 manifest 覆盖审计。
3. 实现 segment anchor 的 session 和 5m/30m 因果聚合。
4. 实现带 `decision_asof` 的合约映射、涨跌停数据和换月冻结。
5. 完成数据质量、时区、换月和前缀不变性测试。

### Phase 2：纯价格行为规则

1. 实现带冻结区间边界的 `RegimeSnapshot`。
2. 实现 Second Entry 影子首次尝试状态机和三类多空镜像 setup。
3. 实现空间、结构止损和净1.10R目标。
4. 确认没有模型依赖和综合分门控。

### Phase 3：1m引擎和账本

1. 实现候选、部分成交、撤单竞态、保护 OCO、持仓和退出状态机。
2. 实现保守 OHLC 路径、封板不可成交和 session 强平。
3. 实现每手/总手续费、平今/平昨、滑点、逐分钟保证金重估和 `marked_equity`。

### Phase 4：风险

1. 实现风险手数和组合预算。
2. 实现 `RuleOnlyRiskAdapter`，逐值传入 YAML 参数、预校验必需输入并强制 fail-closed。
3. 实现 session、exchange trade date、连亏、回撤和固定权益点回吐保护。

### Phase 5：回测和报告

1. 跑开发期 sanity，不改冻结参数。
2. 跑验证期和锁定评估。
3. 生成 RB、CU、组合、压力测试和 RiskScore。
4. 独立复算并原子发布报告。

### Phase 6：vn.py dry-run

1. 实现账户级 `BrooksScalpPortfolioCoordinator` 和每 symbol 的 `BrooksScalpLiveStrategy`。
2. 回放同一历史数据验证离线/在线、单品种/共享账户一致。
3. paper trading 至少 60 个 trade date 后，才讨论实盘准入。

## 19. 运行接口

元数据覆盖校验：

```bash
python3 -m cta.strategy.brooks.scalp.metadata_importer \
  --meta-root cta/strategy/brooks/scalp/meta \
  --symbols RB0.SHFE CU0.SHFE \
  --start 2018-01-03 \
  --end 2026-04-16 \
  --validate-only
```

该命令非 0 退出时，回测 runner 必须立即输出 `BLOCKED_METADATA` 并终止。

冻结回测：

```bash
python3 -m cta.strategy.brooks.scalp.backtest_runner \
  --symbols RB0.SHFE CU0.SHFE \
  --start 2018-01-03 \
  --end 2026-04-16 \
  --meta-root cta/strategy/brooks/scalp/meta \
  --config cta/strategy/brooks/scalp/strategy.yaml \
  --output-root cta/strategy/brooks/report/scalp \
  --run-id 20180103_20260416_rule_only
```

本机本次完整运行耗时 `2354.25s`。单次 run 内缓存规范分钟帧后，各场景不再重复读取源
parquet；缓存不持久化，也不跳过源文件首尾 SHA-256 稳定性校验。

测试：

```bash
python3 -m pytest cta/strategy/brooks/scalp/tests -q
python3 -m ruff check cta/strategy/brooks/scalp
python3 -m compileall -q cta/strategy/brooks/scalp
```

在线 dry-run：

```bash
python3 -m cta.strategy.brooks.scalp.online_runner \
  --symbols RB0.SHFE CU0.SHFE \
  --contracts RB2605.SHF CU2605.SHF \
  --trade-date 2026-01-05 \
  --config cta/strategy/brooks/scalp/strategy.yaml \
  --dry-run
```

`--contracts` 必须是一一对应的冻结真实合约，`--trade-date` 用于选择当日涨跌停、保证金和费率。
dry-run 会实际构建共享 20 万账户、两个 symbol engine 和元数据覆盖校验，并输出对账快照；不带
`--dry-run` 时，在注入 vn.py gateway、经纪商持仓/活动订单查询和三方对账适配器前返回
`BLOCKED_GATEWAY_ADAPTER`，不得把仅通过元数据预检误报为 paper trading 已启动。

首版不提供 `--capital` 命令行覆盖；回测和 online 只能从同一份冻结配置读取
200,000 初始权益。未来若支持其他资金规模，必须通过新策略版本显式开放。
