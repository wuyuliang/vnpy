# 品种连续亏损冷却设计

## 目标

为多周期趋势策略增加按品种独立计算的开仓冷却规则：某品种相邻两笔最终平仓交易均为负收益，且两次最终平仓时间相差不超过自然 `48` 小时，则从第二笔亏损最终平仓后暂停该品种的新开仓。暂停至少经过自然 `24` 小时，并在此后的首个日盘 `09:00` 才解除。

本规则用于完整事件驱动回放，不能通过回测后删除交易近似计算。删除已有交易会改变资金、保证金、动态仓位和后续候选的成交机会，无法得到准确的组合收益和最大回撤。

## 配置

在 `MultiTimeframeTrendConfig` 中增加仅由配置文件维护的参数，不增加 CLI：

```python
symbol_loss_cooldown_enabled: bool = True
symbol_loss_pair_window_hours: int = 48
symbol_loss_cooldown_hours: int = 24
```

两个小时参数必须是正整数，启用参数必须是布尔值。回测 `summary.json` 记录三个参数，以便确认历史结果是否启用了本规则。

日盘恢复时刻固定为策略定义中的 `09:00`，不额外增加配置参数。

## 状态与触发

组合回放为每个根品种独立维护：

- 最近一笔最终平仓亏损的时间。
- 当前冷却恢复时间；未处于冷却时为空。

只在一笔逻辑交易最终平仓后更新状态，使用扣除手续费和滑点后的实际 `trade["net_pnl"]`：

- `net_pnl < 0` 为亏损。
- `net_pnl >= 0` 为非亏损，立即清除上一笔亏损时间，打断连续亏损关系。
- 当前亏损与上一笔亏损的最终平仓时间差 `<=48h` 时触发冷却；恰好 `48h` 仍触发，超过 `48h` 不触发。
- 隔夜保证金部分减仓只有在剩余仓位最终平仓并形成完整逻辑交易时才参与判断，单独的部分平仓腿不算一笔交易。

冷却触发后，先计算：

```text
minimum_time = second_loss_exit_time + 24h
```

再将恢复时间对齐到严格不早于 `minimum_time` 的最近一个本地日盘 `09:00`。例如第二笔亏损在 `1月5日 14:30` 最终平仓，`minimum_time` 为 `1月6日 14:30`，恢复时间为 `1月7日 09:00`。若该日期休市，时间戳无需猜测交易日历；由于没有候选产生，数据中的下一个实际交易日开市后自然可交易。

## 事件顺序与拒绝审计

规则放在组合回放引擎中执行。每个时间戳严格按以下顺序处理：

1. 处理已有持仓的退出和最终交易汇总。
2. 用最终交易净盈亏更新该品种冷却状态。
3. 处理该时间戳新产生的候选。

因此，第二笔亏损最终平仓时刻新出现的同品种候选也会被冷却拦截，不存在同一时刻绕过。

当候选信号时间早于恢复时间时，保留候选但不创建计划、订单或成交，并写入拒绝原因：

```text
SYMBOL_LOSS_COOLDOWN
```

拒绝详情包含第二笔亏损最终平仓时间和计算后的恢复时间。候选时间恰好等于恢复时间时放行。规则只限制新开仓，不干预已有持仓的止损、移动止损、换月退出或隔夜减仓。

当前策略已从候选层屏蔽空头，但冷却判断应按“该品种新开仓”实现，不绑定方向，以免未来重新开放空头后出现不同语义。

正式 runner 即使只有 AG 一个品种也使用组合回放，因此只修改组合回放主路径。保留的单品种辅助回放不承担正式报告生成，不复制第二套冷却状态机。

## 报告与比较

`summary.json` 的上下文增加冷却配置。现有 `rejections.csv` 和机会图表按 `SYMBOL_LOSS_COOLDOWN` 自动形成拒绝审计及对应图表目录，不新增报告文件。

实现后使用用户指定命令重新执行完整 AG 回测，并与未启用本规则、但其他代码和配置完全相同的基线比较：

- 最终成交笔数。
- 总收益和收益率。
- 最大回撤和最大回撤比例。
- `SYMBOL_LOSS_COOLDOWN` 拒绝数量。

两次结果都必须来自完整事件驱动回放，不能从旧 `trades.csv` 后处理推导。

## 测试

1. 配置默认值和非法值校验。
2. 相邻两笔亏损恰好相隔 `48h` 时触发，超过 `48h` 时不触发。
3. 盈利或零收益打断连续亏损。
4. 部分平仓腿不单独计数，最终汇总后的真实净盈亏才参与判断。
5. 自然 `24h` 已结束但尚未到下一个 `09:00` 时继续拒绝。
6. 候选时间恰好等于恢复时间时放行。
7. 同一时刻先处理第二笔亏损最终平仓，再拒绝新候选。
8. `summary.json` 准确记录冷却配置，现有回放测试保持通过。
