# 交易收益率与入场后收益率设计

## 目标

在多周期趋势策略最终生成的 `trades.csv` 中，为每笔已完成交易增加方向调整后的总收益率，以及入场后第 `5`、`10`、`20`、`30` 个可交易分钟的收益率。新增字段只用于分析入场质量，不参与信号、撮合、退出、仓位或资金曲线计算。

## 输出字段

在现有 `gross_pnl` 列之后依次插入：

```text
total_return
return_5min
return_10min
return_20min
return_30min
```

所有字段保存小数收益率，不乘 `100`。多头和空头统一使用：

```text
return = direction * (observed_price - entry_price) / entry_price
```

其中 `direction` 的多头值为 `1`，空头值为 `-1`，因此交易方向上的盈利始终为正，亏损始终为负。

`total_return` 的 `observed_price` 使用交易最终汇总后的加权 `exit_price`。若一笔交易发生隔夜保证金部分减仓，则沿用当前 `trades.csv` 的最终加权退出价，不按退出腿新增多行。

## 入场后收益率

`return_5min`、`return_10min`、`return_20min`、`return_30min` 从 `entry_time` 之后的下一根实际可交易 `1` 分钟 K 线开始计数，并分别使用第 `5`、`10`、`20`、`30` 根 K 线的 `close`：

- 不把入场所在的 1 分钟 K 线计入观察窗口。
- 午休、日夜盘间隔、周末和节假日没有 K 线，因此不计入分钟数。
- 即使交易已在观察期限之前平仓，也继续从市场行情中取得对应观察价。
- 若回测区间结束前没有足够的后续可交易分钟，则对应字段留空，写入 CSV 时表现为空值。

观察行情按该笔交易的 `contract_code` 匹配，使用回放已有的实际成交合约分钟数据，避免主力合约切换造成的价格跳变。常规分钟数据优先，换月执行数据只补充同一成交合约缺失的时刻；若两者在同一合约同一时刻重叠，保留常规分钟数据。不得用其他合约价格填补缺失观察值。

## 实现位置

采用回放结束后统一补列的方式：

1. 保持 `_close_position` 和交易事件顺序不变，先按现有逻辑生成交易汇总。
2. 用一个无副作用的辅助函数，根据交易表和已验证的分钟行情计算全部新增收益率。
3. 单品种回放与组合回放在构造 `ReplayArtifacts.trades` 前调用同一个辅助函数。
4. `TRADE_COLUMNS` 固定新增字段及其顺序，确保内存中的 `ReplayArtifacts.trades` 与最终写出的 `trades.csv` 完全一致。

该方案不在持仓状态中维护未来观察任务，也不在报告层重新读取行情，因此不会改变回测行为或产生两套结果口径。

## 数据边界与校验

- `entry_price` 必须为有限正数；该条件由现有成交逻辑保证。
- 观察价必须为有限正数，否则该期限收益率留空。
- 行情按 `bar_end` 稳定排序后计数，结果不依赖输入原始行顺序。
- 只使用回放已经加载并经过校验的行情，不为计算诊断列扩大下载区间。
- 新增列不写入 `exit_legs.csv`，因为需求仅针对最终逻辑交易 `trades.csv`。

## 测试

1. 断言五个新增列紧跟在 `gross_pnl` 后，且顺序固定。
2. 验证多头和空头的盈利收益率均为正、亏损收益率均为负。
3. 验证 `total_return` 使用最终加权 `exit_price`。
4. 验证入场 K 线不计数，观察价来自入场后的第 N 根 1 分钟 K 线收盘价。
5. 验证跨午休、日夜盘间隔时只累计实际可交易 K 线。
6. 验证交易提前退出后仍继续计算后续观察收益率。
7. 验证后续行情不足或成交合约行情缺失时对应字段为空。
8. 验证组合回放按品种和成交合约隔离行情，不发生跨品种或跨合约取价。
9. 验证新增诊断列不会改变成交数量、盈亏、资金曲线及拒绝结果。
